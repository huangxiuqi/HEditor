## 外部 API 设计 v2（承接 10-21 深夜）

用户四条修正，逐条落进 `docs/外部API设计.md` 与 `web/types/editor.d.ts`（均 `tsc --strict` 0 错）：

1. **`doc` / `text` 移出构造参数** → 内容走 `open(data, {format?})` / `setText(text, {repeat?})`。

4. **change 带格式**：`ChangeEvent{source, version, text, readonly json}`。`json` 是**惰性 getter**

## emcc 能出 .d.ts（实测）—— 类型化计划要改

`--emit-tsd=<file>` 在 emcc 6.0.12 上可用，产出 **14 KB / 107 个带签名的函数**，Embind 的也认：

```ts
type EmbindString = ArrayBuffer|Uint8Array|Uint8ClampedArray|Int8Array|string;
interface EmbindModule {
  typeText(_0: EmbindString): boolean;
  loadDocument(_0: EmbindString): string;
  setZoom(_0: number): void;
  frameRgba(): any;
}
export type MainModule = WasmModule & typeof RuntimeExports & EmbindModule;
export default function MainModuleFactory (options?: unknown): Promise<MainModule>;
```

**前提：链接时 `tsc` 要在 PATH 上**。第一次直接加参数失败，原文：
`em++: error: tsc executable not found in node_modules or in $PATH`。
把 `npm i --prefix out/_ts typescript@5.6` 的 `.bin` 加进 PATH 后成功（样张存
`out/heditor.embind.d.ts`）。注意：那个失败的链接会留下**未优化**的 wasm（4.66 MB vs 4.02 MB），
必须还原参数重建一次才对得上。

三条局限：参数名是 `_0/_1`（C++ 签名没有名字）；返回 typed array 的是 `any`；**JSON 字符串内部看不见**
（`editStatsJson(): string` 仍是 string）。产出形态是 ESM，用 `<script>`/`importScripts` 加载时
套一行 `declare const CreateHEditor: typeof import('./heditor.embind').default` 即可。

⇒ 结论：**wasm 层不再手写类型**。类型有三个来源：C++ → embind d.ts（自动）/ schema → payloads
d.ts（生成）/ 契约 editor.d.ts（手写）。建议把 `--emit-tsd` 做成 CMake 选项（`find_program(TSC)`
有就开，默认关 —— 否则没装 tsc 的机器构建会直接红）。

已还原 CMakeLists 并重建，产物与之前一致（85433 / 4026000）；`web_probe@index` 与
`edit_probe@worker`（369 条）复跑全绿。

## index.html 与 worker.html 能不能合

能，而且 `multi.html` **已经在同一页上跑两种宿主**（`window.__heditorAutoBoot = false` +
自己 `createWorkerEditor` / `createEditor`）。真正的差异只有两处：

1. **标记结构**：#ime 的位置不同 —— 单线程那侧在滚动容器**内部**（坐标 = 滚动位移 + 页内坐标），
   Worker 那侧是滚动容器的**兄弟覆盖层**（坐标 = 文档坐标 − 滚动位移）。摆错了候选框会飘。

合并方案：一张页 + `?transport=worker|inline`；短期用并集标记 + 两脚本都加载（multi.html 的写法），

## 外部 API 方案 v3：构建 / 边界 / 类型（2026-10-22 凌晨）

用户三条要求，落进 `docs/外部API设计.md`（§10–§12 重写，650 行）与 `web/types/editor.d.ts`：
tsc 强制进 CMake、demo 只认公开面、C++/JS 的类型约束怎么做。**只出方案，没改代码**。

### 1. tsc 进 CMake（§12）

- emcc 找 tsc 的顺序（`tools/emscripten.py` 实测）：`<emscripten>/node_modules/.bin/tsc` →
  PATH；都没有就 `exit_with_error('tsc executable not found…')`。
- **不能在链接期才发现**：那次失败的链接会留下未优化的 wasm（4.66 MB vs 4.02 MB）。
- 方案：`if(EMSCRIPTEN)` 里 `unset(HEDITOR_TSC CACHE)` + `find_program(... HINTS
  ${EMSCRIPTEN_ROOT_PATH}/node_modules/.bin)`；找不到 `FATAL_ERROR` 并把修法写进消息
  （`npm install --prefix .toolchain/emsdk/upstream/emscripten typescript@5.6`）。
  `unset` 是为了不吃缓存 —— 删了 tsc 再 configure 也要当场红。
- `--emit-tsd` 必须给**绝对路径**：`phase_emit_tsd` 里是 `os.path.join(dirname(js_target), filename)`，
  相对路径会落到 `build/wasm/web/`。产物 `web/types/wasm.gen.d.ts` 不入库（`.gitignore`）。

### 2. 公开面白名单（§11）

五道闸：产物隔离（demo 只加载 `heditor.js`）/ 实例 Proxy（未知成员抛）/ `api_check.mjs`
（扫 demo 源码）/ `demo_probe.mjs`（`window.__heditor === undefined`）/ `tsc`。
Proxy 上 **`then`/`toJSON`/`constructor`/Symbol 必须放行** —— 拦了 `then`，`await editor` 直接抛。
`diag` 改成 `debug:true` 才有（契约里加了 `debug?: boolean`）。
内部验证台（`web/index.html` 等）不在此列，检查器只扫 `demo/`。

### 3. 类型（§10）

三层各自出类型，不做统一 schema：wasm 自动（emcc）、载荷 = C++ 的投影
（`payloads.json` → `.gen.h` + `.gen.d.ts`）、契约手写。
C++ 侧这次只做 `pk::checked()`（运行时比顶层键，~1 µs/份，常开）；
`Key<Kind>` 常量替换 245 处字面量不做 —— 它不增加覆盖，只把检查提前到编译期。
漂移表：改键名 → `--check` 红；重生成后 JS 读旧名 → `tsc` 红；分支里的键 → `pk::checked` 抛；
多/少公开方法 → `api_check.mjs` + `tsc`。**没有一种漂移是静默的。**

迁移顺序加了两步：**A2 构建与类型**、**A3 载荷契约**，都排在做 `src/` 之前 ——
它们不改运行行为，却决定后面每一步的判据能不能红。

### 追加：契约为什么手写、不从 TS 生成（§10.3 重写）

用户问"对外契约为啥是手写，不是 ts 自动生成吗"。答案的核心：**手写的不是类型，是承诺**。
生成出来的是"实现恰好长这样"——反例就在仓库里：facade 111 个成员（auditFrame/markCheck/
textarea/canvas 都在），worker 62 个、交集 46。生成的话这 111 个会原样发出去，类型正确且无用。

顺带实测了 TS 的两个方向（这是这次唯一的新事实）：
- `const x: Contract = impl`（impl 多 4 个成员）→ **tsc 不报**。结构化类型只对"对象字面量"
  查多余属性；把现成对象赋给窄接口是允许的。
- 自己写的 `Exclude<keyof T, keyof U>` + `[T] extends [never] ? true : { 多余成员: T }`
  → 报 `Type 'boolean' is not assignable to type '{ 多余成员: "c" | "auditFrame"; }'`，直接点名。
⇒ 契约对实现的两个方向：少方法/签名不符编译器管；多成员必须自己写一行断言。
  前提是 impl 的类型要**推断**出来，不能先标成 Editor（标了就是自己跟自己比）。

另：手写只覆盖 33 个签名（约 100 行），载荷那 245 个键仍是生成的 —— 两件事不冲突。

### 更正：契约不是"永远手写"，手写只是迁移期的载体

用户指出：迁移期可以先定接口，但 TS 重写之后**接口本身就是 TS，自带类型**。对，前一版把它
当终态写错了。§10.3 改成三阶段：

| 阶段 | 契约在哪 | 谁保证实现不越界 |
| 迁移期 B–C | `web/types/editor.d.ts`（手写）+ JSDoc | `tsc --noEmit`，实现类型必须推断 |
| 重写后 D | `src/types.ts` 的 `export interface Editor` | `createEditor(): Promise<Editor>` |
| 发布 | `dist/index.d.ts`（`tsc --declaration` 生成） | `src/index.ts` 只导出契约 |

关键不是"手写还是生成"，是**导出什么**：`export` 就是公开面。`class EditorImpl` 一旦导出，
所有非 private 成员都进 `dist/index.d.ts` —— 那是 111 个成员的 TS 版；不导出就一个都进不来。
`implements` 只查"至少满足"（实测），真正的闸是返回类型显式写成 `Editor`，或让工厂返回
**对象字面量**（字面量查多余属性）。

加了迁移判据：契约从 d.ts 搬进 `src/types.ts` 时，`api_check.mjs` 要证明**搬前搬后成员集合
逐条相同**；`src/types.ts` 再加一条成员快照哈希（与摘要 A/B/C 同构），防止"顺手改契约迁就实现"。
迁移表加了 D2 一步。

## 两个 demo bug：多页点击乱跳 + 光标不闪（17:2x~18:0x）

### 一、点第二页 → 落点对、视口被拽走

复现：160 页文档，滚到第 2 页（scrollTop 1712），点页内 (120,120) —— 光标落在第 2 页
（对），但 scrollTop 变成 0。四条成因叠在一起，逐条拆开：

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| inline：scrollTop 1712 → 0 | `scrollReset` 标记只在 `afterEdit` 里消费，而装载/诊断装载走的是 `settle + finish` ⇒ 标记挂到下一次编辑，一点就把视口归零 | 消费点挪到 `finish`（每拍都过），装载那一拍就清掉 |
| worker：晚一拍的状态又把视口归零 | 镜像里的 `scrollReset` 可能在任何一份状态之后到达，被"下一次 finish"消费 | `onState` 里**当场**应用并清掉（`host.resetScroll()`），不再留到以后 |
| worker：滚到第 1 页后点击 → scrollTop 107 | 落光标是异步的，`mousedown` 里的 `ta.focus()` 先发生；承接层还停在上一次光标处，**浏览器把滚动容器滚去露出它** | `ta.focus({ preventScroll: true })` —— 滚视口由 `scrollCaretIntoView` 按落点算 |
| worker：滚视口用的是上一拍的光标 | `settle()` 在 worker 侧是纯本地读镜像，`write` 还在路上就返回 ⇒ stats 是旧的；`afterEdit` 又直接拿 `settle` 的包装对象当 stats（`.stats` 没解包） | `settle` 改成 `await whenIdle()` 再回；`afterEdit`/`repaint` 统一取 `r.stats` |

### 二、光标"亮一下就灭"

`finish()` 末尾每拍都调 `resetBlink()`，把相位按回"可见"并重启 530 ms 计时器；而画面
已经按上一拍的相位画过了。于是每一拍都是"相位=可见 → 翻成隐藏 → 画隐藏" —— 点击后
第一拍还能看到，之后永远隐藏。修法：`finish` 不再碰闪烁；`afterEdit` 在 settle **之前**
写一次相位可见（这一拍要画出来），settle 之后重启计时器；`start()` 起一次计时器。

顺带 `repaint()` 也补上 `.stats` 解包。

载荷就写事件的 `DataTransfer`，Worker 传输拿不到（事件早结束了，`setData` 不报错但剪贴板是空的）

## 24:00 连续粘贴把页面撑长后"末尾没画布、滚轮弹回"（inline 特有）

用户报：复制一段文字、按住 Ctrl+V 不松开，几页之后乱套 —— 粘贴的文字显示不出来、
后面几页是白的、滚动条在中间位置滚轮往下滚会自己弹回来、只能拖着滚动条下去。

**真凶不在滚动跟随，在画布的定位**：`PageCanvases.canvasFor` 只 `appendChild`，
既不设 `position:absolute` 也不设 class，而 `#pages` 本身是 `static` —— inline 传输的
画布**参与文档流**。两个后果：一是 `style.top` 完全不生效（页间距丢失、逐页漂移），
二是换窗时 `remove` / `appendChild` 改变流的高度，浏览器据此做**滚动锚定**，把
`scrollTop` 往上拽。实测抓法：给 `Element.prototype.scrollTop` 装 setter 记调用栈，
3000 → 1244 的那次改写**抓不到任何 JS 调用栈**（是浏览器自己调的），而 `tops` 序列
在此之前是严格 +500 递增 —— 这就是"弹回"的来源。
Worker 的 `SlotCanvases.acquire` 一直带着 `position:absolute; display:block`，
所以只有 inline 显形（用户也是这么报的）。

修：`canvasFor` 补 `className='pg'` + `position:absolute` + `left:0` + `display:block`；
`ensureMarkup` 的 `#pages` 带 `position:relative`（定位基准只能是它——`#stage` 是滚动容器，
absolute 子元素相对它会不随内容走），`createDomHost` 再兜底补一次（旧骨架没有这条）。

顺带三件：
- **`#pages` 的"纸底"渐变删掉了**。它给"还没渲染的页"铺白纸，让"没有画布"和"空白页"
  长得一样 —— 这一轮排查被它误导了整段时间。缺画布现在直接露出 `#stage` 底色。
- **示例页默认传输改成 worker**（`?transport=inline` 切回来）。
- 滚动这条路补了两道：`scrollCaretIntoView` 先把滚动高度按这一拍的总页数对齐（Worker 下
  pages.sync 只在 finish 里跑，滚动发生在它之前，赋值会被旧底边夹住且不再派发 scroll
  事件）；改完用 `nudgeViewport` 当场把位置交给引擎，不等 scroll 事件。`retarget` 的滞回
  判据改成读引擎真实窗口（`windowFirstPage/windowPageCount`），不再用"上次请求的锚点"
  （引擎 present 时会把越界锚点夹回范围内，两者会分叉）。`finish` 里加了 `healWindow`：
  可见页不在窗口里就补一次视口消息，同一处滚动位置只补一次。

判据：`clipboard.spec` 新增"粘贴撑长之后：往下滚不弹回，可见页都有画布也有墨"
（真实滚轮 6 次、scrollTop 必须单调、可见页逐页抽样有墨）× 两条传输。
`clipboard` 22 项全绿；`demo` + `stress`（像素账 69 步差分）4 项绿；`npm run check` 绿。

## 24:30 两条传输怎么兼顾：把"实现差异"收成一处，"能力差异"写成声明

先纠正一处早先的说法：`FontSource::readAt` 是**同步**契约（注释原话"上游要同步契约"），
`FontStorage` 用 `std::FILE*` + `fseek/fread`，也就是 emscripten 的 FS 层；块怎么切、
读哪一段全是引擎自己算的（`FontBlockCache::read(storage_, off, len)`），**宿主不参与、
也不需要知道**。宿主只负责"这份文件在 FS 里存在"—— 现在就是 `fetchFont` 整份拿回来、
`FS.createDataFile` 灌进 MEMFS。

于是"字体缓存到硬盘"要分两档：
- **网络级缓存**（存整份，免得每次下载十几 MB）：Cache Storage / IndexedDB 都有，两条传输都能做；
  代价与现状相同 —— 内存里仍有一整份，进 MEMFS。
- **真按需读盘**（内存只留块缓存）：底层要能同步 `fread` 到磁盘。主线程没有同步 OPFS API，
  只有在 Worker 里用 `FileSystemSyncAccessHandle` 自己接一套 emscripten FS 后端才成立。
  ⇒ 这一档确实**只有 worker 能**（早先"两条都能"的说法对第二档不成立）。

兼顾的三条规则（这一轮落地的就是第一条）：
1. 实现差异只允许存在于"一个接口的两个实现"，且**公共构造只有一处**：`CanvasStore` 的两个
   实现现在都走 `stylePageCanvas(el)`，元素约定不再各写一遍（那正是"worker 加了定位、inline
   没加"的来源）。
2. 必须一样的地方用判据钉住，不靠端到端碰运气：`demo.spec` 新增"页画布与定位祖先的约定"
   （每张画布 computed position 必须 absolute、`#pages` 不能是 static），两条传输都跑，漏一边就红。
3. 能力差异写成**声明**（例如将来的 `supportsFontStreaming`），降级由接口说出来，而不是靠人记。
   判据也按能力分：worker 独占的能力只跑 worker，其余全部两边跑。
