页宽 x（窗口页数 x 步距），不再向引擎要。

**换层当场抓到一个真 bug（已修）**：改光标色 / 选区色 / 图片手柄色之后，屏幕上不变，
要等下一次该区域因别的原因被标脏才生效。根因是覆盖层的差集只比 layer + 矩形
（`overlayHas`），配色不属于任何矩形 —— 颜色变了、矩形没变，两个循环都不标脏，
脏区是空的，画布停在旧色上。读引擎帧永远看不见（帧是现场拼的，已经是新色）。
修法：`OverlayScene` 加 `style`（三色指纹）并混进 `overlayRoot`；present 时
`prev.style != now.style` 就把新旧两边的所有矩形全标脏。

- **教训：删导出的顺序是"先搬判据、再删导出"。** 反过来会分不清红的是"判据没搬完"
  还是"引擎真有 bug"。
- **教训：冗余的读法是 bug 的掩体。** 同一份真值有两条取法（引擎帧 / 画布）时，
  判据读哪条就决定它看不见哪类缺陷；删掉引擎那条，覆盖层配色这类"像素变了但账没记"
  的问题才浮出来。

## `msvc_env.ps1` 的 cl 版本探测（10-30）

- 症状：同一台机器上第一次进环境成功，第二次抛「cl 的输出不认识」。
- 根因（实测分流确认）：中文 VS 的 `cl` 把横幅（带版本号）写 **stderr**、把「用法:」写
  **stdout**；`2>&1 | Select-Object -First 1` 的合并顺序不保证，取到的可能是用法行。
- 改法：版本取 `$env:VCToolsVersion`（VsDevCmd 摆好，如 `14.44.35207`，与语言无关），
  缺席时取 `VCToolsInstallDir` 末段目录名；`cl` 只当"起得来"的探针（看 `$LASTEXITCODE`），
  不再解析任何文本。
- 顺带挖出第二个坑：Windows PowerShell 5.1 把原生命令的 stderr 当错误记录，`2>&1` 与 `*>`
  都一样，配上 `$ErrorActionPreference='Stop'` 直接中止；而 cl 无参数时横幅正是写在 stderr
  ⇒ 「检查 cl」本身成了故障源（`powershell -File` 一路必挂）。探针放进降过 EAP 的子作用域
  `& { $ErrorActionPreference='Continue'; & cl *> $null }`，5.1 与 7 都过。
- 已记入 `ENV.md`；这条坑在 10-26 / 10-27 的日志里反复出现过三次。

## 切样例时"跳到末页再回开头"（10-30 下午）

- 症状：点「示例」换一份文档，先整篇高亮，视口跳到末页，再回到第一页。
- 根因两处，都在"光标挪没挪"的判据上：
  1. `afterEdit` 用五项（段/偏移/侧别/行别/页）判位移。后两项是排版给的 —— 全选后改行距
     文档变长，同一位置从第 6 页变第 8 页、行别也翻，于是判成"挪了"并滚到文末。
  2. 选区类命令走 `caretOp`，不更新 `lastState`，那次位移留给下一条命令消费。
- 改法：`caretsMovedInText`（段/偏移/侧别）管滚动，`caretRelocated`（+行别+页）管
  caret 事件；`caretOp` 非 reveal 分支调 `dom.noteCaret(stats)` 只记基线。
  **不能**把基线同步塞进 `finish()` —— Worker 每拍都调它，基线会被推到下一条命令之前，
  连续粘贴就不滚了（试过，`clipboard.spec` 当场红）。
- 判据：`view.spec` 新增「全选之后改段落格式，视口不跳到文末」，反向一半钉 setCaret 仍会滚。
- 顺带：`edit-selection` 的光标面积判据在高负载下会读到上一档位图（0.4 磅量出 3 磅的值），
  改成改档后先 `H.flush()` 再 `PIX()`。
- 验证：dev 147 passed、dist 连跑两次各 147；`npm run check` 全绿。

## 行距倍数改成 1/240 的整数刻度（10-30 傍晚）

- 起因：面板回显 1.2999999523162842。`1.3f` 的二进制值就是 1.29999995，改显示治不了；
  要让文档里"1.3 倍"是个精确的十进制值，只有整数刻度能做到。
- 口径与 OOXML `w:line` 一致：240 分之一行，240 = 单倍，1.3 → 312。
  `ParaFormat::line_240` / `ParaFormatPatch::line_240` 是 int；引擎侧 `LineSpacing::factor`
  仍是 float（`lineFactorFloat()` 在编译时换算，排版只做乘法，像素不变）。
- 线上：文档 JSON 写 `"lf":312`（整数，不再写十进制字符串）；宿主公开面仍是小数倍数，
  折算只在 `web/src/editor.ts` 的 `LINE_FACTOR_UNITS`，折不成整数刻度当场抛 TypeError。
- 改到的点：`format_map.cpp`（换算）、`document.cpp`（摘要 f32 → i64）、`record_json.cpp`
  （读只收整数、写整数）、`engine.cpp`（回显）、`wasm_main.cpp`（只收整数）。
  六个夹具 `"lf":"1.275"` → `"lf":306`。
- 判据：doc_test 新增"312 写读一致 + 十进制文本被拒"；format.spec 新增"1.3 倍读回 1.3，
  且行高是单倍的 1.3 倍"。
- 验证：native 7/7；dist 147 passed；`npm run check` 全绿；format 156 文件合规。
