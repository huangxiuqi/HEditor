- 做法不是"删断言"，是**把同一条事实换到能证伪的那一层**：页位图自审
  （`auditPageJson` 的 `diff:0` = 缓存页 == 当前状态从零光栅）、排版摘要（`digestOf`）、
  `PlacedRow.cont_top/cont_bottom`（跨页切口要补线）、记录层字段（`glyph_color`、
  `value.flag`）。删掉的只有"画出来是几笔"这类纯光栅结论。
- 整节删除：[10] 光栅确定性、[16] 增量帧 vs 全量帧、[59] 接缝拼图、[75] 裁剪标记。
  前两条搬到 `render.spec.ts`（两次冷启动逐字节相同）、[75] 搬到同文件（四角有墨）。
  [59] 由 `view.spec.ts` 的接缝用例承担（那里看的是"接缝上的标记只有一道横笔"）。
- **教训：读画布要等两帧。** 呈现挂在 rAF 上，`H.flush()` 之后直接 `getImageData`
  拿到的是上一拍；而 `selfCheck` 比的是"画布 vs 引擎页缓存"，两边都旧时差额也是 0，
  判据会假绿。等两帧再读，问题当场消失。
- **教训：用 `rawFrame()` 断言"屏幕上有东西"是半循环。** 它是引擎自己那份缓冲。
  浏览器侧的正解是页画布（用户看得见的那层），`selfCheck` 的差额 0 用来显式证明
  "画布就是引擎当前输出"。
- 已知缺口仍红着：单段文档打字重贴整页（`render.spec.ts` 标了 `test.fail()`，
  修好后会变成"意外通过"提醒删标记）。

## frame 一路彻底删掉：判据全部改读页画布（10-30）

引擎不再导出窗口帧。删掉的是 `EditorEngine::frame()` / `ensureFrameExport()` /
`frame_export_` / `frame_export_valid_`、wasm 的 `frameRgba` / `frameByteSize` /
`frameWidth` / `frameHeight` 四个导出、api 的 `ink` / `inkRows` / `frameDigest` /
`rawFrame`（后三条零消费者，直接删）、diag 的四个成员、worker 的两个镜像 case。

判据侧新增 `PIX()` / `PIXH()`（`web/tests/support/readings.ts`）：等两帧 rAF →
逐页 `drawImage` 取画布像素 → 按"页号 x 步距"拼成与旧帧同形的 `{w,h,data}`，页间隙
填白。43 处 `rawFrame` / `frameDigest` 全部换成它，断言逻辑一字未改；`markCheck` 改从
`host.ctxOfPage` 的 `getImageData` 扫同一列。`selfCheck` 保留 `framePx` 形状，数值改成
页宽 x（窗口页数 x 步距），不再向引擎要。

**换层当场抓到一个真 bug（已修）**：改光标色 / 选区色 / 图片手柄色之后，屏幕上不变，
要等下一次该区域因别的原因被标脏才生效。根因是覆盖层的差集只比 layer + 矩形
（`overlayHas`），配色不属于任何矩形 —— 颜色变了、矩形没变，两个循环都不标脏，
脏区是空的，画布停在旧色上。读引擎帧永远看不见（帧是现场拼的，已经是新色）。
修法：`OverlayScene` 加 `style`（三色指纹）并混进 `overlayRoot`；present 时
`prev.style != now.style` 就把新旧两边的所有矩形全标脏。

- **教训：删导出的顺序是"先搬判据、再删导出"。** 反过来会分不清红的是"判据没搬完"
  还是"引擎真有 bug"。
- **教训：冗余的读法是 bug 的掩体。** 同一份真值有两条取法（引擎帧 / 画布）时，
  判据读哪条就决定它看不见哪类缺陷；删掉引擎那条，覆盖层配色这类"像素变了但账没记"
  的问题才浮出来。
- 收尾：`npm run check` 全绿（协议表 146 条 / wasm 导出 149，四份文件一致），
  dev 与 dist 各 143 passed；`format.ps1 -Check` 155 文件合规。
- 遗留：`wasm_main.cpp` 的 `writingModeFromCode` 是死函数（编译期 warning），
  与本轮无关，未动。
