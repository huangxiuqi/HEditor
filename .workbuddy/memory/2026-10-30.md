## frame 一路彻底删掉：判据全部改读页画布（10-30）

引擎不再导出窗口帧。删掉的是 `EditorEngine::frame()` / `ensureFrameExport()` /

判据侧新增 `PIX()` / `PIXH()`（`web/tests/support/readings.ts`）：等两帧 rAF →
逐页 `drawImage` 取画布像素 → 按"页号 x 步距"拼成与旧帧同形的 `{w,h,data}`，页间隙
填白。43 处 `rawFrame` / `frameDigest` 全部换成它，断言逻辑一字未改；`markCheck` 改从
`host.ctxOfPage` 的 `getImageData` 扫同一列。`selfCheck` 保留 `framePx` 形状，数值改成
页宽 x（窗口页数 x 步距），不再向引擎要。

**换层当场抓到一个真 bug（已修）**：改光标色 / 选区色 / 图片手柄色之后，屏幕上不变，
要等下一次该区域因别的原因被标脏才生效。根因是覆盖层的差集只比 layer + 矩形
（`overlayHas`），配色不属于任何矩形 —— 颜色变了、矩形没变，两个循环都不标脏，
脏区是空的，画布停在旧色上。读引擎帧永远看不见（帧是现场拼的，已经是新色）。
修法：`OverlayScene` 加 `style`（三色指纹）并混进 `overlayRoot`；present 时
`prev.style != now.style` 就把新旧两边的所有矩形全标脏。

- **教训：删导出的顺序是"先搬判据、再删导出"。** 反过来会分不清红的是"判据没搬完"
  还是"引擎真有 bug"。
- **教训：冗余的读法是 bug 的掩体。** 同一份真值有两条取法（引擎帧 / 画布）时，
  判据读哪条就决定它看不见哪类缺陷；删掉引擎那条，覆盖层配色这类"像素变了但账没记"
  的问题才浮出来。
- 收尾：`npm run check` 全绿（协议表 146 条 / wasm 导出 149，四份文件一致），
  dev 与 dist 各 143 passed；`format.ps1 -Check` 155 文件合规。

## `msvc_env.ps1` 的 cl 版本探测（10-30）

- 症状：同一台机器上第一次进环境成功，第二次抛「cl 的输出不认识」。
- 根因（实测分流确认）：中文 VS 的 `cl` 把横幅（带版本号）写 **stderr**、把「用法:」写
  **stdout**；`2>&1 | Select-Object -First 1` 的合并顺序不保证，取到的可能是用法行。
- 改法：版本取 `$env:VCToolsVersion`（VsDevCmd 摆好，如 `14.44.35207`，与语言无关），
  缺席时取 `VCToolsInstallDir` 末段目录名；`cl` 只当"起得来"的探针（看 `$LASTEXITCODE`），
  不再解析任何文本。
- 顺带挖出第二个坑：Windows PowerShell 5.1 把原生命令的 stderr 当错误记录，`2>&1` 与 `*>`
  都一样，配上 `$ErrorActionPreference='Stop'` 直接中止；而 cl 无参数时横幅正是写在 stderr
  ⇒ 「检查 cl」本身成了故障源（`powershell -File` 一路必挂）。探针放进降过 EAP 的子作用域
  `& { $ErrorActionPreference='Continue'; & cl *> $null }`，5.1 与 7 都过。
- 已记入 `ENV.md`；这条坑在 10-26 / 10-27 的日志里反复出现过三次。
