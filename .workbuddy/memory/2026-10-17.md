# 2026-10-17 工作台账

## 5.31 命中测试的输入口径：窗口坐标不是帧坐标

### 5.31.1 现象

**滚动几页之后，有的页面光标点不进去**（点上去没反应，或光标跳到别的页）。

### 5.31.2 最小复现

新探针 `out/_hitwin.mjs`：装载 2000 段（65 页）→ 滚到若干页 → 逐页点该页中部
（`H.clickAt(120, 窗口坐标 y)`）→ 读落点页号。

修前（worker 宿主）：

```
滚到页  窗口首页  页数  帧槽   点到的页 -> 落点页
     1         0     5     5   0->0 1->1 2->2 3->3 4->4
     3         2     5     5   2->5 3->6 4->2 5->3 6->4   << 错 5 页
     6         5     5     5   5->5 6->6 7->7 8->8 9->9
    20        19     5     5   19->20 20->21 21->22 22->23 23->19   << 错 5 页
    33        32     5     5   32->35 33->36 34->32 35->33 36->34   << 错 5 页
40 次点击里有 20 次落到了别的页
```

规律很干净：**窗口首页号是槽数（5）的整数倍时全对**（first = 0 / 5 / 10），
其余全错。错的时候落点页号 = `slot_page_[窗口内下标]`。

### 5.31.3 根因

帧改按页号分槽之后，我把 `hitTestPt` 也改成了"按槽表反推页归属"，理由是它与
`frameOffsetOfPage` 严格对称。**但两边输入口径不同**：

- 宿主 `framePointAt` 给的是**窗口坐标** = 文档坐标 - 窗口首页 × 步距；
- 槽表描述的是"帧里哪一格装着哪一页"。

两者只在"窗口首页号 ≡ 0 (mod 槽数)"时重合 —— 于是首屏与每 5 页起的那一屏看着全对。
错位时反查出的页号可能落在窗口外（那一格装的是窗口外的旧页），光标画不出来，
表象就是"点了没反应"。

### 5.31.4 修法

`hitTestPt` 只把窗口坐标折回文档坐标、按页高反查页号，**不读槽表**：

```cpp
const float doc_y = y_pt_win + static_cast<float>(base_first_page_) * stride;
page = std::max(0, static_cast<int>(std::floor(doc_y / stride)));
local_y = doc_y - static_cast<float>(page) * stride;
```

参数名 `x_pt_frame` / `y_pt_frame` 改成 `x_pt_win` / `y_pt_win`（`controlAtPt` 一并改）——
那次误判的起点就是这个错名。两处声明注释同步改成"窗口坐标"，并说明它与帧槽无关。

★ **输出侧不动**：`caretRectPt` / `selectionRectsPx` 含槽偏移是对的（宿主用
`frameSlotOf` 折回去）。只有输入侧错。别因为"两边看着对称"就把输出侧也改回去。

### 5.31.5 判据

`out/_hitwin.mjs`（新）。要点：

- 目标页列表（默认 1,3,6,7,11,20,33,47,60,64）覆盖"对齐"与"非对齐"两类窗口；
- **每页先重新定位窗口再算坐标** —— 单线程宿主里点击会把视口滚到光标处，
  连点期间窗口会变，逐页点的循环不重新读窗口就会把探针自身的行为报成错位
  （worker 侧没这个现象，因为它不经 `settle` 那条路）；
- 两宿主都跑（门面取值器分叉：worker 用 `H.geom`，单线程用 `H.viewport` + `H.pagePx`）。

结果：

| 宿主 | 修前 | 修后 |
| --- | --- | --- |
| worker | 40 次点击 20 次错 | **10/10 全对** |
| 单线程 | 10 次点击 10 次错（探针版次不同） | **10/10 全对** |

### 5.31.6 顺带清掉 6 个未用变量告警

帧分槽那次改动把"页在帧内的偏移"收敛进 `frameOffsetOfPage` 之后，
三处手算残留的 `page_px_h` / `gap_px` 就成了未用变量（wasm 构建 4 条告警）。
`caretRectPx` / `selectionRectsPxIn` / `drawControlMarks` 各删两行，wasm 构建 **0 告警**。

### 5.32 收尾：输入口径统一成文档坐标

5.31 的修法把 `hitTestPt` 折回文档坐标时读了 `base_first_page_`（渲染状态），于是留下
一个窄竞态：宿主"滚动后立刻点击"时，若引擎已按新窗口重画而宿主还没收到新几何，
两者对"窗口首页"的认知会差一拍（一次往返，5~17 ms）。

改成**文档坐标**（第 0 页顶边为原点）后，引擎与两宿主三边一致，`hitTestPt` 不再读任何
渲染状态 —— 竞态随之消失。**换算点一共四处**，漏一处就重新分叉：

| 处 | 文件 | 改动 |
| --- | --- | --- |
| 拖选取点 | `web/app.js` `framePointAt` | 去掉 `- windowFirstPage() * step` |
| 探针入口 | `web/app.js` `clickAt` | 去掉 `+ windowFirstPage() * step` |
| 拖选取点 | `web/worker_host.js` `framePointAt` | 去掉 `- gm.first * gm.pageStep` |
| 真实按下 | `web/worker_host.js` `onPointerDown` | `+ (page - gm.first) * step` → `+ page * step` |

★ 最后两处最容易漏：`onPointerDown` 是从**页元素 rect** 自己算的，不在"看起来像坐标
换算"的那一组里；`clickAt` 是探针入口，漏了会让探针与真人走两条口径。
引擎侧：`hitTestPt` 参数名改成 `x_pt_doc` / `y_pt_doc`，`controlAtPt` 同步。

探针：`out/_hitwin.mjs` 的点击坐标改成 `target * step + 0.35 * step`（文档坐标，与窗口
无关）。`scripts/edit_probe.mjs` / `worker_probe.mjs` 里的 `H.hit` 与 CDP 真鼠标都在
first=0 的小场景上，口径不变，无需改。

★ 探针里补了"按下事件"这一路：`clickAt` 走门面 `placeAt`，而真人按下走 `onPointerDown`
（从页元素 rect 自己算坐标）—— 两处必须同口径。`out/_hitwin.mjs` 现在也派一次合成
mousedown 到页画布上（worker 靠 `event.target` 的 `dataset.page` 认页，所以必须派到画布
而不是容器），两宿主各 **13/13**。

★ 选元素时踩到一条：槽池里没被这一窗用到的画布**留在 DOM 里、被 `display:none` 藏起来**，
`querySelectorAll("canvas[data-page]")` 会选中它们 —— 它们的 rect 全是 0，
选中了等于点到视口左上角（症状是"点了没反应、落点停在上一次的值"）。

## 5.33 全选后删除：7.4 秒 → 35 ms

### 5.33.1 现象

2000 段示例（160 页 @1.5 倍）**全选后删除耗时非常久**；**全选过程中画面分两拍** ——
先停在中间（画出滚动前那一窗的选区），再跳到文档末尾。

### 5.33.2 量法

新探针 `out/_selallcost.mjs`：A 基线空转 / B 全选后呈现 / C 有选区滚动 / D 无选区滚动 /
F 真 Ctrl+A 逐拍采样（光标页、窗口首页、scrollTop）/ E 全选后删除（三轮取最小）。

改前（worker）：`H.backspace()` 本身 **7375.6 ms**。

### 5.33.3 根因（四处，都是 O(位置数 x 扇出) 或 O(步数 x 节点数)）

| 处 | 成本 |
| --- | --- |
| `makeDeleteTextSteps` 逐位问 `posAt` | 120393 位 x 每次 O(扇出≈1000) |
| `eraseFlowSteps` 逐位找段落标记 | 同样 120393 位 |
| `applyStep` 每步重建 FlowIndex | 4000 步 x 3 次（`canApply` / `applyStep` / `collectCovers`）x O(节点数) |
| `makeRemoveParaMark` 每次自建索引 | 2000 次 x O(节点数) |

`posAt` 要从根下降到最内层，**每一层线性扫孩子** —— 2000 段的文档每次约 O(段数)，
而删除路径上"逐位问"的循环有两处。

### 5.33.4 修法

1. **`makeDeleteTextSteps` 改逐节点跳跃**：拿到当前文本节点后直接跳到它的流末端
   （节点区间两两不重叠），2000 段 → 2000 次 `posAt` 而不是 120393 次。
2. **`eraseFlowSteps` 的标记位置由块表给出**：标记夹在两段之间，位置就是
   `block_flow_[k] - 1`。不再逐位问 `posAt`。
3. **新增 `makeDeleteRangeOneStep`**：区间里全是文本与段落标记时，整段并成**一个**
   `DeleteRange`（`Fragment` 本来就支持多 piece：文本与段落标记交错）。`eraseFlowSteps`
   优先用它 —— 步骤数 **4000 → 1**，`applyStep` 的索引重建随之从 4000 次降到 1 次。
   区间里有控件/原子/容器边界时它返回空，调用方退回按节点切分那条路（安全阀不变）。
4. **流索引复用**：`collectCovers` / `makeRemoveParaMark` / `canApply` 各加一个收
   `const FlowIndex&` 的重载；`applyStep` 里判据与应用**共用同一份**索引。
5. **单线程宿主 Ctrl+A 不再搬视口**（`afterEdit({ scroll: false })`）：全选的焦点端在
   文档末尾，把视口拽过去等于整篇跳一次，而换窗要重画一屏（冷字形 100 ms 以上）——
   画面因此分两拍。主流编辑器的 Ctrl+A 都保持当前视图。Worker 宿主本来就不滚，改后两宿主一致。

### 5.33.5 数据（三轮取最小）

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 全选后删除（引擎处理） | **7375.6 ms** | **35.1 ms**（worker）/ 46.8 ms（单线程） |
| Ctrl+A 后的 scrollTop | +15 ms 跳到 180554（文档末尾） | **一直 0**（视口不动） |
| 有选区滚动 vs 无选区 | — | overlay 13.5~16.8 ms（其余零重画） |

★ 最后一行的对照是干净的：两次滚动**都零重画**（底图里已有那 5 页），只差"要不要画选区"。
换窗那一拍的选区绘制（125 条矩形）是下一个可见成本。

### 5.33.6 验收

见 `out/_seq_full4.log`；native 3/3、lint 0、native 与 wasm 构建均 0 告警。


## 5.34 选区绘制：按新旧差集，整窗那十几毫秒降到一页

### 5.34.1 目标

换窗 / 滚动那一拍的选区绘制（`paintOverlayMs`）是当时最大的可见成本：
全选 2000 段之后每一拍都要混合 64 万像素（125 条矩形），实测 8~17 ms。

### 5.34.2 三次尝试，前两次都不对

**第一次：只按 refresh 过滤**（"不在 refresh 里的像素本来就是对的，何必重画"）。
写完量了一次 —— **没生效**：`overlay` 仍是 6~10 ms。原因在下一行：擦除那一步把
`selection_rects_prev_`（上一拍的**整窗**选区）无条件加进了 `refresh`，于是 refresh
**总是**覆盖整窗选区，过滤等于没过滤。

**第二次：`sel_same` 整段跳过**（新旧矩形逐值相同就不擦不画）。它只覆盖"窗口完全没变"
那一档 —— 而 `selectionRectsPxIn(first, count)` 只返回**窗口内那几页**的矩形，
窗口内平移一页时新旧两批各差一页，`sel_same` 必然为假。实测：重画 0 页的拍降到 0.1 ms，
但**重画 1 页的拍仍是 8~10.5 ms**。

**第三次（正确形态）：新旧差集**。不再有的擦掉、新出现的铺底后画、**交集那一大片不动**：

```
for (q : prev_)  if (q 不在 sel_rects 里) refresh.push_back(q);   // 擦：这一拍不再有的
for (r : sel_rects) if (r 不在 prev_ 里) refresh.push_back(r);    // 画：这一拍新出现的
```

绘制那一遍仍按"与 refresh 相交"过滤，于是交集部分一次也不碰。`prev_` 在这一拍末尾
统一置成 `sel_rects` —— 交集部分没被重贴、仍在帧上，差集那几块刚画过，两者合起来
正好是"帧上真有选区的区域"（下一拍要擦的就是它们）。

★ 差集是这套增量绘制的**正确形态**：只要"上一拍画过的"与"这一拍要画的"都按差集
进 refresh，交集就不必碰。按"整批"处理（擦全部 + 画全部）等于把增量又退化成全量。

### 5.34.3 数据（`out/_selallcost.mjs` 的 G 段：逐页下滚 8 拍）

| | 改前 | 改后 |
| --- | --- | --- |
| 单线程 8 拍 overlay 合计 | 28.7 ms | **5.9 ms** |
| 其中"重画 1 页"的拍 | 8.0 / 9.4 / 10.5 ms | **1.5 / 1.7 / 2.3 ms** |
| worker 8 拍 overlay 合计 | 59.7 ms | **14.0 ms** |
| 重画 0 页的拍 | 6~10 ms | **0.1~0.2 ms** |

换窗那一拍（两边几乎不相交）退化成整窗重画 —— 那是**必要**的，新窗口的选区确实要画。

### 5.34.4 判据

G 段每一拍数一次"画布上偏蓝的像素"（抽样），判据用**有选区 vs 无选区**的差，
不假定某个具体颜色 —— 画面上本来就有偏蓝的像素（背景、字形），绝对阈值分不出
"选区画没画上去"。单线程：无选区 2.4 万 / 有选区 11.3 万 ✓。

★ worker 宿主读不到：它的页画布已经 `transferControlToOffscreen`，
`getContext` 会抛 `InvalidStateError` —— 探针里 catch 成 -1 并跳过这条判据（实测发现）。


## 5.35 连页模式（进行中）

### 5.35.1 目标与结论

一个视口画布承载整个视口，内容按滚动位置重贴；页间隙设 0，页首尾相接。

**现有性能优化全部带得过去** —— 因为它们在引擎侧，与"画布几张"无关：

| 优化 | 连页模式下 |
| --- | --- |
| 帧按槽布局（页号 mod 槽数） | 保留（帧怎么摆与画布无关） |
| 增量重画（脏页 / 槽过期 / 页指纹） | 保留 |
| 字形按页二分、编译增量、删除走一步 | 保留（纯引擎侧） |
| 换窗不搬帧像素 | 保留 |
| 上屏 | N 次 putImageData 到**同一张**的不同 y，实测 **1.13 ms** vs 分页的 1.54 ms |

关键未知先量掉了（`out/_blitprobe.mjs`）：同一张画布上连贴 5 页 **不比**分开贴贵
（1.13 vs 1.54 ms），只贴与视口相交的那段还更省（0.92 ms）。

### 5.35.2 已落地

- 引擎：门面加 `setPageGap(磅)`（`wasm_main.cpp`）—— 连页 0 / 分页 14。
- Worker（`engine_worker.js`）：`continuous` 与 `viewCtx` 两个状态；`blitPageContinuous(p)`
  按文档坐标贴（目标 y = 页号 x 步距 - 滚动量）；`blitPages` 在连页下每拍重贴并先 `clearRect`
  （视口内可能露出没有页的地方）；`pageGap` / `viewCanvas` 两条消息。
- 宿主（`worker_host.js`）：`setViewMode('paged'|'continuous')` 门面 + `viewMode` 取值器；
  `syncViewCanvas` 建一张视口画布（挂在页容器**外面**，放里面会随内容滚）、只交一次；
  `onPointerDown` 在连页下**由坐标反算页号**（没有页画布可问，`ev.target` 是占位 div）。
- `worker.html`：工具条加「视图」下拉（分页 / 连页）。

### 5.35.3 已验证（`out/_continuous.mjs`）

### 5.34 连页模式修错（用户报"用不了"）

用户报：切到连页后整页停用（横幅"宿主处理引擎状态时抛异常"，
`DataCloneError: An OffscreenCanvas could not be cloned because it was not transferred`）。

三处错，全是我 5.33 那版自己引入的（细节见 TRAPS 70）：

1. `syncViewCanvas` 交视口画布时**漏了转移列表**（`post({canvas: off})` → 应为 `[off]`）。
2. 改页间隙只重排、**不重绘帧** ⇒ 贴出去的是"新步距 x 旧像素"，第二页起整体错位，
   且槽表被记成"已贴过"，之后再也补不回来。修法 = `syncFrameSlots()` +
   `relayoutAndPaint()` + 作废槽表 + 重贴（四步，缺一不可）。
3. "窗口没变就只回 ack"在连页下不成立（视口画布不动，落点随滚动量算）⇒ 滚动后画面
   停在上一拍。修法 = ack 那条分支上，连页且滚动量变过时补一次重贴。
4. 提前量拆开：`view` 消息改成 `scrollY`（真实）+ `leadPx`（只喂 `visibleRange`）。
   连页下 `scrollY` 直接决定落点，混进提前量会让画面跑到滚动位置前面。
5. 顺带修 `positionIme`：`gm.first * pageStep + caretY` → 按页号 + 页内 y（帧槽与窗口
   偏移混用，与命中测试那次同类）。

判据：`out/_continuous.mjs` 从"配置层断言"升级为**像素级**——

### 5.35 真连页：排版层不再分页（用户澄清后的重做）

用户澄清："连页模式是直接去掉分页，没有页的概念了，内容都是连一起的"。
5.33/5.34 那版只是把页间隙设成 0（内容照样在页底断开）——方向不对。用户定了两件事：
**正文列宽仍用 A4 正文宽**（断行口径与分页完全一致）、**一整条连续白底**（不画页边框）。

**核心设计**：页号在连页下退化成"渲染条带号" = `floor(块轴位置 / 条带高)`，条带高 = 页高 + 页间隙。
这样帧的槽、光标、选区、命中测试读的仍是"页号 + 页内坐标"，**绝大部分下游代码一行不用改**。

落地（六处）：
1. `PageMetrics` += `continuous` / `slab_pt`（+ 进 `operator==`，切模式才会重排）；
   `EngineConfig` += `continuous`；`setConfig` 里装配（`slab_pt` 只在连页下给值，
   免得改页间隙牵动分页的"要不要重排"）。
2. `layout.cpp`：三条断页判据（页底溢出 / 显式分页符 / 竖排吃页尾）全部短路；
   页号由 `slabOfY(y)` 现算；**所有写进 LineBox / PlacedGlyph 的 y 都过 `locY()` 减条带偏移**
   ——漏一处就是那一处按绝对坐标落进帧里（跨条带整体错位一条带）。
   字形按**自己的** y 取条带（不跟行盒走），否则跨条带那一行的尾字会被画到条带框外。
3. `engine_paint.cpp`：连页下条带整幅填页面底色（= 一整条连续白底），不画边框、不擦页间隙。
4. `engine.cpp`：`hitTestPt` 在连页下按**文档 y** 找最近的行（按页号筛会漏掉跨条带那一行的尾段）；
   `contentBottomPx()` 新增（内容底边 = 滚动高度）。
5. `wasm_main.cpp`：`setContinuous` / `contentPx`。
6. 宿主：`syncSpacer` 连页下高度取 `contentPx`、底图换成一条白列；worker 把 `contentPx` 随 geom 报来。

**判据**（成对，能证伪）：
- native `edit_test` 第 [40] 段（10 条）：分页下跨页那两行的间距 ≥ 页间隙 + 2 倍边距、
  墨迹永远够不到条带底；连页下最大一跳 = 段间距、墨迹跨过条带底（实测 -15.38 磅）、
  条带数 12 → 7。共 1006 项断言、0 失败。
- web `out/_continuous.mjs` 新增像素判据（`inkRows` 读数）：连页下条带里**非白底行 0 行**、
  跨条带行距 4~35 px vs 条带内中位 36 px（内容不断）；分页的反向一半：非白底 126 行、
  跨条带 217 px。外加滚动高度 = 内容底边。
- 截图对照：`out/_shot_cont.png`（连页：一条白底、行距一路均匀、138 页）vs
  `out/_shot_paged.png`（分页：页间隙 + 页边框、160 页）。

★ 判据写错过一次：第一版断言"分页下文档 y 会回跳"—— 实测它**不会**（页号乘上条带高

### 5.36 四个报障（选区变深 / 连页点哪都在行尾 / 长文档末尾偏下 / 页面滚动条）

1. **选区颜色随光标闪烁逐渐加深，最后字被叠成底色**（看上去是"空白的蓝条"）。
   根因：选区是叠加式混色，而增量绘制里 refresh 常常只有光标那一小条，代码却把整块矩形
   再混一遍 ⇒ 每闪一次深一层。修法：**要重画的选区矩形整块进 refresh**（先整块铺回底图再
   混一次），幂等。判据 `out/_repaint.mjs`（帧指纹：同一状态重画 4 轮一字不变）。
2. **连页下点击光标总落在行尾**。根因：worker 宿主按下时 x 从"被点中那张画布"的 rect 量，
   而连页下没有页画布、基准换成了页容器 —— 少减了页列的横向居中偏移 `lastPageX`。
   修法：点选与拖选共用 `framePointAt`（一处换算）。
3. **2000 段文档最后几页点击偏下**。根因：页步距被算了两遍（宿主整数像素步距 1142 px
   vs 引擎磅步距 855.89 磅 = 1142/1.3333 = 856.5 磅），每页差 0.61 磅，第 160 页累积约 130 px。
   修法三条见 TRAPS 73。判据 `out/_hitfar.mjs`（各页落点差恒为 -23~-31 px）。
4. **页面总有一条外层滚动条**。两个来源：① 工具条 `calc(100% - 74px)` 魔数（加了「视图」
   下拉后工具条换行）；② 输入法框跟随光标跑出视口、`#overlay` 不裁剪把它顶出 body。
   修法：纵向弹性布局 + `#overlay { overflow: hidden }`。判据在 `_repaint.mjs`。
5. 顺带：**拖拽期间光标会闪** —— 拖拽每一步没按住闪烁计时器。修法：`dragExtendTo` 里
   `blinkHold()`，且拖选进行中整个停掉闪烁（手指停住不动时没有"拖了一步"可挂）。
