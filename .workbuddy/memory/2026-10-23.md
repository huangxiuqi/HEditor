## 格式"没反应"三条真实根因（用户第二次报）

用户：选中一段文字，点加粗/斜体/下划线"肯定有不好使的，甚至三个都不好使"，以及
"改完格式画面不更新问题还在"、"新输入的文本没继承前面的格式，反而前面的继承了后面的"。

- **画面不重画**：页内容指纹 `mixGlyph` 只混 glyph_id/x/y/rotate/cluster/颜色。斜体是合成
  倾斜（不改推进）、下划线另画一条线、单字行的字号与字重都不动 x/y —— 指纹一样，页位图被判
  "新鲜"，跳过重画。补 `italic/underline/size_pt/weight`（`PlacedGlyph` 加 `weight`，由
  `stampRunMarks` 填）。上一次修的 `shapingFingerprint` 字重是"排版没跟上"，这次是"画没跟上"，
  两条链路（TRAPS 195）。
- **敲字不继承**：段落末尾的流位置落在**段落标记**上（它占 1 个流位置），`posAt` 下沉到标记

  最近的文本兄弟，先左后右"（TRAPS 196）。

## 编辑器内复制粘贴丢样式 / 高度变高：根因不在片段，在宿主剪贴板

- 先证引擎侧是干净的：新增 `edit_test` [65]（全选 → `copySelection()` → 全选 → 粘回）
  段落数 3→3、总高 100.578903→100.578903 磅、粘回来的字仍是 `{"b":true,"sz":20.0}`。
  片段（fragment JSON）本来就带 `marks`：`collect` 的截断分支、`specOf`、`materialize`
  三处都搬了它。
- 真正的断点在浏览器：自定义 MIME（`application/x-heditor-fragment`）不保证穿过剪贴板 ——
  paste 事件的 `getData` 只给标准类型，`navigator.clipboard.read` 没授权时整条拒绝。
  于是粘贴退化到 `text/plain` ⇒ 样式没了（走 `pastePlainText`），而且纯文本以 `\n` 结尾
  时多拆出一段空段 ⇒ "高度高了一点"。两条症状同一个根因。
- 修法：宿主记一份"最近一次写出去的载荷"（`clipboard.ts` 的 `lastPayload`，写入的两条路
  都记；写空片段 = 清空缓存）。粘贴时：事件里有自定义类型就用它；只有纯文本且文本相等 →
  用缓存里的片段（`recallPayload`）；程序化粘贴读不到剪贴板 → 用 `latestPayload()`。
  编辑器内往返从此不依赖任何权限。
- 判据：`clipboard.spec`「编辑器内复制粘贴：样式跟着回来，段数不变」（copy → paste 之后

## 跨实例/跨浏览器复制粘贴：片段改随 text/html 走

- 现象：同实例粘回有样式了，跨实例没有。原因是"最近一份载荷"只活在一个页面里（模块变量），
  而自定义 MIME 过不了剪贴板边界。
- 参照 DCWriter 的口径（"支持纯文本、HTML 与私有格式"三份并用，浏览器里能靠的只有标准
  类型）：把私有格式**藏进 text/html** —— `<div data-heditor-fragment="<转义后的片段 JSON>">`
  + 正文 HTML。别的应用忽略这个属性，本编辑器读得到完整片段；跨实例、跨浏览器同一条路。
  读侧顺序：自定义 MIME → HTML 属性里的片段 → 最近一份载荷（同页）→ 纯文本。
- 判据：`clipboard.spec` 跨实例那条补了"片段能藏进 text/html 并原样取回"；剪贴板 spec 12 项、
  multi+demo 5 项全绿，`npm run check` 0 违规。

## 读了 DCWriterLite 的源码：它的剪贴板也是"私有格式 + 藏在 HTML 属性里"

位置（`D:/Develop/DCWriterLite`，WinForms + WASM 双版）：

- 私有格式名：`WriterConst.XMLDataFormatName = "DCWriterXML20240201"`（`Source/DCSoft.Writer.Core/WriterConst.cs:15`）。
- 复制构造：`DocumentControler.CreateSelectionDataObject`（`Source/DCWriterForWinForm/Writer/Dom/DocumentControler.cs:1127`）
  —— 同时放**纯文本**（全文；另有一份 1024 字符的 Title 作预览）、**图片**、**私有 XML**
  （选区单独序列化成一份文档），再加一个 `WriterHandle` = 源控件句柄。
- 浏览器侧的第二条道（关键）：`wwwroot/_framework/WriterControl_UI.js:1883-1895`（`PasteDateFromUTF16`）
  —— 粘 HTML 时找 `[dcxmlshow]` 属性，有就把它当成私有 XML（没有这一项就 push 一份），
  然后把属性从 DOM 里 remove 掉再粘。也就是说**私有格式是藏在 text/html 的属性里过剪贴板的**，
  不指望自定义 MIME 能活下来。
- 同源判断：`WriterViewControl_MouseEvent.cs:275` 用 `WriterHandle` 比"是不是同一个控件"，
  同控件拖拽按 Move 处理（我们现在的 `lastPayload` 用文本相等来判同源，弱一档）。
- 纯文本在 HTML 里没有元素时降级成 `text/plain`；>50 KB 的复制在 500 ms 内拒绝重复触发。

结论：我们今天的做法（片段藏进 `text/html` 的 `data-heditor-fragment` 属性）与它同一条路，
可以补的两处：一是同源判断改用片段里的实例 id 而不是文本相等；二是将来若要做 HTML→文档
导入，解析前先把那个属性剥掉。

## 剪贴板同源判断改成本实例 id（照 DCWriter 的 WriterHandle）

- 宿主每次建实例生成 `instanceId`（`crypto.randomUUID`，退化到随机串）；载荷 `ClipPayload`
  多一个 `origin` 字段，写剪贴板时记进去。
- 缓存检索（`recallPayload` / `latestPayload`）从"纯文本相等"改成"**必须同源** + 文本相等"：
  文本相等不等于同一份内容 —— 用户在别处复制了同样的字、格式可能完全不同，拿旧片段去粘
  就是拿旧格式覆盖新内容。
- HTML 载体上另加 `data-heditor-origin`（只记出处，粘的时候不据此拒绝：跨实例本来就要能粘）。
- 判据：`clipboard.spec` 跨实例那条补了三条 —— 同源命中、异源（文本相同）不认、
  读不到剪贴板时也只认本实例那一份。剪贴板 spec 12 项、multi+demo 5 项全绿，check 0 违规。

## 两条都定案并修好：页指纹漏了行结构 / 末段标记够不到

前一节的"问题在宿主/门面那一层"判断错了。两处都在引擎，且都用 `edit_test` [67] 复现：

- **空段标记不出现 = 页被判成新鲜，一次都没重光栅**。末尾连按三次回车只多出三条行盒、
  一个字形都没多，而 `computePageFingerprints` 只混字形 ⇒ 页指纹不变 ⇒ 直接跳过重画。
  "一改文字样式就出来"正是字形变了才触发整页重光栅。修法：把 `computeLineFingerprints`
  的产物按页混进页指纹（只混重算范围内的页），行指纹补 `size_pt` / `bracket_axis_pt`。
- **末段没有选区 = 它那枚段落标记不在任何一块的内容区间里**（`extent.span` 只数内容），
  `selectAll` / `setSelection` 的钳位上界正好是标记位本身。横排 [66] 里"三条矩形都在"
  说的是**末段文字**那一条，标记那一条从来没有过 —— 上一节把这两件事混了。
  修法：`selectionRectsIn` 按"正向（anchor < focus）且焦点在文档末"给末行补一条；
  空段走原有窄条分支，有字的末段把那枚宽度并进本行矩形（另推一条会重叠 → 深色缝）。
  反向选到末位不补（与字处理软件一致，这也是用户观察到的方向差异）。

判据 `edit_test` [67] 共 18 条：横排（三次回车后三个空段墨迹 + `auditPage` diff 0 /
正选 5 条 / 反选 4 条 / 末段有字时末行宽出行末一枚 / 末列窄条）与竖排（4 列都有墨迹、
末列矩形 19.2 × 4.2、`auditPage` diff 0）各一组。竖排段各占一整页，取墨迹要逐行用它
自己那一页的 `pagePixels(lb.page)`。
