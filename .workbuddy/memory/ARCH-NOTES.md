## 核心机制
- 光标真源 = `Range selection_{anchor, focus}`；`caret()` 是 focus 的投影，写入口只有 `setCaretRel`；重编译必须落基 —— anchor 与 focus 两个读数都要在 `block_flow_.assign` 之前取。
- 拖选 = 按下定位 + 移动只搬 focus；**收尾信号不止 mouseup** ⇒ 一并收 pointerup / pointercancel / dragend / drop + 判 `ev.buttons` bit0。
- 编辑入口先吃选区（8 个：插类删完继续，删类删完即止）；跨段删除走 `eraseFlowSteps`：**整段并成一个 `DeleteRange`**（Fragment 支持多 piece，文本与段落标记交错；`makeDeleteRangeOneStep`），退回"按节点切分"那条路，**从后往前**带安全阀。★ 区间里逐位问 `posAt`（O(扇出)）就是亿级 —— 2000 段全选删除 7.4 s → **35 ms**；判据 `out/_selallcost.mjs`（三轮取最小）。
- ★★ **选区两条线，不是粗细两档**：文字选区只盖文字（拖选 / Shift / 程序化设区间），单元格选区整格反白（含内边距与显式行高撑出的空白）。产生它的只有三种几何手势：点格左侧边距带、三击、**拖选跨过两个格**。★ 跨没跨格**由引擎判**（`syncCellSelection`，接在 `projectCaret` 的 extend 分支 —— 宿主只给落点，没有表格结构；键盘 Shift 扩展因此同口径）：两端都在格内且不是同一格 ⇒ 整格，否则文字（含拖回起手格、拖出表格）。★★ **一格的身份是块区间，不是流区间**（`CellBlocks{first,count}`）：空格内容长度为 0，流区间退化成点，与下一格第一段共用同一个流位置 ⇒ 按流位置既选不中它、也画不出一条高亮（"空单元格无法选区"就是这个）。流包络只剩摘要用（选区报告 / 撤销快照 / 覆盖输入）。★★ **反白铺格的外框**（`cell_box_lo/hi`，格线本身），不是内容区 `cell_lo/hi` —— 后者两侧各让出一层内边距，拿它铺就是"选区左右还有缝"。命中给的是**段号** `cellPara`（`selectCellAtPara`），宿主不搬流区间。★★ 两份读数分工：`sel_` 是用户落下的位置（`rawSelection`，拖回起手格时靠它退回文字），`cell_lo_ / cell_hi_` 是这些格的流包络（可以退化），`selection()` 返回它（方向跟 focus 走）。渲染与编辑必须读同一个 `selection()`。★ 整格删除走 `eraseCellContents`（逐格清空，格与格之间的结构不动）—— 按整条区间删会把单元格边界卷进去、安全阀过不去 ⇒ 表现是"选中几格按 Del 没反应"。★ 三击**不能读 `ev.detail`**（pointerdown 上恒为 0，规范只给 mousedown 定义），两宿主各一份 `clickCountOf` 自己数。★ **插入点钉在焦点那一格的末尾**（`cell_caret_`，`caretPara/caretRel/caretSide` 统一走 `caretFlow()`）—— 从 `sel_.focus` 派生的话光标会跟着鼠标在格内逐字跑；`sel_.focus` 仍留原值（拖回起手格靠它）。★★ **会改帧的入口必须是命令（WRITE）**：worker 的查询（READ）只回一个值，不 present、不 `blitPages` ⇒ 帧画好了画布还是旧像素，要等下一次闪烁相位（530 ms）才重贴，量到 557 ms；走命令后 4~23 ms。判据 `edit_test [48]` + `out/_tabledrag.mjs`（后者量"三击之后 250 ms 内推出新状态且 label 是 cellSelectAt"）。★★ **`setCellBlocks` 一个字都不写回 `sel_`**：拖选每动一步都靠 `rawSelection()` 判"两端还在不在同一格"，把锚点改写成包络之后**反向拖选（从下往上、从右往左）再也长不回去** —— 实测整格反白直接消失（命中 0 份矩形）。单格吸附（点边距带 / 三击）由 `selectCellAtPara` 先 `setSelection({格首,格末})`，这是唯一该搬端点的地方。★ **空格也只留左边那一条边距带**（外框到文字左沿）：整格都算的话点空格任何地方都成了"选整格"，光标放不进去。★ 这类判据必须**逐步拖**（按下落一次锚点 + 每步只搬焦点，且每步断言），"一次 setCaret + 一次 setFocus"的助手每次重设锚点、把错整段盖住（TRAPS 95）。
- ★ **控件边界上的删除只有两条出路：删内容里那一项，或者（控件空了才）删控件本身**。四条规则（`bracketBackspace` / `bracketDeleteForward`，返回 `BracketHit{None,MoveOnly,MoveThenErase,Handled}`）：退格贴闭括号右面 ⇒ 进控件删左边那一项；退格贴开括号右面 ⇒ 退到开括号左面不删；前删贴开括号左面 ⇒ 进控件删右边那一项；前删贴闭括号左面 ⇒ 跳到闭括号右面删右边那一项；四种情形下控件为空都直接删控件。"进控件"**递归**（内容最后一项是非空控件就再进一层）。判定只能落在**流位置**上（这些格子两两共用同一个码点偏移）。★ 旧行为"退役控件、内容留成正文"（拆壳）**从键盘路径撤掉**，`removeControl(keep_content)` 这个 API 保留给宿主按钮。★ 后果：**"内容全空但控件都还在"按键到不了**（删掉最后一个字后光标就在空控件内部，再按一下删控件）—— 要构造它只能显式建树。★ 表单模式的 `structureLock` 只挡"删控件"那一下，挡不住时退化成"只把光标移出去"+记账，不吞按键。
- ★★ **`InsertNode` / `RemoveNode` 也必须按流位置定位**（TRAPS 39 那条只改了 `UnwrapNode` / `WrapNode`）。漏了的症状：删控件之后**撤销永远失败**，`while (canUndo()) undo()` 那种写法把它变成**死循环**。`applyStep` 用 `slotAtFlow`（必要时切文本节点），`canApply` 用 `slotForFlow`（只读）。★★ **取"某个孩子自己的槽位"不能用 `posAt`** —— 它对**叶子**孩子把"流位置 == 叶子起点"归给叶子自己，于是容器找出来的是那个叶子（报"目标不是容器"）。
- ★ **删控件的撤销快照记"按键之前光标在哪"**：`removeControl(index, keep_content, caret_before = -1)`，键盘四个调用点传当时的 `selection_.focus`；不传（-1）时按"选中整个控件"记（显式按钮的叙事）。判据要两条一起：光标回位 + `hasSelection()` 为假。
- ★ **光标与位置解析独立成类 `CaretResolver`**（`engine/caret.h` / `caret.cpp`，2026-10-18）：位置代数、选区与光标状态、行盒几何与命中、光标移动全在它里面；引擎的公开方法只剩 1~8 行前向器。★ 留在引擎的是**帧像素与帧槽偏移**、`hitTestPt`（要页像素步距）、**重排触发**（聚焦档下移动光标会换占位集合 ⇒ 要重排，移动族入口是"记计划 id → 调解析器 → 按需重排 → 行首行尾再投影一次"）。输入是只读视图 `PositionView`（9 个指针）——★ 视图只存**地址**，所以摆的时机是正确性的一部分（`init` / `setDocument` / `rebuildFromTree` / `relayout` 各摆一次）；★★ `flow_` 要持 `std::optional` 的地址而不是它内容的地址（持内容会在第一次重建时拿到空指针并一直空下去）。下一刀是**命令层 `EditCommand`**。
- ★ **编辑操作独立成命令层 `EditCommand`**（`engine/edit_command.h` / `edit_command.cpp`，2026-10-18）：插入 / 删除（含控件边界四条规则）/ 分段合并 / 缩进 / 结构操作 / 选区删除前缀全在它里面；引擎的编辑入口只剩 1~3 行前向器。★ 留在引擎的是**编译产物重建**（命令只交事务，出口是 `EditHost::commitEdit`，`EditorEngine` 私有继承 `EditHost`）、`loaded_`、`markAllLayoutDirty`（由 `setControlProp` 的 `PropResult::Structural` 带出）。输入 `EditView` 存容器地址（同 `PositionView` 那套）。★ `ParaDelta` 已从引擎内嵌提到 `edit_command.h`。★ 引擎侧拆分到此为止，剩下三项被阶段 4 / 5 / 6 卡着。
- ★ **行内原子（图片 / 公式）已进流**（阶段 4，2026-10-18）：模型有 `ImageSpec` / `FormulaSpec`，编译产 `InlineObject{kind=Atom}`（盒宽高在编译层定死），排版按"不可断的盒子"参与断行（★ 行高 = `max(行距, 内容高 + 行距 - 文本高)` —— 盒子撑高的是内容、行距是段落属性，取 `max(行距, 盒高)` 会让下一行贴着盒底排，见 TRAPS 92），引擎按"开 / 非开"分桶计入 `BracketCounts`、不被括号名单筛掉、后缀复用不把它当占位。绘制是**显式占位框**（不做伪渲染）。★★ 原子与括号共用"占位簇"，但原子的 `bracket_side` 是 **None**：绘制侧必须按 `== Open` 正向判，"不是闭括号就是开括号"那种写法会给每枚原子画出一枚开括号（TRAPS 89）。★ 新增 `Node` 字段必须同步四处：`NodeTree::assignFrom`、`NodeSpec`（capture / materialize）、序列化读写 —— 漏一处是**静默丢字段**。★ `demoTree` 是**有损转换**（只读文本与块级字段），锚点这类只在对象表里的信息要显式重建（TRAPS 91）。★ **原子删得掉**：删除是一条白名单（文本 / 段落标记 / 原子三类各产一种步骤，`eraseFlowSteps` 的安全阀按覆盖长度卡）—— 加一种新的流内容时先问"它在删除的两条路上各产什么步骤"（TRAPS 93）。
- 树是唯一装载 / 编辑入口；编译与排版都是增量的；空段落必须占一行。
- 编译层按"段数变化的形状"选路（`ParaDelta`）：段数没变 ⇒ 只编一段；第 at 段之后插入一段
  （分段）⇒ 只重编被劈开的两段（`rebuildAfterSplit`），其余段产物按段号平移；形状不认识
  （控件结构操作）或前置不满足 ⇒ 整树重编。★ 新标记的定位是"在原标记所在容器里往回找最近
  的一枚段落标记"（插入点在段的内容中间，两者不是紧邻兄弟）。实测：编译那一项 **8.5 → 0.00 ms**
  （同一产物内与"合并走整树"的 3.90 ms 对照）。★ 首段分段与合并仍走整树兜底。
  ★ 诊断字段 `rebuildPath`（0 整树 / 1 单段 / 2 分段）与 `rebuildReject`（被第几条判据否决）。
- 交互入口全走 `opUser` / `blinkHold`；指针事件委托挂滚动容器、末尾必须 `ta.focus()`；`present()` **只画不排**。
- ★ **光标位置有四个分量**：(段, 码点偏移, 侧别, **行别**)。折行处"上一行行尾"与"下一行行首"是同一个位置
  （偏移与侧别都一样），只有行别分得开 —— 0 贴上一行（默认，任何别的定位都清回 0）、1 贴下一行（只有点击会翻）。
  命中测试算（`cp == first_cp && first_cp != 0`）→ `hitTest` 的 `line` → `setCaretAtSideLine`（拖选是
  `setFocusAtSideLine`）→ `findLineFor(pos, aff)` 与五个读行盒处都要吃它。漏一处 = 点行首跳到上一行行尾。
- ★ **方向键 = 物理方向等于视觉移动方向**（Chrome 实测，`out/_vkeyref.mjs`）：横排左右走字/上下换行；
  竖排**上下走字、左右换列**。换列往哪边由**列序**定，不只由"竖不竖排"定：中日 `vertical-rl` 往左、
  蒙文 `vertical-lr` 往右 ⇒ 宿主键位表吃 `caretVertical` + `caretBlockReversed`（取自段自己的书写模式，
  别用行盒的 `sideways` 代用）。判据要两半：ArrowLeft 一律往屏幕左 + 文本前后随列序翻转。
- ★ **undo 恢复的是事务里的 `selection_before`**：删除类操作必须记"删除之前光标在哪一端" ——
  退格/反缩进在**终点**（`eraseOnTree(..., caret_at_end=true)`），前删在起点。记错一端 = undo 后光标
  落到被恢复字符的前面。判据写"撤销后偏移回到编辑之前那一格"，一条压住三条路径。
- ★★ **表格是扁平化进块流的**（阶段 5，2026-10-19）：每块带 `cell_path`（外层到内层），
  格内段落是独立段。三条连带：① **格内段落必须以段落标记结束** —— 块与流位置的映射靠标记
  递推，无标记的格后面接下一格时起点会停在格边界上（编辑与审计同时红）；② `finishRebuildFromTree`
  的段起点取 `max(上一条递推值, 本块 first 的区间起点)` —— 表格的格边界夹在两者之间，控件从中间
  切开的场景仍取递推值；③ **有表格时一律不做增量**（`can_resume` 与 `trySuffixReuse` 都直接
  返回空/假），续排状态只有页号 / 块轴 / 行数三个标量，"第几行第几格"续不上。
- ★ **行高 = `max(内容高, 显式行高)`，内容高 = 最后一行盒底 + 上下内边距 - 最后一段的段后距**；
  格内可用宽 = `列宽 - 2 x kTableCellPaddingPt`。跨页两档：`can_split_by_page` 真 ⇒ 按行盒切片
  （切点落在行与行之间），假 ⇒ 整行挪到下一页。切点不画横线靠 `PlacedRow::cont_top/cont_bottom`
  —— 绘制按"每个格自己的外框"画，合并格内部因此不会多出线。
- ★★ **表格让"同一块轴位置上有多个行盒"成为常态**（一行的几个格各一个行盒、y 完全相同）。
  三处必须成对处理，漏一处的症状都在"看起来没反应"那一类：① **行带**（`lineBand`）的上下
  边界按"同一 y 的整组"算 —— 取"与下一个行盒的中线"会拿到同一行的另一格，带只盖住字的上半，
  重画后**字被裁成两截**（用户报"输入不更新"）；② **命中**并列时用 `LineBox::cell_lo/hi_pt`
  （格左右边界）比 x，不能用行内文字范围 —— 否则点格子后半跳到下一格；③ **格线**按行矩形
  （放置前顶到放置后底），不按行盒范围 —— 否则 `AtLeast` 行高的空白段没有线，一行断成两块。
  ★ 抓 ① 只能用**底图 vs 从零全建**（`auditBaseJson` / 宿主 `auditBase`）：帧从底图搬，
  `auditFrameJson` 与屏幕自检全绿（注入旧口径实测底图差 555 像素、帧自检 0）。
- ★ **切格也要结算上一格**：`openCell` 一开头先 `closeCell()`，否则"同一行里切到下一格"时
  上一格的内容高从没被记（`row_content_h` 停在上一次），**格内多行不撑开行高**、下一行压上来。
  判据必须用**两列**的形状（单列时切格与切行同时发生，走会顺带结算的那条路径，抓不到）。
- ★ **格线一条边只画一次**：相邻两行各画自己的下边与上边，两条 1px 线错开一格就是"边框怎么
  这么粗"的真因。现在每行只画上边、只有表格最后一行补下边；跨页片段的切口两边都不画。
  颜色 `table_line` 比页边框更浅（格线成片出现，同深度会显得加粗）。★ 探针里硬编码了这个颜色
  （`out/_table.mjs` 的 `LINE`），改颜色要同步改它。
- ★★ **表格的删除有且只有三种，键盘首尾不删表**（2026-10-19 撤掉 `eraseTableBeside`）：
  ① 单元格选区 ⇒ 逐格清空，格与格之间的结构不动（`eraseCellContents`）；② 文字选区**完整跨过**
  整表 ⇒ 删节点（`eraseWholeTables`，判据按**块区间**：`covered && (from < blo || to > bhi ||
  whole_doc)`，"覆盖整表但两头都在表内"要拒绝）；③ 其余按流区间删。**格内第一段开头退格、
  末段结尾前删什么都不发生** —— 曾经为了"删空一格后能删表"留过一条"格首退格删整表"，它与
  `sameCellBlocks`（格首不动）语义相反，后果是**连按退格删空第一格再按一下就整张表没了**。
  要删表只能用选区选上。★ 段落合并必须过 `sameCellBlocks` 守门：跨格合并只会删掉格尾那枚
  段落标记（结构位），不会把两段并起来，结果是前一格少结束标记、内容删空后整块消失、
  格子没有行盒 ⇒ 命中落不到它（"有的格子点不进去"）。
- ★ **删表之后 `tables_` 变空，但** `can_resume` / `trySuffixReuse` 还必须看 `layout_.placed_tables`
  是否为空 —— 否则这一下被当成普通编辑，`layout_` 里全是带表格时排出来的行盒（实测 `auditLayout` 差 8）。

## 坐标与可见性（2026-10-20）

- 流位置是**（位置，可见性）二元组**：呈现态下隐藏子树整棵不在流里，同一个整数在两种口径下
  是两个落点。携带它的类型必须带 `FlowVisibility`：`rev::applySteps(doc, steps, vis)` 与
  `rev::damage(before, after, vis)`，**都没有默认值**；`Edit`（para, cp）不需要，因为段落
  文本不过滤隐藏。
- 块数也有两个：`Node::paras`（设计态）与 `Node::paras_display`（呈现态，
  `hidden ? 0 : Σ 孩子`，不进哈希）。投影按 `ViewParams::vis` 选一个，损伤按同一个 vis 选 ——
  混用会让 `after_blocks` 比真实块数多出隐藏子树的宽度，`shift` 算错，splice 一块不删再插一块，
  表现为**段落重复**（TRAPS 124）。
- 判据：`rev_test` [23]（同一整数两种口径两个落点、隐藏/显示切换的 after_blocks、增量投影后
  块数与全量相同）与 `edit_test` [34](g)（隐藏字段之后打字的可见文本）。注入验证：把 vis 改回
  写死 `Design` 或把 `vp` 改回 `paras`，[23] 当场两红。

## 块的位置（2026-10-20）

- 位置**不是块的属性**，所以它进不了 `BlockKey`（那 32 字节只有内容哈希与来源身份）：
  - 绝对值是前缀和：`block_flow_[i]` 由前面所有块推出来，上游一段变长，下游全体平移；
  - 块与块之间还有不属于任何一块的空隙。表格里 `first` 的区间起点会比递推值大两位
    （离开上一格、进入这一格），所以"这一块占多少位"（span）也不是块自己的数；能存的只有
    "到下一块起点的距离"，而它取决于下一块落在哪一格。
- 因此"把位置并入投影"与"复用"互斥：复用块在 `canReuse` 里一句 `return true` 就过去了，
  没有游标走过它们。2000 块复用 1999 块时，位置只能另走一趟递推（`engine.cpp` 的
  `finishRebuildFromTree`），每块两次 `intervalOf`。
- 那一趟里的两处取大是"块起点有两个说法"（递推值 / 首元素区间起点）的症状，不是补丁：
  控件从中间切开的场景递推值更大，表格格边界场景首元素起点更大。消掉它的前提是先定
  "位置由谁持有"，而那一刀排在步 5（`blocks` 所有权变动时一起做）。
- 若哪天真要存，判据必须是"增量之后每块位置与全量递推逐块相同"，且要覆盖跨格与嵌套表 ——
  位置漂移的症状是"光标偏一个字"，现有 291 + 1368 条判据一条都抓不到。

## 排版的脏区（2026-10-20）

- 脏状态是两个数：`layout_dirty_from_`（起点，含）与 `layout_dirty_to_`（右端，不含；
  -1 = 未知）。"没有脏段"用 `from >= to` 且 `to >= 0` 表示（relayout 收尾把两者都置成
  `n_para`）。
- 三个写入口径：`markLayoutDirty(para)` 只给起点（右端记 -1）；`markLayoutDirtyRange(lo, hi)`
  给区间（提交与撤销都用它，hi 来自损伤区间）；`markAllLayoutDirty()` 整篇 + 禁止复用。
- **后缀复用只在右端已知时允许**：它把 `[from + m_new, 末尾)` 原样搬回，等于断言"那之后
  一个字没变"。`markLayoutDirty` 只给起点，这个断言不成立（TRAPS 125）。
- `trySuffixReuse(from, dirty_count, ...)`：新版脏区占几段由调用方给，旧版那一段等于
  `n_old - n_para + dirty_count` —— 两侧尾巴对齐到同一段。旧写法按段数差反推，等于假定
  "一次只在一处动段落标记"，撤销一批跨段步骤时不成立。
- 括号占位换字段：脏区是两个字段各自段跨度的凸包（`markLayoutDirtyForBracketPlans`）。
  拿"最靠前的控件段到末尾"代替，在聚焦档下等于整篇重排。
- 撤销的两笔账：排版从损伤区间起排（`markLayoutDirtyForDamage`，右端落在文档末尾之外时
  夹到最后一段，用来截掉旧尾巴）；括号计划用 `bracketPlanKey()`（档位 + 聚焦字段的节点
  id）比对，变了就从最靠前的控件段起重排。

## 控件集合（2026-10-20）

- 唯一来源是投影的 `rev::ControlSpan`：`exportControls(spans)` 照原序建 `controls_`，
  区间、标识、种类、锁定态全从跨度与节点载荷取。旧路径是"扫 `blocks_full_` 的对象表按 owner
  配对两枚边界，再对每个控件 `findNode` 一次"—— `findNode` 是全树 DFS，于是每次重建
  O(控件数 × 节点数)，还带一次 vector 分配。
- **跨度的顺序由产生端保证**：`project` 在进入控件时占槽、离开时填末尾（前序）。离开时 push
  会得到后序，嵌套时内层排到外层前面。区间恢复不了这个顺序：`[7,7)` 与 `[7,100)` 同起点时，
  前者可能是一个"前面的空字段"（兄弟，文档序在前），也可能是被后者包住的空控件（父子，
  文档序在前）—— 区间一模一样，排法却不是一回事，只能靠产生的那一刻定。
- 判据：`auditCompile` 逐项比区间与顺序（参照侧从 `compileDocument` 的产物重算，保持独立），
  不再只数个数；`edit_test` 有两条显式断言（装载后、删成零宽后）。注入验证：`end_cp` 加一
  红 114 项，跨度逆序红 155 项。

## 派生索引的下标（2026-10-20）

- 节点号是**递增水位**：新建节点才分配新号，旧号不回收。所以"按节点号开数组"的索引
  占用只随时间变差 —— 2000 段文档编辑一万次之后，`rev::FlowIndex` 三个数组约 0.5 MB，
  每次构造还要整份 `assign` 清零（一次按键构造三次上下）。
- 现在的形状：`nodes_` / `first_` / `span_` 按**活节点重新编号**（紧凑下标），节点号只作
  查表键；查表是开放寻址哈希（容量取 `2 × 活节点数` 的 2 的幂，负载 ≤ 0.5，`id = 0` 空槽）。
  占用约 48 B/活节点，与水位脱钩。
- 构造顺序"先遍历、后建表"：`measure` 只写不读，所以不必边插边查；表在 `measure` 之后一次建好。
  `indexOf` 是唯一入口，`first_` / `span_` 按它返回的紧凑下标访问。
- 判据 `rev_test` [24]：三千轮分段+合并（水位 43 → 3062、段数回到原样），每活节点 ≤ 96 字节、
  总量小于 `水位 × 8`；反向一半是"400 段文档的索引明显更大"。
  ★ 必须先断言水位与编辑次数，否则"占用不变"在什么都没做时恒真（TRAPS 110/126）。

## 统计的发布（2026-10-20）

- `EditStats` 分两组、两个发布点，不统一挂在呈现上：
  - 排版组（`relaid_*` / `layout_was_full` / `layout_ms` / `page_fp_ms` / `total_lines`）
    由 `relayout()` 发布；
  - 文档规模组（`total_paragraphs` / `doc_codepoints` / `control_count`）由
    `finishRebuildFromTree()` 发布；
  - 呈现只写它自己产生的那些（`paint_*` / `repainted_*` / `caret_*` / `window_*`）。
- `layout_ran` 仍按拍结算：它是"本轮有没有重排"的唯一表达，只有呈现能回答。呈现**只清标志、
  不清数字** —— 数字的语义是"最近一次"，清零之后排版刚算出来的那份就再也读不到（TRAPS 127）。
- `total_ms` 用 `layout_ran` 决定要不要把排版与页指纹加进来：不加的话闪烁拍会每 530ms
  重复上报一次排版耗时；无条件加则会把上一轮的排版算进这一拍。
- `documentCodepoints()` 按 `blocks_full_` 数：它是文档的码点数，不是"当前可见的码点数"。
  聚焦档下 `blocks()` 是筛过的副本，用它会让同一个文档在有、无聚焦时给出两个规模
  （与 TRAPS 120 的"访问器返回哪一份"同族）。

## 页位图与槽（5A，2026-10-20）

- 光栅产物按页存：`page_cache_` 的每条是 `{Bitmap px（页宽 x 页高）, uint64_t fp, bool valid}`。
  `fp` 是"这份像素对应哪一版页指纹"，与 `page_fp_new_[page]` 相等就不重画。
- 帧（`base_`）仍是窗口形状：整建时清成背景色，再把每页 `blitFrom` 到
  `slotOfPage(page) * 步距 + y0`。页间隙只由背景色提供，页位图里没有页间隙。
- 行带重画直接作用在页位图上（页内坐标）；搬进帧时按同一条带的整数范围搬，
  取整必须与 refresh 那个 Rect 一致（floor 起点 / ceil 终点，TRAPS 130）。
- 失效只有两条：页指纹变了（内容），或 `setConfig` 里那几项光栅配置变了
  （zoom / 页度量 / 页面底色 / 页边框 / 是否画边框 / 格线 / 原子框）。页指纹看不见配置，
  所以后者必须显式清缓存（TRAPS 128）。
- 容量 = 窗口页数 + 2（下限 4）；窗口页数 > 12 时整份清掉（整篇模式没有"近邻"可言）。
  这一阶段 `base_` 还在，缓存的每一页都是净增内存（96 dpi 一页 3.6 MB）；5C 删掉
  `base_` 之后才回本。
- 自审分三层，各管一层：`auditPage` 比页位图（绕开缓存从零光栅）、`auditBase` 比整窗
  底图（先清页缓存再全建，TRAPS 129）、`auditFrame` 比帧（覆盖层）。前一条是后两条的前提。
- 换窗、换槽数、换视口只改落点：页位图仍作数时只搬不画，`repainted_pages` 记的是
  真正光栅了几页，不再恒等于窗口页数。

## 按页接口与光栅签名（5B，2026-10-20）

- `pageRgba(page)` / `pageBytes(page)` / `pagePixels(page)`：页位图的零拷贝视图，**纯读**。
  页不在缓存、指纹不符、光栅签名不符、尺寸不符时给空视图，不补光栅 ——
  补了会把字形账算到读命令头上（TRAPS 133）。宿主在 `present()` 之后读。
- `pageDirtyRects(page)`：页内像素坐标，自上次取走以来累积、读后清零。来源两条：
  内容重光栅（整页或行带，记在 `rasterPageInto` 的调用点）+ 瞬态新旧矩形
  （旧光标 / 旧标记 / 选区新旧差集 + 新光标 / 新标记）。**帧的 `refresh` 不作来源**：
  整窗重建时它每页一整块，但页像素一个字节都没动，算进来会让换窗退化成整窗重传。
- 合并：相交/相接的并成一个；超过 16 条退回一个并集。并集是上界，宁可多传不可少传。
- 光栅签名：`rasterSignature(cfg)` 混 zoom / page（含 continuous、slab）/ page_fill /
  page_border / draw_page_border / table_line / atom_fill / atom_border / atom_text /
  atom_pad_pt，存进 `PageBitmap::raster_sig`，`pageBitmapFresh` 比它。`setConfig` 不再
  手写清单清缓存；以后加水印只把水印状态加进签名，所有页自动失效（TRAPS 128 的正解）。
- 判据 `edit_test` [58]：页视图 vs 帧（先藏光标，TRAPS 132）、光标移动 **72 px²**、
  打字 **12338 px²**（整页 102000）、读后清零、改底色四页全重光栅、同配置再设 **0 页**。

## 上屏面积（5C，2026-10-20）

- 引擎侧：`pageDirtyRects(page)` 是"页位图上真的变了的地方"，读后清零；
  `pageDirtyPages()` 是"还欠着矩形"的页号，读后**不清**（清零在 takePageDirtyRects）。
  宿主按后者决定贴哪几页 —— 矩形是累积的，某一拍的 present 可能没被消费
  （窗口平移、槽重建），按本拍 `dirtyPages` 贴会永久漏几块。
- 矩形的来源是 `transient_dirty` ∪ `refresh`：瞬态按"谁画的"记（精确），`refresh` 按
  "帧上真的写过哪儿"记（完备，含擦除）。只有前者会漏 —— 实测 93 px 的旧光标
  （TRAPS 136）。代价是整帧重贴那一拍退回整页上传，与改动前同价。
- 宿主侧：`blitPage(p, rects)`（worker）/ `blitFrame`（单线程）按矩形 `putImageData`。
  六参数重载的目标位置是 `(dx + dirtyX, dy + dirtyY)`，所以取 `dy = -srcY` 把帧坐标折回
  页内坐标；源仍是整帧的零拷贝视图，不按块拷贝。
- 槽过期（窗口刚平移进来的页）整页贴；引擎报脏却给不出矩形时也退回整页 ——
  兜底方向永远是"多传"，不是"少传"。
- 连页模式不按矩形：目标 y 随滚动变，整页都得重贴（滚动不是"某几块变了"）。
- 单线程宿主的画布记录带 `fresh`：新分配或刚改尺寸必须整页贴 —— 窗口平移进来的页
  内容没变、引擎没有矩形，而画布是空白的。
- worker 侧按块贴要**逐块拷成小图再两参数贴**：六参数 + 负 dy 在 OffscreenCanvas 上
  会裁错那一块（TRAPS 137）。
- `selfCheck` 开头先 `host.blitPages()`：两次操作之间可能有一拍只 present 没 blit，
  直接比会把时序当成贴错（TRAPS 138）。
- 账：`__heditor.blitStats.px` 两个宿主同形（单线程 `lastBlit.px` / worker `mirror.blitPx`，
  后者随 state 推回来）。判据 `edit_probe` [3]：光标移动后 `(0, 2000)`，整页 1.13 Mpx。
- 实测：光标一次移动 72 px²、打字 12 338 px²（`edit_test` [58]）。
- 未做：删帧与槽、连页条带画布 —— 它们以"瞬态能独立导出"为前提，随 5D 一起。

## 帧、画布、窗口
- **帧是视口窗口，画布一页一张**（一页一张是行为法器，冻结）。页度量由**宿主**传（A4 595.276 x 841.89 磅 + 边距 **2 厘米** 56.7 磅）；页间隙 14 磅是另一件事。**边距只改内容区，不改页像素与内存**。
- 缩放：`zoom` 单位是"设备像素 / 磅" ⇒ 96 dpi = **4/3**（`kZoomBase`，三文件各一份）。默认页 **794 x 1123**、间隙 19、一页背衬 **3.40 MiB**；底图与帧各一份。**界面收倍数（写 `1`）、引擎收密度（4/3）** —— 每宿主一对 `engineZoomOf` / `uiZoomOf`，门面 `zoomLevel`（密度）/ `zoomFactor`（倍数），**判据侧别读输入框**。**密度基准含 DPR**（`kZoomBase x dprNow()`）：DPR 2 ⇒ 引擎 1587 x 2245、显示回 794 CSS px、内存 x4；读倍数用 `zoomDpr`，DPR 不许缓存。量法 `out/_zoomcheck.mjs` / `out/_dprcheck.mjs`。
- 画布**按槽复用**：`slot = 页号 mod N`。★ **N 只有一个真源 = 宿主**（画布在它手里）：它随每条 `pageCanvas` 把 `slots` 报给引擎，引擎照用、**不再自己算**（`out/_slotsync.mjs` 实测过 11 对 8 的错位：宿主按"已建槽数"只增、引擎按"当前几何"可减，两侧各算一次必然分叉，画面每页都是别的页）。★ 宿主此前那个 **下限 8 是错的**，已改取 `maxWindowPages()`（与文档位置无关，**本机 5**；`geom.maxWindowPages` 报来，宿主 `nSlots = max(1, 上限, count)`）—— 8 既浪费 3 个槽（帧槽化后是 13.9 MB/块）又与引擎口径无关。`blitPage` 用槽号取源行；页号→元素映射是每状态按槽重建的派生量；`ctxOfPage()` **现算不缓存**。★ 池化会弄丢隐式触发 ⇒ 换窗必须显式说。
- **空转 present 的耗时必须与文档规模无关**（现在 0.1 ms）。同族已修三处：`drawControlMarks` 遍历 `layout_.lines`（→ 只过窗口内行，两端二分）、`paintPageIntoBase` 与 `prewarmPageGlyphs` 遍历全篇 `layout_.glyphs`（→ `glyphRangeOnPage` 二分）。★ 字形量实测 **118393**（示例 7 / 每页 740，别按"段数 x 40"估，会低估近一半）；省 **1 ms/页**、p90 省 5 ms。判据 `out/_glyphpages.mjs`（`auditGlyphPages`：二分区间 vs 全篇归属，双向）。★ **同一条代码路径当判据必然恒绿** —— `auditBase` 是"强制全建再比"，全建也走二分，注入"区间少一格"时它全程 0，只有 `auditGlyphPages` 精确报出（diff = 页数）。★ 该审计**只保护函数与单调性，不保护调用点**（往调用点注入 `gb+=1` 它抓不到）。
- ★★ **帧已改「按页号分槽」**（2026-10-17）：帧内行偏移 = `(页号 mod 槽数) x 步距`，**与窗口开在哪里无关** ⇒ 窗口平移不再搬像素（换窗那一拍的帧搬运 **9~10 ms → 1 ms**，paint 中位 **13.5 → 3.5 ms**，rtt **16 → 5.2 ms**）。帧高 = **槽数 x 步距**（不是「窗口页数 x 页高 + 间隙和」），只多一格间隙。★ 平移复用分支整段删除；「槽过期」与「页指纹变了」合并成同一套判据，**槽过期必须整页重画**（行带判据比的是同一页的上一个版本）。★ `hitTestPt` 收**文档坐标**（第 0 页顶边为原点），**不读槽表也不读窗口** —— 帧槽是渲染私事，混用会让页归属整体错位（只在首页号是槽数整数倍时看着对；判据 `out/_hitwin.mjs`）。参数名 `x_pt_doc` / `y_pt_doc`；两宿主 `framePointAt` 与 worker 的 `onPointerDown` 都直接给文档坐标。★ **输出侧相反**：`caretRectPt` / `selectionRectsPx` 含槽偏移是对的（宿主用 `frameSlotOf` 折回）。
- ★ **两套槽号并存、可以不等**：**画布槽**建了不回收（只增，历史最大）；**帧槽**跟 `maxWindowPages` 走（可增可减）。`blitPage` / `selfCheck` 用帧槽取源行、用画布槽取目标 —— **四处都得各用各的**（漏一处就是整段比错位置，实测差 17%）。
- ★ **页在帧内的偏移只有一个算法**：`frameOffsetOfPage(page)`（全仓唯一）。★ 它读 `base_first_page_` ⇒ **两个重建分支必须先落定首页、再画页**（TRAPS 66）。
- ★★ **两种视图模式**（2026-10-18）：**分页**（默认，行为法器）与**连页**（只在 `worker_host.js` 主线，工具条「视图」切）。连页 = **排版层不再分页**（不是把页间隙设成 0）：`PageMetrics.continuous` 让三条断页判据（页底溢出 / 显式分页符 / 竖排吃页尾）全部短路，页号退化成**渲染条带号** = `floor(块轴位置 / 条带高)`（条带高 = 页高 + 页间隙），于是帧槽 / 光标 / 选区 / 命中测试读的仍是"页号 + 页内坐标"，下游几乎不用改。★ 三处成对改：① 断页判据全短路；② **写进 `LineBox` / `PlacedGlyph` 的 y 都要减条带偏移**（`locY`，漏一处整条带错位）；③ 字形按**自己的** y 取条带（跨条带那一行的尾字）。绘制上"条带整幅填页面底色"就是**一整条连续白底**（不画页边框、不擦页间隙）；宿主滚动高度取 `contentPx`（内容底边），不是"页数 x 步距"。判据成对（TRAPS 71）：native `edit_test` [40] + `out/_continuous.mjs`（`inkRows`：条带内非白底行连页 0 / 分页 126）。
- 帧缓冲：`base_` 与 `bitmap_` 各 `frame_w x frame_h`；帧尺寸只在槽数变时重置，**空槽铺背景色且不记账**（透明黑会被 ink / markCheck 当成墨迹）。
- 换窗在"前方还剩 2 页"时触发；**追不上就主动放弃**（判据 = 实测成本 x 速度 > 提前量）；`needFirst` / `needLast` 必须夹回文档范围。

## 双宿主
- 视口门闩 = 一条在飞 + 一个待发标记；**每条视口消息都必须回话**；报的位置沿滚动方向提前（夹 ≤4 页），安静 200 ms 后补一趟零提前量对齐；位置不写回 `scrollTop`。
- 跨线程**不能相减时间戳**；残差口径 = `rtt - work - packAvg` **逐条相减后取中位**。
- **消息机制近乎免费**（只回小 JSON 的往返 0.3~0.6 ms；整份状态回推 + 宿主落地 <0.2 ms）⇒ 精简状态字段是白干。固定成本几乎全在 `present()`。
- 两宿主差价只在"跨线程往返"（窗口落后 1~2 页、缺画布率 2~5 倍）；**装载时间持平**（Worker 把装载的活搬离主线程）。

## 渲染与性能
- wasm 下 **Skia 比自写后端快 12.4 倍**（自写后端保留当尺子）；一页满字（2cm 边距、1520 字形）**8~9 ms**，字形约 1.2 µs/个（开 SIMD 前 33.6 ms / 14.3 µs）⇒ "一页满字 < 10 ms"达成。
- `paintPresentMs` 是**残差**（`paint - fill - glyph`），已拆成六段产品字段 `paintPreMs / SwapMs / BlitMs / OverlayMs / LedgerMs / ReportMs`（并起来 = `paintMs`）；★ **段界按"谁写的"切，不按"看起来像什么"切**。
- 每页光栅 17 ms 是硬墙；`putImageData` 是全程唯一 CPU→GPU 上传；GPU 理论上限约 6 ms、碰不到那 8 ms 帧搬运。
- SIMD 已开（三处成对：args.gn + 撤 `SKVX_DISABLE_SIMD` + CMake 编译/链接，缺一处静默无效或 ODR 违规）；探测在 `web/wasm_feature.js`；标量回退待办（库备在 `out/_bak_libskia_nosimd.a`，判据 = v128 指令数为 0）。
- GPU：Ganesh + WebGL 可做（`skia_use_webgl = is_wasm`）；WebGPU 缺 Dawn。★ 真门槛是判据依赖可读帧 + 逐字节 memcmp；本机 `--disable-gpu`，**别用"跑了没变快"否掉 GPU**。
- 字体：wasm 无系统字体，中文 16.9 MB 每实例一份；回退链是空架子（缺字 = 豆腐块）。
- ★ 覆盖层（选区/光标/标记）画在**帧**上、不进底图；选区按**新旧差集**进 refresh（交集不动）⇒ 窗口内平移那拍 overlay 8~10.5 → **1.5~2.3 ms**，换窗那拍两边几乎不相交、退化成整窗重画（必要）。判据 `out/_selallcost.mjs` 的 G 段（按像素：有/无选区的差，只有单线程宿主读得到 —— worker 的画布已 transfer 到 OffscreenCanvas）。

## 判据与纪律
- 基线（2026-10-20）：native `ctest --preset native` ⇒ **4/4**（`shaping_and_layout` **150** / `edit_and_caret` **1368** / `doc_model` **845** / `rev_layer` **291**）；web `edit_probe` **365 x2**、`worker_probe` 74、`error_probe` 19 x2、`multi_probe` 35、`stress_probe` 69、`web_probe` 6。跑法 `out/_run.sh <探针> <url>`。
- **探针一律串行**：固定端口 9222 + 固定 user-data-dir，并行互相踩（识别特征 = **断言总数也变了**）；批量走 `out/_seq.sh`。
- 量法：**真滚轮**才能量滚动空白（写 `scrollTop` 是串行，量不出，事件不要 await）；默认档单独量；空转/固定成本用 `out/_presentfloor.mjs` / `out/_fixedcost.mjs`；反证看"红的是不是它、而且只有它"。
- 探针模板字面量禁反引号（会截断，Node 报 missing `)`）；告警归因先比对 HEAD；临时对照用**文件备份 + 手工回退**（不用 git）。
- 几何单位两套：`caret.x / y / h` 是**帧像素**；`controls.items[].rects` / `bracketSlots` / `selection.rects` 是**帧磅**（zoom = 1 时相同 ⇒ 假绿）。
- 自审要配对：`auditFrame` 比的是帧（帧从底图搬 ⇒ 底图错了照样绿），故有 `auditBase`；**逐字节比较必须配第二把尺子**。
- ★ **一条"卡死/变慢"的归因顺序：先最小复现，再跑对照，最后才怀疑自己的改动**；本机抖动极大，超时值本身不可信。
