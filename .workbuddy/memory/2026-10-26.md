## 控件族：做完了（八种 + 光标屏障 + 点击切换 + 异步前置回调）

用户中途加了一条硬约束：**控件数据要"只带自己用得到的属性"**。据此把 `ControlSpec` 的特有层

  appearance / validateRef）+ `ControlDetail` 变体：monostate（纯文本）/ TextDetail（数值过滤）/
  ChoiceDetail（标签、选项、互斥组、多选、光标屏障）/ DropdownDetail（选项、自由输入）/
  DateDetail（格式、单位）/ CustomDetail（宿主自定义类型的属性袋）。
- 序列化写成 `"d":{"k":"choice",...}`；**不认识的 k 整份读入失败**（形状未知，猜一个就是伪造）。
- `makeControlSpec(type)` 是默认值的唯一出口：值形态、只读、光标屏障都按类型定。

**选择类的显示文字改成数据的投影**（单控件标签在 ChoiceDetail::label，组控件在选项表），
由 `controlDisplayText` 生成进内容。这条改动换来"切换 = 重建内容"能成立 —— 原来标签是作者
打的字，切换时没有第二份真相可依据。付出的是"标签不再是正文内容"，但光标本来就进不去。

其它：
- **光标屏障**三档都生效：`caretBarrierAt`（能力层，收调用方的流索引）+ 引擎的
  `barrierSpanAt`（贴到块外）+ 方向键跨块 + `canEditAt` 直接拒编辑。选区不受限。
- **点击切换**：命中载荷多带 `opt`；输入层问宿主 `controlToggle`（读主线程镜像，不再往返）、
  跑前置回调（可 async）、再 `toggleControl`。引擎里互斥/多选整批一次提交。
- **数值过滤**：`ContentFilter::Number`，`numberAccepts` 管"再打一个字行不行"，

- **日期**：值存 ISO（YYYY-MM-DDTHH:MM:SS），`formatControlDate` 按格式串折显示；
  `units` 位掩码是选择器的可选单位，与格式互不推导。2 月 30 日这类坏值按公历拒掉。
- **下拉**：`free_input` 打开后值可以不在选项表里；关闭时设值要过选项表校验。

## 更正：上一条「空内容控件第二个字掉到框外」的判断是错的

复现之后（段末、段中各写一节探针）**引擎的落点是准的**。真相是两层：

1. **判据自己的期望值写错了**：那一节先打 `12` 再打 `.-3`，期望内容 `12.-3` —— 但 `-`
   只允许出现在开头（`numberAccepts`），正确答案是 `12.3`。我当时把"判据红"误读成
   "光标跑到框外"，还用初值 `0` 绕过去，把真问题盖住了。
2. **`typeTextUtf8` 不重排**（`typeTextAndRender` 才重排）。连打三个字时相隔着零次重排，
   `para_cluster_starts` 还是上一版文本的，`snapToCluster` 拿旧表往下吸会**吸到上一个字**，
   落点整体前移：表象是"第二个字插到第一个字前面"或"掉到控件外面"。
   真宿主每敲一个字都重排，所以浏览器里看不出；原生判据连打就撞上。

修法两条（都留下了）：
- `CaretResolver::clusterTableFresh`：表尾记的是排版那一刻的码点数，与当前段落长度对不上
  就是旧表，**旧表不吸附**（`snapToCluster` / `clusterCeilAt` 都走这条）。不吸附的代价
  是不合并组合字符，小于整体前移一个字。
- 判据改成 `typeTextAndRender` 连打三次（真实节奏），再补一条"不重排连打"钉住旧表不吸附。

教训：**判据红先看判据自己的期望值**；引擎侧"位置对不上"要先问"排版是不是旧的"。

## 第二批：插入光标位置 / 整块删除 / 记号外观与颜色

用户三条反馈，逐条落：

1. **插入单选插出两个、第二个还嵌在第一个里** —— 演示页自己插了两个（改成插一个），

2. **选择类删除时能进去一个字一个字删** —— 括号规则里那条"光标进到内容末尾再删左边那一项"
   对屏障控件正好是"进去删字"。新增 `eraseWholeUnitBeside`（贴着就整块 `removeControl`）

3. **复选要"方框里一个对勾"、图标颜色可配** —— 字体里没有 ☐/☑（只有 ✓ 与 □）。做法：
   内容用 U+2610/U+2611（语义正确），成形时把 codepoint 换成 U+25A1 只为借格宽（块流不改），

### 顺带挖出的两个真 bug（都是"改了但画面不变"）

  进对象（**两个编译入口**：`doc/compile.cpp` 与 `rev/project.cpp`，后者才是引擎用的那条），
  行指纹混 `content_hash`，并按对象表补一条（括号宽度为 0 时排版不插槽）。
- **`emitSlot` 只给原子搬 content_hash**，控件括号没搬 —— 同一个病。已补齐。

## 第三批：四种选择类的记号色 / 复选外观 / 无组单选 / 把手光标 / 括号字体 / 键盘跨控件

用户六条反馈，逐条落：

1. **四种选择类的记号色都能配** —— 引擎的 `ControlPatch.glyph_color` 本来就只认 `choiceOf`，
   四种都通；缺的是演示面只有复选配了颜色。演示页四个插入按钮各给一种颜色，另加一个
   "控件颜色"取色器（改光标所在控件的 `glyphColor`）。判据补单选 / 单选组 / 复选组各数蓝色像素。
2. **复选框下右边框粗、对勾毛糙** —— 根因是 `side = size_px * 0.70` 不是整数，`fillRect`
   的 `ceil(x+w)` 让右 / 下边各多占一像素；对勾用两个三角形拼四边形且关闭抗锯齿。
   修：边长与线宽都取整后 `strokeRect`；新增 `Bitmap::strokePolyline`，按像素中心到折线的
   距离算覆盖率（圆头圆角，与画布高度 / 裁剪无关，分带重画仍逐字节一致），对勾改走它。
3. **未配组的单选不互斥、点自己切换** —— `toggleControl` 原来对单选恒置 true。改成
   `multi || group.empty()` 时取反；互斥清理本来就只在 group 非空时跑。演示页单选不再
   默认给 `group: 'demo-radio'`，插两个就是两个独立开关。
4. **图片把手悬停光标** —— 输入层新增 `onPointerMove` / `onPointerLeave`，命中带
   `imgHandle` 时按 0..7 折成 nwse / nesw / ns / ew 四种 cursor；一条在途 + 代际号，
   指针离开后回来的旧结果不改光标；按着键移动（拖选 / 拖尺寸）不参与。
5. **括号不随字体变** —— 排版原来用块主字体算槽宽、画也用块主字体。给
   `BlockShaping::Cluster` 与 `LineCluster` 加 `bracket_font`，按边界那一侧正文 run 取字体
   （开括号取内容首字、闭括号取内容末字，缺 `[` 字形退回块主字体），槽宽与绘制共用这一份。
6. **方向键跨不过选择类** —— `confineCaret` 落进屏障后按"从哪边来"贴回**同一侧的端点**，
   于是原地不动。改成跳到块的**另一侧**（右来落开括号之前，左来落闭括号之后）。

## 第二轮反馈（七条）

1. **勾选后画面不更新（要等别处变动）** —— 页指纹只混了外观摘要。勾选状态一变内容只换
   一个码点（U+2610 → 2611），成形时两者都归一成同一枚方框字形，几何一个字节都不差，
   那一行被判成"没变"。新增 `controlPaintDigest(spec)`＝外观 + 值，compile / project
   两个入口一起换。
2. **复选记号偏小、与单选不一样大** —— 单选的圆圈一直借字体字形（直径随字体），复选是
   自绘的。改为两族都自绘：`Bitmap::strokeCircle / fillCircle`（覆盖率 = 像素中心到圆周
   的距离，与折线同一套，分带重画逐字节一致），外径共用 `size_pt * 0.72` 取整。
3. **相位停在暗半拍时按方向键，光标移了却看不见** —— `move` 是 self 档，移动这一步自己
   present 一次；相位写在它之后，那一帧画出来仍是隐藏态。改成先 `showCaret(true)` 再移动
   （vertical / docStart / docEnd / lineStart / lineEnd / tabCaret 同）。
4. **不能从控件内部起选区 / 点控件不清旧选区** —— `placeAt` 的控件分支原来直接 toggle 并
   return，既不落点也不清选区。改成先 `env.place(act)`（落点照摆、旧选区塌掉）再 toggle，
   并 `armDrag(true)`：anchor 落在屏障里正是"选区可以从里面开始"。
5. **跨行控件的闭括号落下一行时，键盘左移跳过它** —— 折行处同一个文字偏移压着两行，行别
   只有点击落点带。新增 `CaretResolver::lineAffinityAtFlow`：光标贴左边那一格，那一格排在
   哪一行就画在哪一行。`setCaretRel` 的 `line_aff` 改成哨兵：0/1 显式（点击），-1（默认）
   自动判。第一版写成"遇到第一个 start < f 的行就返回 1"，普通折行也判成 1，被第 41 节
   两条判据抓住 —— 要取**最后**一行 start <= f。
6. **跨行控件点页边距也会切换选中** —— 命中会把点吸附到最近的行，页边距因此落进控件区间。
   `hitTestPt` 里加"点在行内内容起止之外时归属按块外报"。
7. **图片把手与光标重合处拖不动 + 拖动卡顿 + 撤销丢焦点**
   - 左右中把手只按正方形判（±3.6 磅），而图片后面的光标竖线比把手高一整行，竖线上下
     两端点在把手外 → 落成文字。改成左右中把手纵向铺满整行高，横向不动。
   - 拖动每帧 `resizeImageAndRender` = 每帧重排 + 重光栅。改成拖动只更新瞬态预览框
     （`previewImageResize`，锚点由把手方位定），松手才提交一次 `resizeImage`。
   - 撤销丢焦点：`resizeImage` 把 `pending_before_/after_` 写成空 `Range{}`，撤销当成
     "文档开头"。改成记当前选区。

判据：native 新增第 83 节（22 条：闭括号行首的光标行别、左移不跳行、选区端点落在屏障里、
勾选切换后页位图真的变）；第 79 节补 2 条把手纵向铺满 + 横向不放大。浏览器：`insert.spec`
补"从控件内部起拖""拖右中把手（偏移 5 磅）：拖动中尺寸不变、松手落地、撤销回原尺寸且
光标不动""点控件内部清掉已有选区"；`input.spec` 补"相位隐藏时方向键之后立刻可见"。

坑（判据写法）：`p.ev` 不拼读数前言（没有 H / D），要读诊断面必须用 `p.read`；`showCaret`

## 第三轮反馈（四条）

1. **点控件内部光标在左右来回跳** —— `confineCaret` 原来一律按"来的那一侧"取对面：同一处

## 用户报的六个缺陷：整图选区、混选删除、图片撤销、格内控件三击、表格间距

- **整图选区只有窄条**（`caret.cpp` 的 `selectionRectsIn`）：零宽兜底原来是按 `l_lo == l_hi`
  判的，而"整段只有一张图"恰好两端同偏移（原子占一位、`cpOffsetInBlock` 把两端折到同一个
  cp），宽度被算成 0.35 em。改成按**算出来的宽度**判（`!(width > 0)` 才兜底）—— 原子两侧
  侧别不同，宽度本来就是盒宽。
- **文字 + 控件混着选删不掉**（`edit_command.cpp` 的 `eraseFlowSteps`）：控件在流里占两枚
  边界，删除步只覆盖内容，覆盖校验必然差 2 → 整条拒绝。现在先把"整块落在区间里的控件"
  挑出来（去嵌套、按 lo 排序），单独发 `RemoveNode`，文本 / 标记 / 原子那三条整体跳过这些
  区间；覆盖校验里控件按它自己的区间长度计。
- **改尺寸撤销后拖动框消失、光标冒到图右边**（`engine.cpp` 的 undo/redo + `restoreImageSelection`）：
  撤销末尾那句 `setSelection` 会清 `image_sel_`，于是框没了、文本光标按撤销快照回到图右边。
  现在撤销/重做前记下选中项，节点还在就放回去，并顺手清掉尺寸预览。
- **格内控件连点三次变成选整格**（`web/src/input/input.ts`）：三击分支原来不看命中。现在
  先问一次 hit，落在控件或图片上就断掉连击计数、按普通落点走（`placeAt` 加了个 `preHit`
  参数省掉第二次往返）；落正文才走 `cellSelectAt`。
- **表格与相邻块之间没有间距**（`layout.h` 的 `kTableGapAfterPt` + `closeTable`）：表格不是
  段落，没有段后距可挂，紧跟其后的图段 / 文字贴着表底。现在最外层表格底边之后让出 6 磅
  （与默认段后距同档）；嵌套表不补，格高由内容结算。

## 表格格内折行后半截字不渲染：行带分组漏掉了纵向重叠的行

- 上一轮"格内插图后敲字变一堆换行符"没复现，这一轮按用户给的步骤（3x3 表、第一格
  插图并缩小、第二格连续输入）复现了。**根因不在排版，在局部重绘的行带（band）**。
- `pageLineBands` 原来按"top 相同"分组，再取相邻两组的中线当带边界。但同一表格行里
  各格的行数可以不同：图片格行盒 97.38..130.84、邻格第二行 114.76..132.14，两者纵向
  相交，"中线"算出 122.8，落进行盒内部 ⇒ 这半截不属于任何带。擦除按带做，于是它被
  擦掉却不再重画（页位图与从零光栅差 62 px，一条 3 px 高的横条；肉眼是"字没出来"）。
- 修复：分组按**纵向重叠**合并（`it.top < back.bottom - 0.01` 并入，bottom 取并集），
  item 归组改成按范围找（`it.top >= groups[gi+1].top`）。组内共一条带，宁可多画几十像素。
- 复现的决定性条件：**A4 页 + 4/3 缩放 + 表格前有一段正文**。native 原来用 320x300、
  zoom 1.0 构造，八种排法全绿；换成 595x842/72 磅边距/4-3 缩放后立刻抓到。
- 判据：`edit_test` 第 86 节新增"图在左格、字敲在右格并折行"（逐键对页位图，一次不对
  就报第几键 + band）；浏览器 `table.spec.ts` 新增 3x3 用例（逐键 type、auditLayout、
  auditPage、数墨）。
- 定位手法留档：`auditPageJson` 给的 box 与 `edit_stats.band_y0/y1` 一对，就能看出
  "变化区在带外面"；再按 `pageLineBands` 的分组推一遍就知道中线落在哪里。
