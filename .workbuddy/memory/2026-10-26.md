## 图片插入：做完了（资源表 → 光栅 → 插入 → 命中 → 拖拽改尺寸）

用户给的是整批需求（图片插入 + 八种基础控件 + 选择类的光标屏障与切换前置回调 + 下拉自由输入
+ 时间格式）。拍了两个板：**先做图片**；**选择类的"光标不能进"三档模式都拦**（标签不许直接
编辑，选项走属性面板）。图片这一刀已落地，控件那一刀没动。

**资源走宿主解码**：宿主给 `createImageBitmap` + canvas 拿到的 RGBA，引擎里没有解码器。
理由写进了 `docs/文档模型设计.md` 第十一节末尾：wasm 不涨体积、不给 Skia 链 codec。
这条是可逆的 —— 以后要原生解码，加一个"先解码再 register"的入口，模型与排版不动。

- `EditCommand::insertImage / resizeImage`：只在文档模式放行（改尺寸是设计动作；表单模式
  拒绝的词写在命令层 —— `canEditStep` 全仓没有调用点，别在那里加策略）。
- `engine_image.cpp`：注册/删除/插入/命中/选中/改尺寸 + 拖拽框的瞬态矩形；

- 瞬态层新增 `PageTransient::image_ui`（拖拽框 + 八个把手），只进呈现、不进导出。

## 控件族：做完了（八种 + 光标屏障 + 点击切换 + 异步前置回调）

用户中途加了一条硬约束：**控件数据要"只带自己用得到的属性"**。据此把 `ControlSpec` 的特有层
从"再摊七个字段"改成变体：

- 共同层（key / controlType / valueShape / value / readonly / required / structureLock /
  appearance / validateRef）+ `ControlDetail` 变体：monostate（纯文本）/ TextDetail（数值过滤）/
  ChoiceDetail（标签、选项、互斥组、多选、光标屏障）/ DropdownDetail（选项、自由输入）/
  DateDetail（格式、单位）/ CustomDetail（宿主自定义类型的属性袋）。
- 序列化写成 `"d":{"k":"choice",...}`；**不认识的 k 整份读入失败**（形状未知，猜一个就是伪造）。
- `makeControlSpec(type)` 是默认值的唯一出口：值形态、只读、光标屏障都按类型定。

**选择类的显示文字改成数据的投影**（单控件标签在 ChoiceDetail::label，组控件在选项表），
由 `controlDisplayText` 生成进内容。这条改动换来"切换 = 重建内容"能成立 —— 原来标签是作者
打的字，切换时没有第二份真相可依据。付出的是"标签不再是正文内容"，但光标本来就进不去。

其它：
- **光标屏障**三档都生效：`caretBarrierAt`（能力层，收调用方的流索引）+ 引擎的
  `barrierSpanAt`（贴到块外）+ 方向键跨块 + `canEditAt` 直接拒编辑。选区不受限。
- **点击切换**：命中载荷多带 `opt`；输入层问宿主 `controlToggle`（读主线程镜像，不再往返）、
  跑前置回调（可 async）、再 `toggleControl`。引擎里互斥/多选整批一次提交。
- **数值过滤**：`ContentFilter::Number`，`numberAccepts` 管"再打一个字行不行"，
  `numberTextValid` 管整串。过滤在落点判定之后做，全滤光就当这一下没成立。
- **日期**：值存 ISO（YYYY-MM-DDTHH:MM:SS），`formatControlDate` 按格式串折显示；
  `units` 位掩码是选择器的可选单位，与格式互不推导。2 月 30 日这类坏值按公历拒掉。
- **下拉**：`free_input` 打开后值可以不在选项表里；关闭时设值要过选项表校验。

判据：native 第 80 节（54 条）；web `insert.spec.ts` 加一条（单选组取值/图形、引擎侧切换、
真实鼠标点第三项 + 异步回调先拒后放），该 spec 现在 12 个用例。
验证：`ctest --preset native` 7/7（49.7 s）；`npm run test:dist` 68/68（56 s）；`npm run check` 全绿。

**已知缺陷（下一轮修）**：插入一个**空内容**的控件之后，插入文本会把光标留在闭括号外侧，
于是第二个字起就落进正文而不是控件里（非空控件没有这个问题 —— 判据用初值 "0" 绕过去了）。
疑点在 `commitInsert` 的 focus 与 `flowForRel`/`sideForFlow` 对零宽内容的侧别推导。

- Playwright 的 CDP `Input.dispatchMouseEvent` 这一轮点控件时没进输入层，换 `page.mouse.click` 才通。

## 更正：上一条「空内容控件第二个字掉到框外」的判断是错的

复现之后（段末、段中各写一节探针）**引擎的落点是准的**。真相是两层：

1. **判据自己的期望值写错了**：那一节先打 `12` 再打 `.-3`，期望内容 `12.-3` —— 但 `-`
   只允许出现在开头（`numberAccepts`），正确答案是 `12.3`。我当时把"判据红"误读成
   "光标跑到框外"，还用初值 `0` 绕过去，把真问题盖住了。
2. **`typeTextUtf8` 不重排**（`typeTextAndRender` 才重排）。连打三个字时相隔着零次重排，
   `para_cluster_starts` 还是上一版文本的，`snapToCluster` 拿旧表往下吸会**吸到上一个字**，
   落点整体前移：表象是"第二个字插到第一个字前面"或"掉到控件外面"。
   真宿主每敲一个字都重排，所以浏览器里看不出；原生判据连打就撞上。

修法两条（都留下了）：
- `CaretResolver::clusterTableFresh`：表尾记的是排版那一刻的码点数，与当前段落长度对不上
  就是旧表，**旧表不吸附**（`snapToCluster` / `clusterCeilAt` 都走这条）。不吸附的代价
  是不合并组合字符，小于整体前移一个字。
- 判据改成 `typeTextAndRender` 连打三次（真实节奏），再补一条"不重排连打"钉住旧表不吸附。

教训：**判据红先看判据自己的期望值**；引擎侧"位置对不上"要先问"排版是不是旧的"。

## 第二批：插入光标位置 / 整块删除 / 记号外观与颜色

用户三条反馈，逐条落：

1. **插入单选插出两个、第二个还嵌在第一个里** —— 演示页自己插了两个（改成插一个），
   根因是 `insertControl` 把光标摆在**内容末尾**：对选择类来说那是"塞进一个按不动的格子"，
   下一次插入就落进它的内容里。现在按数据分：可编辑字段仍摆内容末尾，选择类摆**整块之后**
   （`choiceOf(s)->caret_barrier`）。注意：wasm 产物不重编的话页面上看不出变化（这一轮踩到）。
2. **选择类删除时能进去一个字一个字删** —— 括号规则里那条"光标进到内容末尾再删左边那一项"
   对屏障控件正好是"进去删字"。新增 `eraseWholeUnitBeside`（贴着就整块 `removeControl`）
   与 `expandWholeUnits`（选区只盖住一部分时扩到整块）+ `soleWholeUnitIn`（扩完正好等于
   一整块就整块删节点）。**判据从 `caret_barrier` 改成 `valueShape != Text`**：下拉与日期
   没有屏障（只读），但内容同样是投影，不该被删成半截。
3. **复选要"方框里一个对勾"、图标颜色可配** —— 字体里没有 ☐/☑（只有 ✓ 与 □）。做法：
   内容用 U+2610/U+2611（语义正确），成形时把 codepoint 换成 U+25A1 只为借格宽（块流不改），
   图形由绘制层画（方框描边 + 两条斜线当对勾；圆圈按记号色重画字体字形）。
   颜色取 `Appearance.glyph.color`（默认 alpha 0 = 跟随文字），公开面叫 `glyphColor: RGBA`。

### 顺带挖出的两个真 bug（都是"改了但画面不变"）

- **页指纹没覆盖控件外观**：`InlineObject::content_hash` 对控件边界恒为 0，行指纹也不混它。
  改记号色/边框时位置一个都不动 → 页被判新鲜 → 不重光栅。修：`controlAppearanceDigest`
  进对象（**两个编译入口**：`doc/compile.cpp` 与 `rev/project.cpp`，后者才是引擎用的那条），
  行指纹混 `content_hash`，并按对象表补一条（括号宽度为 0 时排版不插槽）。
- **`emitSlot` 只给原子搬 content_hash**，控件括号没搬 —— 同一个病。已补齐。

教训：
- 改注释块用 `index()` 切片时，第二个锚点落在很后面会把整段代码切掉（我把 `compile.cpp`
  切得只剩 32 行）。**立刻 `git checkout -- <file>` 恢复**，再重做小改动；事后核对
  `git diff --stat` 的行数是否合理。
- `std::fprintf` 的实参求值顺序未定义：把 `setControlSpecAndRender(...)` 与 `controlViews()`
  写在同一个调用里，读到的可能是改之前的值 —— 白查了半小时。分开写。
- 看外观类改动的判据不能只看"记录里是什么"，要数像素（这一轮用临时探针导出 PNG 目视 + 判据数墨）。

判据：native 第 80 节 58 → 64 条（+整块删除）、第 82 节新增 21 条（方框墨量、记号色、
改色后重绘、给文本控件配记号色被拒）；`insert.spec.ts` 13 → 15 条（插入光标在整块之后 /
连插两个单选是兄弟 / 贴着选择类退格删整块）。全量：ctest 7/7、test:dist 71 passed、
check 违规 0。
