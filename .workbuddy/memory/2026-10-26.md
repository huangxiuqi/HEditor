# 2026-10-26

## 图片插入：做完了（资源表 → 光栅 → 插入 → 命中 → 拖拽改尺寸）

用户给的是整批需求（图片插入 + 八种基础控件 + 选择类的光标屏障与切换前置回调 + 下拉自由输入
+ 时间格式）。拍了两个板：**先做图片**；**选择类的"光标不能进"三档模式都拦**（标签不许直接
编辑，选项走属性面板）。图片这一刀已落地，控件那一刀没动。

**资源走宿主解码**：宿主给 `createImageBitmap` + canvas 拿到的 RGBA，引擎里没有解码器。
理由写进了 `docs/文档模型设计.md` 第十一节末尾：wasm 不涨体积、不给 Skia 链 codec。
这条是可逆的 —— 以后要原生解码，加一个"先解码再 register"的入口，模型与排版不动。

新增/改动（C++）：
- `src/core/engine/image_store.{h,cpp}`：资源表，注册时预乘 alpha，256 MB 上限，超了拒绝
  （静默淘汰会让某页突然变回占位框）。`imageResourceKey` 是光栅缓存的键。
- `Bitmap::drawImage(key, version, rgba, sw, sh, dst)`：Skia `RasterFromPixmapCopy` + 按 key
  缓存已解码的 SkImage（缓存与资源表同寿，删图时 `forgetImage`）。线性采样，不做 mipmap。
- `SetImageSize` 步骤（steps.h/cpp + rev/steps.cpp）：位置映射恒等，记原值，逆操作自足。
- `EditCommand::insertImage / resizeImage`：只在文档模式放行（改尺寸是设计动作；表单模式
  拒绝的词写在命令层 —— `canEditStep` 全仓没有调用点，别在那里加策略）。
- `engine_image.cpp`：注册/删除/插入/命中/选中/改尺寸 + 拖拽框的瞬态矩形；
  `imageNodeIds()` 按 `session_->generation()` 缓存（命中测试每次按下与拖动都问它）。
- `rasterSignature` 混进资源表代际：换了图页指纹看不出来，只有它能让页位图作废。
- 瞬态层新增 `PageTransient::image_ui`（拖拽框 + 八个把手），只进呈现、不进导出。

**一次拖拽只留一步撤销**：会话层加了 `rev::MergeRun{None, Start, Continue}`。第一帧 Start
（压旧修订），后续帧 Continue（并进上一步）。两态布尔表达不了"两个拖拽挨着"这件事。

坑与判据：
- 把手命中半径必须按图身压到三成：小图上八个把手连成一片，图身就点不到了。
- 判据：native `edit_test.cpp` 第 79 节（29 条）；web `insert.spec.ts` 加两条
  （API 全链路 + 真实鼠标点图片只选中不落光标），该 spec 现在 11 个用例。

验证：`ctest --preset native` 7/7（50.9 s）；`npm run test:dist` 67/67（53.5 s）；
`npm run check` 全绿。中途 `edit-longdoc.spec` 的 `auditLayout diff 0` 红过一次，
单跑与复跑全量都绿 —— 判它负载抖动，别为它改代码。
