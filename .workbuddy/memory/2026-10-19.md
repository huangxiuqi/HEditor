# 2026-10-19 台账：阶段 5 表格

## 一刀六层，按"模型 → 编译 → 排版 → 引擎 → 绘制 → 演示"推进

模型层两刀（`c4cc139` 行属性与单元格对齐、`ce6dc85` 表格进编译）：

- `CellSpan` 就地扩成 `CellSpec`（加 `v_align`）。改名用词边界替换，`SetTableCellSpan`
  这个步骤名刻意保留（它说的是"设跨度"，不随记录类型改名）。
- 新增 `RowSpec` 挂 `TableRow`：`can_split_by_page` / `is_header` / `page_break_before` /
  `height` + `height_rule{Auto,AtLeast,Exact}`。
- `TableSpec` 加 `width:Length` / `align`，删 `header_rows`；`headerRowCount(tree, table)`
  降为派生量。
- 新不变量"标题行是从第 0 行起的连续前缀"。判据要两条一起：派生量遇断前缀只数到 0，
  坏形状由不变量报 —— 拿派生量当判据会永远绿。
- 序列化：行记录 `rw{sp,hd,pb,ht,hr}`，默认值不写；单元格第三个元素是可选的对齐名。

编译层（`ce6dc85`）：

- 表格走扁平化：格内内容照常编段落，每块带 `cell_path`；单元格是段落边界（进格前先落当前段）。
- 产物加 `LayoutTable`（网格尺寸由跨度推、行属性、列宽、每格块区间）。
- 表格不再记"尚未进入编译"的诊断。
- `LayoutTable::at_block` 没做（排版按块流的路径切换，不需要"表在哪一块开始"）。

排版层（`03b309b` 表格排版、`5c25e1b` 跨页断行）：

- 格矩形只改两个变量（`cur_cx` / `cur_cw`），断行与放置复用同一条代码路径。
- 行高在行末结算：`max(内容高 + 2 x pad, 显式行高)`；内容高要扣掉最后一段的段后距
  （否则 Auto 行高每行多 10 磅）。
- 跨页两档：`can_split_by_page` 真 ⇒ 按行盒切片；假 ⇒ 整行挪走。切点不画横线靠
  `PlacedRow::cont_top/cont_bottom`。
- `layoutDocument` 加带默认值的 `tables` 参数，`layoutDocumentRangeWithTables` 是新增重载 ——
  所有旧调用点一个字都不用改。

引擎层（`35ecdc5` 表格进引擎与格线绘制）：

- `tables_` 随编译产物落地；**有表格时 `can_resume` 与 `trySuffixReuse` 都直接返回**。
- 段起点递推多一步：`max(上一条递推值, 本块 first 的区间起点)`。表格的格边界夹在两者之间。
  这一步漏了的表现是"格内打字落在相邻格"（注入验证：只有那一条判据红）。
- `auditCompile` 的来源契约放宽一处：`seg_start` 允许落在本块第一个元素**之前**
  （格边界就是那两位），只要求它不越过该元素的末尾。
- 绘制按"每个格自己的外框"画线 —— 合并格内部因此不会多出线。

判据：145 / 1176 / 845，浏览器 `out/_table.mjs` 7 项全绿（格线 8565 px、反向场景 0 px、
屏幕与帧差 0）。六次注入各自命中预期的那几条。

## 三处踩到的坑

1. **格内段落必须以段落标记结束**。块与流位置的映射靠标记递推，一格没有标记时下一块的
   起点会停在格边界上 —— `auditCompile` 差 3、`setCaret(1,1)` 之后打不进字，两个症状同一个根因。
   演示文书与判据都按真实形态建（每格文本 + 标记）。
2. **Python 改探针里的 `\n`**：字符串里写 `\\n` 落到文件里是真正的换行，C++ 字面量会跨行。
   改测试代码里的转义要手改，别走脚本替换。
3. **`hitTestPt` 只按块轴比距离**：表格让"同一 y 上有多个行盒"成为常态（一行的几个格），
   点第二格的字一律命中先出现的那一格。修法是块轴距离并列时再用行内轴距离定夺
   （`(d, dx)` 字典序）。正文里同一 y 不会有两行，所以无表格时选择不变 —— 判据是
   `edit_test [45]` 的两条（点第二格命中第 1 段、点两行空隙落相邻两行之一）。
4. **场景入口有两份清单，加场景要两边都改**：`web/app.js` 的 `SCENARIOS` 由单线程页
   动态生成下拉，`web/worker.html` 是**硬编码的 option 列表**。这一刀漏了后者 ——
   worker 页连场景 9（行内原子）都没有，index 页停在 9、没有 10（表格）。
   判据只能靠"两个宿主各跑一遍"发现（`_table.mjs` / `_atom.mjs` 传 `--url` 换宿主）。
   顺带暴露探针的宿主差异：单线程门面**没有 `lines`**、`selfCheck` 给的是
   `window.comparedPages` 而不是 `compared` —— 探针要取"哪个有就用哪个"。

## 用户报的四条（同日）

1. **看起来是三个表格、中间有空隔** —— `PlacedRow` 的几何按"行盒范围"给，而 `AtLeast 36`
   的行实际占 36 磅、文字只有 27 磅：中间那 9 磅没有格线，一行看起来断成两块。
   改成按**行矩形**给（放置前的顶到放置后的底），跨页时按页切（首片段到页底、中间占满、
   末片段到行底）。
2. **格子拿不到光标 / 怎么删除** —— 光标其实拿得到（诊断连点带打字都通）；缺的是"删表格"。
   补 `EditCommand::eraseTableBeside`：光标在表格**第一个块的最前**（退格）或**最后一个块
   的末尾**（前删）时整张表删掉，走 `makeRemoveNode` + `ParaDelta{true}`，撤销整张回来。
   判定落在块流上（段号 + 偏移），嵌套表格按最内层判。
   ★ 连带修一处：删表之后 `tables_` 空了，`can_resume` / `trySuffixReuse` 只看当前表会
   把它当成普通编辑 —— 必须同时看 `layout_.placed_tables` 是否为空（旧版有没有表）。
3. **格内输入、删除不更新** —— 编辑其实生效了（字形 38→39、光标在段 1），是**行带重画把字
   裁了**：`lineBand` 取"与下一个行盒的中线"当 hi，而表格一行的几个格各是一个行盒、y 完全
   相同，取到的是同一行的另一格，带只盖住字的上半。修成按"同一块轴位置的整组"算上下边界。
   ★ 抓它的判据只能是**底图 vs 从零全建**（`auditBaseJson` / 宿主的 `auditBase`）；
   `auditFrameJson` 与屏幕自检全绿 —— 帧从底图搬，底图错了照样一致（实测注入旧口径：
   底图差 555 像素，帧自检 0）。
4. **点格子靠后跳到后一格** —— 命中并列时用"行内文字范围"比 x，而格子后半段没有字。
   给 `LineBox` 加 `cell_lo_pt` / `cell_hi_pt`（格左右边界），命中优先用它。

**边框粗细**：固定 **1 个设备像素**（`lw_px = 1.0f`）。96 dpi / zoom = 4/3 时等于 0.75 磅，
DPR 2 时等于 0.375 磅。刻意不随缩放变粗：跨页切口两侧是两条半像素线，跟着缩放变粗会显缝。

## 用户报的第三轮（同日）

1. **选区要按格铺满**（参考图）。规则是"整段被选中 ⇒ 单元格选区"，两个条件必须合取：

## 选区：文字选区与单元格选区拆成两条操作线

用户两条抱怨指向同一件事：旧实现靠**几何猜**（"选区覆盖了这一段的行首行尾" ⇒ 整格），
于是「把文字一路选到最后一个字」与「选整格」在数据上无法区分，视觉上就跳成整格。

改法是加一个显式的粒度标记，不再猜：

- `CaretResolver::sel_cell_`（唯一真源）+ `selectionIsCell()`；`setCaretRel` / `setSelection` /
  `clearSelection` 一律清回文字；只有 `selectCell(lo, hi)` 置位。
- 渲染 `selectionRectsIn`：`sel_cell_` 时铺满格（宽到 `cell_lo..cell_hi`、高到
  `cell_top..cell_bottom`，含显式行高多出来的空白），否则只盖文字 —— 旧的那两段
  "l_lo==first_cp 就把 x0 推到格边界""整段覆盖就整格"全部删掉。
- 同一个格的一页片段有多个行盒，整格矩形只画第一份（否则半透明选区按行数叠深）。
- `selectAll()` 仍然整格铺满（Word 的 Ctrl+A 视觉），只对表格有影响。

两个入口（都是几何，不是猜）：

1. 单击格左侧的**边距带**。注意行盒的 `cell_lo_pt` 是**内容区左边**（列左 + padding），
   格本身还要再往左一个 `kTableCellPaddingPt`；所以判定是
   `ip >= cell_lo - kTableCellPaddingPt && ip < 文字左沿`。命中侧在 `hitTestPt` 里把这一格
   的流区间算出来（`out_cell_lo/hi`），宿主原样搬回去调 `selectCell`。
2. **三击**：`hitTestPt` 之外另开 `selectCellAtPt(x, y)`（点字中间也算），宿主 `ev.detail>=3`
   时走它。两个宿主都接（app.js / worker_host.js + engine_worker 的 READ 表
   `cellSelectAt`）。

判据（都可证伪）：

- native `edit_test [47]`：格内两段、行高 AtLeast 60；断言边距带命中给区间、点字上不给、
  三击选中整格、整格矩形 = 格宽/整行高且只画一个、同一对区间按文字选区设时**只盖字**。
- 浏览器 `out/_tablesel2.mjs`（worker 宿主）：同四条，另加三击后选区是整格。8 项全绿。
- 注入 `cell_sel = true`（等价于退回"几何猜"）⇒ 上面最后两条必红（实测）。

顺带补的取证面：`linesJson` 多四个字段 `clo/chi/ctop/cbot`（格范围），探针不用再猜几何。

## 三击选整格：pointerdown 的 detail 恒为 0

Worker 宿主把手势挂在 pointerdown 上，读 `ev.detail >= 3` 永远不成立（规范只给 mousedown
定义了连击计数，指针事件沿用同一个字段却没人填）—— 症状就是"三击没反应"。
改成自己数（520 ms 内、位置差不超过 4 CSS px 算同一次连击），两宿主同形各一份
（`clickCountOf`），判定用 `=== 3` 而不是 `>= 3`（detail 会一直往上加）。

## 跨格拖选 = 单元格选区

判定放在引擎（`EditorEngine::syncCellSelection`，在 `projectCaret` 的 extend 分支里调）：
两端都落在格内、且不是同一格 ⇒ 整格；退回同一格或拖出表格 ⇒ 文字选区。宿主只提供落点，
"跨没跨格"是表格结构的事，它手里没有。键盘 Shift 扩展走同一条 `projectCaret`，自动同口径。

两份读数分工：

- `sel_` 是用户落下的两个位置（`rawSelection`），拖回起手那一格时靠它退回文字选区；
- `cell_lo_ / cell_hi_` 是吸附到格边界的渲染与编辑端点；`selection()` 在吸附时返回这一对，
  方向跟 focus 走（不然删除后"光标落在哪一端"读错）。

渲染与编辑都读 `selection()` —— 两处各算一次就会出现"反白到这里、删到那里"。

## 整格删除必须逐格清空

按整条区间删会把单元格边界卷进去，`eraseFlowSteps` 的安全阀（覆盖必须刚好等于区间长）
过不去，整条编辑被拒 —— 表现是"选中好几格，按 Del 没反应"。
`eraseCellContents` 改成对每格的内容区间各发一批步骤（格与格之间的结构不碰），合并成一个
事务；嵌套表被外层区间包住时只留最内层。判据：[48] 的 `backspace()` + `auditLayout() == 0`。

## 整格选区的插入点钉在焦点格的末尾

抱怨：选了单元格之后光标跟着鼠标跑。成因是 `caretPara / caretRel / caretSide` 全都从
`sel_.focus` 派生，而拖选时 focus 是鼠标在格内的**任意**位置。

改法：加一份读数 `cell_caret_`（整格选区的插入点），三处派生统一走 `caretFlow()`：
整格时给 `cell_caret_`，其余给 `sel_.focus`。焦点那一格的末尾由引擎算好传进来
（`syncCellSelection` 里 `cellFlowRangeAt(focus)` 的 `fhi`；`selectCell` 传 `hi`）。
`sel_.focus` 保持原值不动 —— 拖回起手那一格靠它退回文字选区。

反方向拖也一样：插入点在**焦点那一格**（第一格）的末尾，不是选区起点。

## 三击要等一秒：查询改了帧却不重贴脏页

`cellSelectAt` 原先挂在 worker 的 READ 表（宿主用 askOp）。查询只回一个值，
**不 present、不 blitPages** —— 引擎把帧画好了，画布上还是旧像素。要等下一次闪烁相位
（530 ms 的 blinkPhase 命令）才重贴，实测 557 ms。

改法：三击走命令（`opUser('cellSelectAt', ..., true)`，WRITE 表里本来就有这一条），
`changed = false` 时退回落光标。宿主门面 `cellSelectAt` 也从 ASK 表挪出来走命令。
READ 表里那条删掉 —— 一个入口两条路，迟早有人接到慢的那条上。

实测 4~23 ms。

## 判据

- native `edit_test [47]`：三击之后插入点 = 格末（第二段末尾），不是点击那个字。
- native `edit_test [48]`：跨格拖选插入点 = 焦点格末；**同一格内移动焦点**插入点不动；
  反向拖选插入点在焦点那一格（第一格）的末尾。注入 `caretFlow` 恒给 `sel_.focus`

# 表格：矩形选区、跨格合并守门、整表删除（设计见 docs/表格交互设计.md）

用户报两条：跨行拖选把整行都选上；从最后一格连按退格删两行内容时光标来回跳、之后
有的格子点不进去。

## 根因

两条同一个结构缺口：**编辑与选区都按"一条流区间"处理，而表格结构位不在任何可删区间里**。

退格那条的链路：格首退格 → `mergeWithPreviousParagraph` → `mergeParagraphInto` 删掉
"前一块的结束标记"。跨格时那枚标记在格尾，是结构位 —— 删掉它不会把两段并起来
（两段在两个容器里），只会让前一格少一个结束标记；那一格的内容再删空，整块消失，
格就一个块都不剩（没有行盒 ⇒ 命中落不到它）。同时 `setCaretAtFlow(at_a)` 把光标送到
"合并点"，画面上就是光标跳到上一格末尾。

选区那条：`syncCellSelection` 取 [首格首, 末格末] 的流包络，第二行前面那些格全在区间里，
于是整行反白、按 Del 也整行清空。

## 改法

- 单元格选区改成"哪几格"：`CaretResolver::cell_spans_`（`setCellRanges`），包络只是 min/max。
  引擎按行/列包络挑格（`syncCellSelection` 用 `layoutCellAt` 拿行列），矩形在流里是断的也不会错。
  渲染按 `cellCovers(base)` 筛行盒；删除按 spans 逐格清空。
- `mergeParagraphInto` 加前置判据 `sameCellBlocks`：两块同格才并，跨格拒绝（与 Word 一致：
  格首退格不动）。这条同时挡住"表后正文并入最后一格"。
- 新增 `eraseWholeTables`：选区完整覆盖的表整张删节点（判据按**块区间**算，不按节点区间 ——
  全选的区间两头都在块内容上，够不到节点边界），表外空隙照常按区间删。全选删除因此从
  "按 Del 毫无反应"变成清空。
- 新增 `auditTables` / `auditTablesJson`（六类计数）：格没有块 / 块没有标记 / 同表区间重叠 /
  `cell_path` 与格区间不一致 / 跨度越界 / 块说自己在正文。**排版自审抓不到这类损坏** ——
  两边吃同一份 blocks_ 与 tables_，一格没块时两边都排不出行盒，逐字段比对全绿。

- `edit_test [51]`：全选退格成功且只剩一个空块、撤销四块全回、格内文字选区只删字、

# 表格：格内首尾的删除不再删表（`eraseTableBeside` 整条撤掉）

## 根因

  真的在表外**（`from < blo || to > bhi || whole_doc`）。这是"覆盖整表但两头都在表内"

# 表格：空格可选中、反白铺满外框（格的身份从"流区间"改成"块区间"）

用户报两条："空的单元格无法选区"、"单元格选区左右还有间隙，没有铺满"。

## 根因

**空格那条**：一格的身份一直用"流区间"表示（`cell_spans_` 是一串 `Range{lo,hi}`），
而空格的内容长度为 0 —— 空段不占流位，`cellFlowRangeOf` 直接 `if (b <= a) return false`。
于是三处一起断：命中不给 `cell`、`selectCell` 当场拒、`setCellRanges` 把退化区间丢掉；
即便侥幸设上了，`selectionRectsIn` 的 `if (seg_hi <= seg_lo) continue;` 也会让它一条高亮都不画。
**退化点没有身份**：空段与下一格的第一段共用同一个流位置。

**间隙那条**：行盒上的 `cell_lo_pt / cell_hi_pt` 是**内容区**（`openCell` 里
`cell_cx = 格左 + padding`，`cell_cw = 格宽 - 2 x padding`），反白直接拿它铺 ——
左右各留一条内边距（实测 4 磅/侧，外框 160.6 对内容区 152.6）。

## 改法

- 格的身份改成**块区间** `CaretResolver::CellBlocks{first,count}`：每格至少一个块、
  块区间两两不重叠，空格也有确定身份。流包络由块区间现算，退回"摘要"（选区报告、
  撤销快照、覆盖输入），渲染与删除都按块区间走。
- 渲染：先判 `cellCoversPara(para)`（合并成不相交的 `cell_mask_` 后二分），整格那一支
  **不读流区间** —— 参考几何（外框 + 整行块高），与格里有几个字无关。
- 行盒新增 `cell_box_lo_pt / cell_box_hi_pt`（`TableFrame::cell_box_lo/hi` 在 openCell 里算）：
  内容区给命中，外框给反白。
- 命中 `out_cell_lo/hi` 改成 **`out_cell_para`**：宿主与探针搬段号，`selectCell(lo,hi)`
  改成 `selectCellAtPara(para)`（wasm 绑定同名）。空格没有文字可挡 ⇒ 整格都是边距带。
- `selectionIsCell()` 改成 `sel_cell_ && (!sel_.empty() || !cell_blocks_.empty())`：
  粒度与"有没有文字被选中"分开问；空格选区 `hasSelection()` 仍为假（没有内容可删）。
- `eraseCellContents` 按块区间逐格清空，空格跳过（`hi <= lo`），删不动仍整条拒绝。

## 判据（均已注入验证）

- `edit_test [52]`：空格仍出行盒、三条手势都能选中、反白贴外框且铺满宽高、
  拖选跨过空格时它在选区里、删除之后格数不变、选中空格按退格什么都不发生。
  注入"退化包络一律不认" ⇒ 6 条红（正是用户报的形态）。
- `[47] [48] [49]` 与 `[45]` 的全选判据改成外框口径：注入"按内容区铺" ⇒ 10 条红，
  其中两条正是"左右各差 4 / 差 8"。

## 契约变更（要知道）

**内容区间**（空格是 `[0,0]`）；宿主只读 `cellPara`。wasm 命令 `selectCell(lo,hi)` →
`selectCellAtPara(para)`；两个宿主（`app.js` / `worker_host.js`）与 `engine_worker.js` 同步。

## 用户第 7 条：点空格变选格、反向拖选长不出来

两条同源，都在"空格"与"锚点"上，各改一处。

**一、点空格任何位置都成选整格。** 上一轮为了让空格选得中，把空格整格都算成边距带
（`no_text ⇒ 整格`)；用户要的却是"点一下落光标，拖或三击才选格"。改回：空格也只给
左边那一条（外框到文字左沿），`hitTestPt` 里那段 `no_text` 分支撤掉。

**二、反向拖选失效（从下往上、从右往左）。** 根因在 `setCellBlocks` 里把
`sel_.anchor/focus` 改写成了包络。拖选每动一步都靠 `rawSelection()` 判"两端还在不在
同一格"：锚点被搬到最早那一格的起点上之后，往回拖就永远判成"同一格"，`syncCellSelection`
直接 `clearCellRange()`，整格反白消失。改法：`setCellBlocks` 一个字都不写回 `sel_`；
单格吸附（单击边距带 / 三击）改由 `selectCellAtPara` 先 `setSelection({格首, 格末})`。

## 判据：一条判据两种写法，差的正是这一条

★ 原来的 `drag(a,b)` 助手是"`setCaretAtSideLine` + `setFocusAtSideLine`"各一次 ——
**每次都重设锚点**，所以注入旧行为后全绿（第一次尝试注入时我连目标行都没匹配上，
拿到的绿是未注入代码的绿，白跑一轮）。改成逐步拖：按下落一次锚点，之后每一步只搬焦点
（`setCaretAtSideLine(6)` → `setFocusAtSideLine(3)` → `setFocusAtSideLine(0)`）。

- 注入"锚点改写成包络" ⇒ 恰好一条红：`逐步反向拖到底（拖回第一格）：仍是那一列三格
  （实际 2 份）`——少了起点那一格，与用户报的形态一致。
- 注入"空格整格都算边距带"（窄版：整格没有非占位簇才生效）⇒ 恰好一条红：

- 两条注入同时在 wasm 上跑浏览器探针：`_tabledrag` 反向斜拖 **"实际命中 []，共 0 份矩形"**、

# 重写方案（2026-10-19 晚，假设不兼容旧代码、不计成本）

产出 `docs/重构方案-2026-10-19.md`。核心判断：现在的复杂度不是"拆得不够"，是"可变 + 事后推导"
这个形状决定的；换形状的唯一办法是**不可变修订 + 纯函数 + 按内容哈希记忆化**。

六个决定（细节在文档）：
- D1 文档是不可变修订：路径复制 + Merkle 哈希；撤销 = 旧修订，保存 = 序列化修订，
  宿主不持文档；Node 按 kind 带载荷（不再是 1496 字节并集）。
- D2 位置只有流位置（容器边界占位）：`side` 消失、空格可寻址；格选区仍是矩形

- D3 投影是纯函数，括号筛选是参数；缓存键 =（块哈希，列宽，可用高，样式哈希）。
  **损伤报告不需要了 —— 两个修订的 Merkle 差就是损伤，且精确。**

  `ReflowState`、`can_resume` 的 &&、表格后门一起消失。例外只有跨页行拆分与竖排吃页尾。
- D5 渲染单位是页：页位图 + 覆盖层，帧/槽/8 本账/presentInternal 整族消失。

代价（文档第五节）：不可变树要自己写（600~900 行，替换 steps.cpp 1238 行 + 重建逻辑）；

重建顺序：修订层 → 投影层 → 排版层 → 会话层 → 渲染层 → 宿主/IDL；前四步做完产品能跑。

# 追问：换新架构后旧性能优化还成立吗（2026-10-19）

结论写进 `docs/重构方案-2026-10-19.md` 第九节。要点：

- 旧优化分三类：**原样保留**（逐页画布、Skia/SIMD、字形/整形缓存、断行、表格几何、
  窗口滞回、提前量）、**被取代且更强**（帧槽/两套槽号→页位图；页/行指纹→页/行哈希；
  空转 present 的二分→页表；增量编译→块哈希，顺带干掉流索引 1.7ms 与整份块流拷贝；
  后缀复用→分页前缀和，页号不写进元素）、**本就该删**（帧槽、平移复用、对象表扫描）。
- **唯一会真退的是整页光栅**：行带 3.5ms（实测）vs 整页满字 8~9ms。规避方式是接口第一天
  就分两层：对外 `rasterPage`，对内行带哈希缓存。这是设计约束，不是"以后优化"。
- 打字同口径对照（2000 段）：今天 2.4ms 实测；新设计估计 1.5~3ms。撤销从整篇重编重排
  降到与编辑同价。最坏情况（中段打字/撤销）差距最大。
- 防补丁的办法：性能写成**结构判据**而不是时间阈值 —— 投影/断行重算块数 = 1、滚动 0 次、
  插入一页只重光栅 1 页、每次按键堆分配 ≤100 次、行带命中 ≥90%；四套固定语料 + wasm 基准
  + p50/p90。时间有噪声，调用计数没有。

# 重写第一步：不可变修订层的骨架（2026-10-19 夜）

按 `docs/重构方案-2026-10-19.md` 第六节的顺序开始落地。步 1 的第一块：
`src/core/rev/rev.h` + `rev.cpp`（约 430 行）+ `tests/rev_test.cpp`（约 280 行），
以 `rev_layer` 进 ctest，27 项断言 0 失败；native 四套测试全绿（150 / 1338 / 845 / 27）。

## 这一块做了什么

- **不可变节点**：`rev::Node` + `std::variant` 载荷（Run / Mark），`shared_ptr<const Node>`
  持有，构造后不再改。载荷用 `std::visit` 且不写默认分支：加一种节点种类时漏写哈希分支
  直接编不过 —— 这比"记得改哈希"可靠。
- **路径复制**：`withChildren` 复制根与正文节两级，别的段落节点原样共享。实测改第 0 段之后
  第 1、2 段的 `get()` 不变。
- **128 位内容哈希**：两条不同源的 FNV 通道（不同乘子与混合方式）。身份 NodeId 不进哈希，
  于是同内容不同构造路径哈希相同，撤销回到旧值哈希回到原值。
- **四个编辑原语**：insertText / eraseText / splitPara / mergePara，每个都返回
  `EditResult{ok, doc, error}`，失败带原因，不返回"看起来没变"的文档。
- **判据**：400 步随机编辑与朴素模型（vector<u32string>）逐步比对；旧值不变（十份历史回读）；
  结构共享；哈希的同与不同两半；六种非法操作全被拒。

## 有意收窄的地方（下一块）

只有文本 run 与段落标记。控件、表格、域、图片、节属性、序列化往返，以及"与旧模型逐字段
一致"都还没做。`rev::Doc` 的载荷加一支就要动哈希与 locate，这是设计使然。

## 两个坑

- `WritingMode` 是三个枚举的结构体，不是枚举 —— 直接 `static_cast<uint8_t>` 编不过，
  要逐字段哈希。
- 测试里 `std::u32string` 参数必须写 `U"..."`；`"..."` 是 `const char[]`，不会隐式转换。
  自己用脚本批量替换字面量时把 `u32(U"x")` 换成 `U"x")`，多出一个右括号 —— 当场编不过，
  但值得记一笔：批量替换字面量要复核括号。

## 命名冲突（记进文档了）

模型层已有 `heditor::Revision`（修订留痕 / track changes），与重构方案里说的"修订"
不是一回事。新概念用 `rev::Doc` + 内容哈希，文档第十节写明了这条。

# 第二块：控件进载荷 + 投影层（2026-10-19 夜）

`rev_layer` 27 → **56** 项断言；native 4/4 全绿（150 / 1338 / 845 / 56）；
浏览器 `edit_probe` 365 项、0 失败；wasm 构建过。

## 做了什么

- **控件进载荷**：`std::variant<monostate, RunPayload, MarkPayload, ControlSpec>`。
  `ControlSpec` 直接当载荷（它自带 operator== 与全部字段），不再包一层单字段结构。
- **hidden 放节点上**，不放载荷：它对任何节点都成立；且呈现态下它决定的是位置空间
  （摘掉子树，后面所有位置前移），所以进哈希。重复设同一个值 = 空操作（哈希不变）。
- **`insertControl(para, cp, spec, label, NodeId* created)`**：在位置处切开 run，
  放进控件，label 作为控件里的一枚 run。`created` 回写控件号（紧接着要设隐藏/回填值）。
- **`setHidden` + `replaceNode`**：任意深度的路径复制原语。没命中的分支返回同一个指针
  —— 这是"结构共享"能成立的地方。
- **`project(doc, sheet, ViewParams)`**：一次遍历产出 `ProjectedBlock{spec, source, hash}`
  + 控件跨度 + 诊断 + style_version。产物是 `BlockSpec`，**不另造并行类型** ——
  排版层现在就能吃，等价判据才有意义。
- **`blockHashes` / `diffBlocks`**：块哈希只从贡献该块的节点算；损伤 = 掐掉相同头尾。
  这是 P2（事务带损伤报告）的代替物。
- **`format_map`**：三层解析结果 → 引擎字段的映射，编译与投影共用一份。
  `sameRunFormat` 升成 `FormatRun::sameFormat`，`BlockSpec::operator==` 也加了。

## 判据（关键几条）

- 差分：同一份文档经 `NodeTree+compileDocument` 与 `rev+project`，`BlockSpec` 逐字段相等；
  呈现态隐藏之后再比一次。
- 块哈希局部性：改第 2 段 → 只有第 2 块哈希变；段首插段/合并/空编辑/整篇删空四种损伤区间精确。
- 控件 29 个字段逐个构造"只差一个属性"的规格，断言块哈希都变（**这条抓到了真缺陷**：
  控件节点哈希原本没进块哈希，改控件属性一个都不动；修法是 `emitObject` 把节点哈希喂进
  对象累加哈希）。

## 坑

- `BlockSpec::operator==` 若包含 `objects[].owner`，跨模型永远不等 —— owner 是节点号（身份），
  两边各自从 1 起分配。测试里 `sameBlock` 把 owner 摘出来跳过，另用控件表测跨度。
- 同一个测试块里 `cc`（树里的控件号）与 `rcc`（修订里的控件号）**不能混用**：两边号码
  空间独立，用错还能"成功"（恰好撞上另一个节点）。第一版就这么错了，表现为呈现态文本不同。
- `clang-format -i` 在这台机器的沙箱里不落盘（输出重定向写 /tmp 时 bash 与 Windows python
  看到的不是同一个 /tmp）。要么用 `> out/_fmt.tmp` 再读回，要么别用 -i。
- `format.ps1 -Check` 在 HEAD 上就有 28 个文件"需要格式化"（layout.h 一个文件差 1393 行）——
  它不是本仓库的实际门槛，只有新文件要求 clang-format 干净。

# 第三块：损伤定位（哈希下降）落地（2026-10-19 深夜）

`rev::damage(before, after)` 落地。`rev_layer` 56 → **71** 项断言；native 4/4 全绿
（150 / 1338 / 845 / 71）。

## 做了什么

- **下降式比较**：每层先比哈希（相同即整棵剪掉），不同才按 `NodeId` 对齐孩子下钻。
  快路径覆盖"孩子在原位被换掉"（改字/改格式/改控件），慢路径才建身份集合。
- **`paras` 顺序统计量**：构造时算好，`paraCount` 从"每次遍历全篇"变 O(1)，
  `locate` 在循环里调它 ⇒ 定位一段从 O(段数 × 每段节点数) 掉到 O(段数)。删掉了 `marksIn`。
- **叶子差异的归属**：两边都不含段落标记的差异记成"它所在的那一块"。少了这一条，
  改一个 run 里的字会报出空损伤 —— 漏报，且所有断言都是绿的。

## 判据（[11] 一节 15 项）

- 同一份修订：`visited == 1`，"整篇没变"真是 O(1)。
- 段内改字：区间与 `diffBlocks` 逐字段一致；300 步随机编辑零不一致（快路必须与慢路同答）。
- 合并两段：只报一块，与 `diffBlocks` 恰好一致；分段报两块（内容相同、节点被重建）。
- `visited` 与段落文字量无关（400 段 × 1 字 vs × 200 字，都是 802）。

## 实情（别把它说成"与段数无关"）

`visited = 802 = 全部节点数`。孩子表是 vector，要找出"哪个孩子变了"必须扫一遍孩子。
所以现在拿到的是**不做物化**（0.006~0.018 ms vs 0.20 ms，12~32 倍），不是 O(changed)。
真正的 O(log) 要等孩子表分块（每块 32 个带聚合哈希），那一步只改 `DamageWalker` 的下降方式。
`scanned` 计数就是给那一步留的判据。

## 坑

- 注释规则 R10 禁止 `// (1)` 这种行首编号；R3 禁止 `★` 与 `**强调**`；R9 要求结构体里的
  声明处用块注释，而 R12 又不许单行 `/** */` —— 两个字段的注释必须展开成三行。
- 分段报两块不是缺陷：`splitPara` 在 cp=0 时丢掉原 run、另建同内容的新 run（新节点号），
  于是"删一个、插一个"被分别记成两块。没加"按哈希跨位配对"的启发式，理由是它的失效方式
  是静默的（把两个真变化的节点当成同一份内容），而收益只是一次块缓存查询。

## 踩到的坑（★ 值得记）

`Site` 曾同时持有 `path` 成员，而 locate 的递归栈也是它（`locate(..., &site.path, &site)`）：
成功时 `out->path = *path` 成了**自赋值**。MSVC 的 `vector` 先释放再拷 → 路径退回空 →
落点变成顶层 → 文字跑到控件外面。**而"字进去了""控件还在""不切段"这些断言照样绿**，
只有内容比对（前aXb）与兄弟指针比对能抓到。
规则：**递归栈与结果要么是两个对象，要么根本不分开**（现在成功时栈里留着整条链，失败才弹）。

另一个小坑：`kidsAt` 的起点是**正文那一节**，不是根。按根算会让 path 的口径与 locate 差一层，
症状是空 path 时返回 `[section]` 而不是节的孩子表 → 越界读 → 段错误。

读端按"会不会静默做错事"定严格度：版本 / 种类名 / 号重复 / 水位 / 池下标越界都拒；

## 表格进载荷（rev + 投影 + 损伤）

载荷加三支：`TableSpec` / `RowSpec` / `CellSpec`，种类到载荷是一张查表（Table→TableSpec、
TableRow→RowSpec、TableCell→CellSpec），没有"表格载荷里再套三种"的包装。三者都进哈希
（列定义字符串按内容算，不按下标）。

**投影**（`rev::project`）补齐表格：`Projection` 加 `tables`（`LayoutTable`，与编译同类型），
格里的段落照常产块并带 `cell_path`；进表/进格/出格都先落掉残留（表格是块级元素）。
"改列宽该重排什么"拆成两半，两半都必需：

1. 块哈希并进外层容器栈（表格/行/格）的自身哈希 + 自己的格路径 —— 否则重排命中排版缓存。
2. 损伤下降先比自身哈希（`hashSelf`：种类+隐藏+载荷，不含孩子），变了整段记账 ——
   否则容器属性变化时孩子哈希全同，报"没有损伤"。

范围按容器层级：列宽 → 整表 `[1,6)`，行高 → 那一行 `[1,4)`。

**单一实现**：网格规则抽成 `buildGridFromSpans`（模型层与投影层共用），长度→宽度、行高规则、
垂直对齐的映射并进 `format_map`（compile.cpp 里的两份删掉）。
