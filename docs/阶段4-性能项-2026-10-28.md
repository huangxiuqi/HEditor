# 阶段 4 性能项：分块持久孩子表与文本切片

## 当前事实

阶段 4 的模型统一已经完成，性能项还没有开始：

- `doc::Node::children` 是 `std::vector<Ref>`，路径复制会复制整层孩子表，改一段的成本随这一层的块数线性增长。
- `doc::RunPayload::text` 与 `BlockSpec::cp_text` 都是整段码点容器，投影与编辑会复制整段文本。
- 因此阶段 4 判据里的两条还不成立：
  - 改一个字：复制的 `Ref` 数与重算哈希数只与树高/块大小同阶；
  - 改一个字：不复制整段文本，`alloc_bytes` 与段落长度无关。

## 目标形状

孩子表按固定块大小（建议 64）分块，每个块不可变、可共享。路径复制只复制被改的那一块和路径上的节点，未改动的块共享。

文本按 arena/切片存放：修订持有不可变文本块，`BlockSpec` 只持 `(buffer, offset, length)`，投影不再复制整段文本。

## 迁移顺序

1. 先引入只读孩子表容器，保留现有 `makeNode(std::vector<Ref>)` 入口，内部转成分块；这一阶段只做结构替换，不动编辑算法。
2. 把 `withLeafChildren` / `applyAtPath` 改成按块替换：叶子层构造新的小块，父层只替换受影响块。
3. 把 `hashNode` 的父节点摘要改成块级聚合：每块保存聚合哈希与段落数，父节点按块合并，不再逐孩子重算。
4. 文本层最后做：`RunPayload` 先支持共享 buffer，再让 `BlockSpec` 持切片；整形与断行改为读切片。
5. 每一步都用现有 `doc_test` 的段文本/哈希/共享对照与 `native-perf` 的 2000 段场景守住行为。

## 风险

- 孩子表容器要维持现有遍历、下标、`size`/`front`/`back` 语义；先做只读容器，避免同时改编辑算法。
- 哈希定义不能静默改变：块级聚合必须与当前的逐孩子顺序哈希逐位一致；做不到就保留旧摘要作为对照，单独定义新摘要。
- 文本切片会影响序列化、共享比较与剪贴板截断，必须在同一步里给往返判据。

## 状态

四项已落地：孩子表按 64 分块并共享、父节点哈希与段落数按块聚合、
RunPayload::text 与 BlockSpec::cp_text 都是共享缓冲区的切片（投影对单个 run 零拷贝）。
doc_test 第 28 节钉住块共享（只有改动所在的那个块被换掉），第 29 节钉住文本切片。

块共享的边界要说准：孩子表本身分块共享，但编辑热路径仍是
loadKids → toVector（整层拍平）→ 改一项 → rebuilt（逐元素比较后重建分块），
也就是每次击键的成本仍然随这一层的孩子数线性增长，只是不再复制每个 Ref 指向的对象。
真正的 O(块) 路径 withReplaced 目前只有一个调用点。要判断这条路值不值得推广，
先量"一次击键复制了多少个 Ref"，再决定要不要做绳/分段缓冲。
