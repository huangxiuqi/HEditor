# 步 5：渲染层（页位图 + 覆盖层）实施方案

先测绘现状，再定刀口与判据。这份文档的作用是：动手之前把"改哪些成员、加哪些接口、
每刀怎么验、哪里可能翻车"写死，避免做到一半发现接口对不上又回头改设计。

## 一、现状测绘

### 1.1 数据（引擎侧）

| 对象 | 尺寸 | 内容 |
| --- | --- | --- |
| `base_` | `pageW × (槽数 × 步距)` | 整窗底图：页底色、页边框、表格格线、字形 |
| `bitmap_` | 与 `base_` 同 | 帧：从底图拷贝 + 选区 + 光标 + 表单标记 |
| `prewarm_` | `pageW × 96` | 预热带，`shareFonts(base_)` |

`bitmap_` 是"窗口内所有页拼成一张图"，宿主拿到它再按页切回去贴到页画布上 —— 拼一次、
切一次，这是 D5 要删的那道中间层。

### 1.2 账（判断"画面上是什么"的八本）

| # | 成员 | 回答什么 |
| --- | --- | --- |
| 1 | `slot_page_` | 这个槽里现在装的是哪一页 |
| 2 | `page_fp_new_` / `page_fp_in_base_` | 页内容变了没有 |
| 3 | `line_fp_new_` / `line_fp_in_base_` | 这一页的哪几行变了 |
| 4 | `line_lo_in_base_` / `line_hi_in_base_` | 底图里每行的块轴范围（擦除用） |
| 5 | `frame_needs_full_refresh_` | 帧要不要整块重贴 |
| 6 | `mark_sig_prev_` / `control_marks_prev_` | 表单标记的计划与上一帧的矩形 |
| 7 | `selection_rects_prev_` | 上一帧的选区矩形 |
| 8 | `caret_rect_px_prev_` | 上一帧的光标矩形 |

外加：`base_valid_`、`base_first_page_`、`base_page_count_`、`frame_slot_count_`、`blit_acc_`。

### 1.3 接口

- 引擎：`frame()` / `frameBytes()` / `frameWidth()` / `frameHeight()`、`dirtyPages()`、
  `windowFirstPage()`、`windowPageCount()`、`setFrameSlots()`、`frameSlots()`、`takeBlitBox()`。
- wasm 门面：`frameRgba()`、`present()`、`setFrameSlots()`、`takeBlitBox()`、`relayoutAndPaint()`。
- `presentInternal(first, count, force_full)` 739 行，含：槽表维护、底图全建/增量、
  行带筛选、页指纹/行指纹记账、选区差集、光标擦除与填充、表单标记、记账与上报。

### 1.4 宿主

两个宿主都已经是"一页一张画布"：宿主按槽摆 canvas（worker 宿主把每张
`transferControlToOffscreen` 交给 worker），引擎给一张整帧，宿主按 `srcY = 槽号 × 步距`
切片 `putImageData`。页间隙的白色纸底由宿主用 CSS（`syncSpacer` 的 linear-gradient、
单线程的 `syncPageBackdrop`）画，引擎底图里那份页间隙背景是重复的。

### 1.5 判据

| 判据 | 现在的比较对象 |
| --- | --- |
| `auditFrameJson` | 帧 vs "强制整帧重贴" |
| `auditBaseJson` | 底图 vs "强制底图全建" |
| `selfCheck` | 宿主画布 vs 引擎帧 |
| `edit_probe` / `worker_probe` / `stress_probe` / `multi_probe` | 直接读 `frameRgba` / `canvas` / `dirtyPages` |

## 二、目标形态

### 2.1 页位图

```cpp
struct PageBitmap {
    Bitmap px;                      // pageW x pageH，原点 = 页左上角
    uint64_t fingerprint = 0;       // 页内容指纹（沿用现在那把尺子）
    std::vector<uint64_t> line_fp;  // 页内行指纹
    std::vector<float> line_lo;     // 行带上下界（页内磅，擦除用）
    std::vector<float> line_hi;
};
```

引擎持 `std::unordered_map<int, PageBitmap>`，容量上限按页数（默认 `max(2×窗口页数, 8)`），
超出时淘汰"离窗口最远"的页。页位图**只含页本身**：页底色、页边框、格线、字形；
页间隙不进页位图（宿主已有纸底，见 1.4）。

### 2.2 覆盖层

"覆盖层"指现在直接画在帧上、靠三份矩形清单擦除的那三样：**选区蓝条、光标竖条、
表单标记（方括号 / 小点）**。内容是页纸底、页边框、格线、字形。

必须分开的理由：内容那张图贵（一页上千字，8~9 ms），瞬态那张便宜（几十微秒）。现在两者
在同一张位图里，所以"光标闪一下"要靠"从底图贴回光标矩形再重画"来收尾 —— 一页一张画布
之后，页内容位图不能再被光标动（一动就是整页重光栅）。

`putImageData` 是覆盖不是合成，透明像素会把下面刷成透明，所以 alpha 混合必须发生在某处。
三种做法，差别只在"由谁做"：

| 做法 | 混合在哪 | 代价 | 前置条件 |
| --- | --- | --- | --- |
| 两张画布叠放 | 浏览器合成器 | DOM 里 canvas 翻倍；`multi_probe` / `web_probe` 数 canvases 的断言要跟；两层要对齐 | 无 |
| 一张可见画布 + 离屏覆盖层，每帧 `drawImage` | 宿主 JS | DOM 不变；覆盖层变化时多一次 `drawImage`（一页 0.9 Mpx，估计 0.2~0.5 ms，未实测） | 要量 |
| **引擎合成**：页内容位图 + 一份合成缓冲 | 引擎 | DOM 完全不变；多一份页大小的缓冲（**不是每页一份**）；覆盖层变化时多一次矩形 memcpy | 引擎按矩形做增量合成 |

三种都不影响 5A / 5B / 5C —— 那三刀只动"页内容位图"。

**调研补记（2026-10-20）**：查过 pdf.js / Excalidraw / tldraw / Flutter / Figma / PSPDFKit /
Chromium 的做法之后，这一项的判断口径改了。见 `docs/分层渲染调研-2026-10-20.md`，要点：

- 别人的"几十层"便宜，是因为那些层是**显示列表或稀疏 DOM**，不是全幅位图。全幅像素层
  按 `W×H×4×dpr²` 收费，跟内容多少无关；Chromium 自己的层策略是"默认合并，能压就压"，
  Chrome DevTools 团队还说过"多个 canvas 比一个更大的 canvas 更贵"。
- 真正决定成本的是**每次上传/重画的面积**，不是层数。现状是"一次光标移动上传整页
  893×1263 = 1.13 Mpx"，而光标只有 2×20 —— 这一笔比"层不够多"严重得多。
- 因此三种做法的差别不在"混合由谁做"（上传面积三者相同），而在**像素账是否逐字节可控**：
  两张画布把混合交给浏览器合成器，`selfCheck` 要改成"合成后再比"，且 alpha 取整可能差
  1 LSB；引擎合成则与现在完全同源，现有 365×2 条像素判据的形状不变。

**当前倾向第三种（引擎合成、单画布）**，前两种降为备选。真正的分叉收窄为一句话：
覆盖层是"单层 + 矩形合成"，还是"每页再开一张稀疏透明层"（后者只在出现昂贵静态内容、
批注、协同光标时才值得）。这一条等到 5D 前用实测确认，不再作为 5A–5C 的前置条件。

第三种容易被误读成"每页两份位图"，实际不是。引擎合成的形状是：

- 页内容位图：每页一份，整页（3.4 MB/页）—— 内容缓存，省不掉；
- 合成缓冲：**只有一份**，页大小，跨页复用；
- 三份擦除清单（光标 / 选区 / 标记）：仍然是矩形，几百字节，不是像素。

每帧对"覆盖脏矩形"（旧 ∪ 新）做三步：把页内容位图那一块 `copyRectFrom` 进合成缓冲、
在这块上画覆盖、把这一块 `putImageData` 回页画布。矩形通常只有一行高，全选时最坏是一整页
3.4 MB —— 而那一笔现在也存在（选区画在帧上，本来就要重贴整块）。这一条与现在的
`copyRectFrom(base_, r)` 完全同构，坐标从帧换成页内，不是新增机制。

内存对照（5 页窗口，现状 `base_` 18 MB + `bitmap_` 18 MB）：

| 路线 | 像素缓冲 |
| --- | --- |
| 引擎合成 | 页缓存 N×3.4 MB + 一份 3.4 MB 合成缓冲 |
| 两张画布 | 页缓存 N×3.4 MB + 宿主每页一张 3.4 MB 覆盖背衬 |
| 离屏 + drawImage | 页缓存 N×3.4 MB + 宿主一张 3.4 MB 离屏画布 |

三条都比现状省，因为"整窗拼接"的那一张没有了。

两种模式下的落地形态不同：

- 分页：一页一张页画布，覆盖层按页给（同尺寸，叠在页画布上或 `drawImage` 上去）；
- 连页：一张视口内容画布 + 一张视口覆盖画布，每页的覆盖小图按 `dy = page*step - scrollY`
  贴上去，相邻页在缝上不重叠。

缓存键：`(selection, caret, mode, bracket 计划, zoom, page)` 的签名；签名没变就不重画。

### 2.3 页间隙归宿主

引擎不再画页间隙背景。判据要加一条"页纸底色与引擎页底色是同一个值"——两边白不一样
时会出接缝，而它只在页边界那一两像素上，像素判据容易漏。

### 2.4 连页：条带画布（2026-10-20 定）

连页现在是"一张视口画布 + 每拍按 `页号 × 步距 − scrollY` 重贴"（`worker_host.js` 的
`syncViewCanvas`、`engine_worker.js` 的 `blitPageContinuous`）。这条路径要删掉，改成与
分页**同一套贴图**：spacer 撑到 `contentPx`，画布按 `页号 × 条带高` 绝对定位，gap = 0、
不画页边框。原生滚动，滚动时引擎一次都不用被叫醒。

**为什么不是"一张真实高度的画布"**：画布有硬上限（Chrome 单边约 65,535，Firefox 约
32,767，Safari 桌面约 25,600；dpr 2 时全部减半）。96 dpi 下一页 1123 设备 px，58 页就
顶到 Chrome 的边、29 页顶到 Firefox 的边；内存是 O(文档)——58 页 207 MB、200 页 713 MB，
而现在是窗口 5 页 18 MB。超限时 canvas **不抛错**：宽高一设，后续绘制全变 no-op，
表现是整片空白。

**为什么条带能直接换过去**：连页排版是"无翻页、页号由 y 现算"（`layout.cpp` 的
`slabOfY`），所以一**行**可以跨条带；但每个**字形**的页号是逐字按 `slabOfY(pen_y)` 记的
（`layout.cpp` 里 `gpage` 那行），`glyphRangeOnPage` 给出的就是"这一条带该画的字"。
绘制侧的口径一个字都不用改。表格行按 `PageSpan` 分页，同样落在条带内。

**要删的**：`syncViewCanvas` / `viewCtx` / `blitPageContinuous` / 门面的"视口画布"消息；
`syncSpacer` 里那条 `viewContinuous` 分支的滚动高度来源保留（它取 `contentPx`，是对的）。

**风险两条，5C 时实测**：条带边界接缝（两张画布整数位置相接，band 已 ±1 px 外扩）；
原生滚动的亚像素位移会让快速滚动时字轻微重采样——分页模式已经如此，产品已接受。

### 2.5 水印：最底层，但不是第二张画布（2026-10-20 加）

产品后续要加水印，层序因此定死为：

```
页底色 -> 水印 -> 页边框 / 格线 / 字形 / 原子框 -> 装饰 -> 瞬态
```

水印在**视觉上**是最底层，但**物理上不该是第二张画布**。理由是内容位图不透明（页底色 + 字），
要让下面的水印透出来，内容层必须带 alpha：整条像素路径（字形抗锯齿混的是水印色还是透明）、
`selfCheck`、"内容层 == 文档的纯函数"这条不变量全要改，代价远大于收益。

实际形状是**一张共享的水印位图**：

- `WatermarkLayer { Bitmap px; uint64_t fp; bool valid; }`，**页大小、全文档一张**（不是每页一张）。
  它同时包含页底色——因为它是最底层，底色本来就属于它。
- 页光栅的起点从 `fillRect(page_fill)` 换成 `blitFrom(watermark.px, 该页或该带)`。
  带光栅时只搬那一条带，面积与原来的整页填充相同，成本是 memcpy 对 memset，同一量级。
- 水印本身只光栅一次（文本 / 倾斜 / 平铺 / 图片都画进这一张），之后每页只是搬它。
  水印关闭时 `valid = false`，走回原来的 `fillRect`，**默认路径零回归**。

**失效靠"光栅纪元"，不靠逐项比对。** 水印状态（文本、字体、字号、颜色、角度、间距、页大小、
zoom）连同缩放、页度量、底色、边框、格线、原子框，一起混进一个 `raster_epoch_`；每一页的
指纹 = `hash(内容指纹, raster_epoch_)`。改水印 = 纪元 +1 = 所有页自动失效。
这同时把 5A 里"`setConfig` 手动比七项再整份清缓存"收成一处，是 TRAPS 128 的正解
（页面底色这类配置本来就不在内容指纹里，靠人工列表迟早漏一项）。

**判据**：

- 水印关闭时，页位图与今天的实现逐字节相同（默认路径零回归）；
- 开水印后 `auditPage` 仍逐字节一致（它绕开缓存从零光栅，也会走水印）；
- 改一次水印文本，窗口内**所有**页 `repainted_pages == 窗口页数`（纪元让它们全失效），
  且再改回来像素回到原值；
- 排版自审的摘要 A/B/C 不变——水印不进排版，只进光栅。

**什么时候才需要真正的一张底层**：水印动态变化（每页不同、随时间变、按用户变）或必须
"不可移除"地压在最上面时。那时按页缓存水印位图，或按 PSPDFKit 的 overlay mode 拆层；
静态文档水印用共享位图就够了。另：本方案是"水印在下、文字在上"，若产品要的是
"安全水印盖在文字上"，那是顶层，需要另一套混合规则，不要混为一谈。

## 三、刀口与判据

四刀，每刀都能独立验证、独立回退。先后顺序按"风险从低到高"排。

### 5A 页位图（纯引擎内部，对外接口一个字不改）

- 新增 `PageBitmap` 与 `pageCache_`；`paintPageIntoBase` 改成 `rasterPageInto(PageBitmap&, page, band)`，
  坐标全部页内化（`off_y` 从 `frameOffsetOfPage(page)` 变成 0，页边框与格线的坐标跟着减）。
- 每次 present：
  1. 按页指纹判断哪些页要重光栅（页在缓存里且指纹相同 → 跳过）；
  2. 重光栅的页写进 `pageCache_[page]`（可只画一条行带）；
  3. 把窗口内每页从缓存 `copyRectFrom` 到帧的槽位置（新增
     `Bitmap::copyRectFrom(src, srcRect, dstX, dstY)`）；
  4. 覆盖层逻辑原样不动。
- 槽、`slot_page_`、`frame_needs_full_refresh_` 这一刀都保留。
- **收益**：换窗与"窗口外页回来"不再整窗重光栅（现在 `base_valid_ = false` 会整窗重来）。
- 判据：
  - 新增 `auditPageJson(page)`：页位图 vs 从零光栅同一页，逐字节相同；
  - 现有 `auditFrame` / `auditBase` 改指向页缓存，diff 必须仍为 0；
  - 空转 present 耗时不变（现 0.1 ms 量级）；
  - 换窗计数器：只光栅"新进窗口且缓存里没有"的页。

### 5B 按页接口（引擎加，宿主不用）—— 已落地

- `pageRgba(page)`：这一页的像素视图（wasm 堆上，零拷贝）。**纯读**：页不在缓存里或已过期时
  给空视图，不在读命令里补一次光栅 —— 补了会把字形账算到读命令头上，而账是"这一拍排了多少"
  的证据。宿主在 `present()` 之后读它。
- `pageDirtyRects(page)`：自上次取走以来这一页写过哪些矩形（页内坐标），读后清零。
  口径是"页位图上真的变了的地方"：内容重光栅（整页或行带）+ 瞬态（光标 / 选区 / 标记）的
  新旧矩形；**帧的重建不算** —— 帧重建只改落点，页像素一个字节都没动，算进来会让换窗
  退化成整窗重传。
- `frameRgba()` 保留（内部用页缓存拼），作诊断与 5C 之前的兼容路径。
- 判据：`pageRgba(p)` 与 `frameRgba()` 里第 p 页那一块逐字节相同（对窗口内每一页）。
  **比之前必须藏光标**：页位图不含瞬态，帧含瞬态，不藏就永远差光标那一块（TRAPS 132）。

这一刀同时落地了 **`raster_signature`（光栅签名）**：把缩放、页度量、页面底色/边框、
格线、原子框混成一个哈希，记进每条 `PageBitmap`，`pageBitmapFresh` 比它。
`setConfig` 里原先那张"手写八项、任一不同就清缓存"的清单删掉 —— 漏一项就是 TRAPS 128
那种"改了底色屏幕不变"。改水印时只要把水印状态加进 `rasterSignature()`，所有页自动失效。

### 5C 宿主按页贴，删帧与槽

- `engine_worker.js` 的 `blitPage` 直接用 `pageRgba(p)`，不再算 `srcY`；`app.js` 的页画布池同理。
- **连页一并收口**（见 2.4）：删 `syncViewCanvas` / `viewCtx` / `blitPageContinuous` 与
  "视口画布"那条消息；连页从此走分页的同一条贴图路径（gap 0、无页边框、spacer 取
  `contentPx`）。做完这一步，宿主只剩一种贴图方式。
- 删：`setFrameSlots` / `frameSlots` / 槽表 / `slot_page_` / `frameOffsetOfPage` /
  `frame_slot_count_` / `base_valid_` / `base_first_page_` / `base_page_count_` /
  `windowFirstPage` / `windowPageCount` / `takeBlitBox`。
- `takeBlitBox` 换成 `takeDirtyPages()`（`[{page, rects[]}]`）。
- `frameRgba()` 保留但变成"现场拼一张"（只给探针与诊断）。
- 判据：`selfCheck`（画布 == 页位图，逐字节）+ 现有 365×2 / 74 / 35 / 69 条像素探针；
  连页另加一条截图判据——条带边界上下各 2 px 带内不得出现整行像素差（接缝）。

### 5D 瞬态层（形态待定，倾向"单层 + 矩形合成"）

不论选哪种形态，这三条是共同的：

- 瞬态不再触发整页重贴，上屏粒度是**矩形列表**（与 5B 的 `pageDirtyRects` 同一口径）；
- 擦除方式从"从底图拷回"变成"重新合成这一块"（先清、再画），
  于是 `sel_paint` 那套"整块重铺再混一次"的防累积逻辑连同它防的 bug 类一起消失；
- 三份 `prev` 清单的角色从"擦除依据"变成"脏矩形来源"，`frame_needs_full_refresh_`
  随 5C 一起消失。

两种形态：

| | B 单层 + 矩形合成（推荐） | A 每页稀疏透明覆盖层 |
| --- | --- | --- |
| 额外全幅像素 | 0（一份矩形大小的合成暂存） | 有标记的页各一张（通常 1~3 页） |
| 混合由谁做 | 引擎（与现在同源） | 浏览器合成器 |
| `selfCheck` | 语义不变，逐字节 | 要改成"合成后再比"，容差 1 LSB |
| 像素判据 | 365×2 条形状不变 | 凡是对着画布找光标/选区的都要跟 |
| 内容层是否被弄脏 | 是（小块，一次 `putImageData`） | 否 |
| 新风险 | 全页重贴时要把瞬态重新合成一遍 | 两层对齐（分数 DPR / 亚像素滚动） |

选 **B** 的理由是判据面与像素账都不变；选 **A** 的触发条件是出现"昂贵且几乎不变"的内容
（扫描件底图、水印、签名图）或批注、协同光标这类有独立更新频率的装饰 —— 那时它符合
"同频同层"，才值得为它多开一张位图。依据见 `docs/分层渲染调研-2026-10-20.md`。

- 引擎：`pageUploadRects(page)`（内容损伤 ∪ 瞬态新旧矩形的并集）、
  `pagePixels(page)`（合成后的页视图，零拷贝）；分配只给"这一页真的有瞬态"的情况。
- 宿主：仍然一张页画布，`putImageData(img, 0, -rect.y, rect.x, rect.y, rect.w, rect.h)`。
- 删：`control_marks_prev_` / `selection_rects_prev_` / `caret_rect_px_prev_` /
  `mark_sig_prev_` 里"用来擦除"的那部分语义（保留为脏矩形来源）。
- 判据：一次光标移动的上传矩形 ≤ 2 个、总面积 < 200 px²（现在是整页 1.13 Mpx）；
  `selfCheck` 逐字节；全选拖动时上传面积 == 选区矩形面积之和，不是整页。

## 四、回退点与"停下来问"的条件

每刀的检查点，出现下列任一情况先问，不自行改设计：

- 5A：`auditPage` 出现非零 diff，且原因不是"页间隙/页边框坐标没减干净"。
- 5B：`pageRgba` 与 `frameRgba` 的对应块差在 1 个通道以内但位置整体偏移 —— 那说明
  页内坐标与帧坐标的换算还有一处没统一，属于设计问题不是笔误。
- 5C：`multi_probe` 因 DOM/画布数量变化翻红（它直接数 `canvases`）。
- 5D：一次光标移动的上传面积没有降到 10³ 像素以下，或 `selfCheck` 出现 1 LSB 的差 ——
  后者说明合成路径与绘制路径没有真正同源（同一个 Skia 调用面），不要用容差糊过去。
- 任何一刀要让 `edit_probe` 的像素断言改写超过 20 条 —— 说明接口粒度选错了。

## 五、不做的事

- 不动 `bitmap_skia.cpp` 的 Skia 调用面（hinting / 亚像素 / 灰度抗锯齿 / 旋转），
  那是"今天的像素长这样"的全部原因。
- 不改 `Continuous` 的**排版语义**（页间隙为 0、页号由 y 现算、无翻页）；2.4 换的只是
  贴图方式，排版一行不动。
- 不做"多线程光栅"、不做"GPU 合成"。
- 不顺手改表格增量（`can_resume` / `trySuffixReuse` 的两个早退），那是另一条欠账。

## 六、2.1 与 2.2（块流收成一份、位置索引）

复核报告把这两项挂在步 5，理由是"与 `blocks` 所有权同一件事"。实际读下来它们
**与渲染层正交**：`rasterPageInto` 只读 `layout_`（行、字形、`placed_tables`）与 `cfg_`，
不读 `blocks()`；`syncInlineObjects` 读块流是在排版之前，不在光栅里。

所以它们是步 5 的伴生项，可先可后，但**建议放在 5D 之后**：那时渲染层已经稳定，
改块流只需要跑排版与编辑两套判据，不用同时盯像素。

2.2 的位置口径有三种选法（复核报告 2.2 的追记），需要在动手前定：

- a：位置仍由 `finishRebuildFromTree` 递推，只是把 `block_flow_*` 收进 `BlockFlow` 结构
  —— 只收形状，不动口径，风险最低；
- b：位置进块流（每块带 `flow_start`），复用时按 delta 平移 —— 要解决"复用块的 delta
  各不相同"，是真正把位置变成块属性的做法；
- c：位置按需计算（查询时用前缀和），不常驻 —— 每次查询 O(块数)，与"空转 present 0.1 ms"
  冲突。

建议 a：它兑现"引擎不再有七个数组"，但不引入任何会静默漂移的坐标。

## 八、5A 实施记录（2026-10-20）

已落地。实际形状与上文 2.1 的草图有三处不同，都是实施时才定下来的：

**缓存条目只记一个版本号。** `PageBitmap` 是 `{Bitmap px; uint64_t fp; bool valid;}`：
`fp` 记"这一份像素对应哪一版页指纹"，与 `page_fp_new_[page]` 相等就不重光栅。
指纹数组里没有这一页时一律判"不新鲜"——没有版本号就不敢断言像素作数。
`markPagesChangedFrom` 的哨兵值也算一版（它的低位每次都会翻，同一个哨兵不会连着出现两次）。

**配置变化必须整份作废缓存，页指纹看不见它。** 缩放、页度量、连页、页面底色、页边框、
格线、原子框这几项决定页里画出来的像素，而它们一个都不在页指纹里（指纹只哈希字形）。
`setConfig` 里据此比一遍，任一不同就 `page_cache_.clear()`。
漏掉这一条的后果是"改了底色，屏幕上还是旧底色，直到某一页的内容变了"。

**容量是"窗口页数 + 2"，整篇窗口不缓存。** 这一阶段整窗底图（`base_`）还在，缓存的每一页
都是净增内存（96 dpi 一页 3.6 MB）。两条余量够"滚回来一页"。窗口页数超过 12（没有视口
锚点的整篇模式）时整份清掉：那种模式下"离窗口近"没有意义，而内容没变的页在下一拍
根本不会走到光栅那一步，清掉不亏。

实施中新发现的两条口径：

- `blitFrom` 的取整必须与 refresh 那个 `Rect` 完全一致（`floor(起点)`、`ceil(起点 + 高)`）。
  少取一行就是"版面上留一条旧墨迹"，而且只在恰巧跨半像素时出现。
- `auditBaseJson` 必须先 `page_cache_.clear()`：不清的话"底图全建"只是把同一批页位图
  再搬一遍，比出来的是搬运的确定性，而不是光栅的确定性。

判据（`edit_test` [57]，8 条）：窗口内每页 `auditPage` 与从零光栅逐字节一致；换窗一页时
`repainted_pages == 1`；缓存清空后四页全部重光栅（反向一半，防止计数器恒报小值）；
打字之后逐页仍与从零光栅一致（行带增量没有留下旧像素）。
另外 [5] 里那条"页数变了 → 两页都重画"改成了"新页被光栅进缓存"——第 0 页内容没变，
复用它的像素正是这一刀要省的那笔。

## 九、5B 实施记录（2026-10-20）

已落地。接口与判据如上，实施时定下来的三处：

**脏矩形按"页位图写入"记，不按帧的 `refresh` 记。** 帧整窗重建时 `refresh` 里每一页都有
一整块，但那些页的像素一个字节都没动；照抄 `refresh` 会让换窗/改配置时所有页都整页重传。
所以内容部分在 `rasterPageInto` 的调用点记（整页或行带），瞬态部分单独记（旧光标、旧标记、
选区新旧差集），最后落到页内坐标。

**合并规则要能收住表单页。** 一页几十个字段时，新旧标记加起来上百个小矩形，逐条
`putImageData` 反而更贵。`notePageDirty` 把相交/相接的并成一个（光标擦旧画新就是这种），
超过 16 条退回一个并集 —— 并集是上界，宁可多传不可少传。

**`pageRgba` 不补光栅，`pageDirtyRects` 读后清零。** 前者保证读命令没有副作用（字形账不被
污染），后者与 `takeBlitBox` 同一套"取走即消费"的语义。宿主在 `present()` 之后按页读，
顺序反了会读到空视图 / 上一拍的矩形。

判据 `edit_test` [58]（14 条）：四页 `pageRgba` 与帧对应块逐字节相同（先藏光标）、
无缓存的页给空视图、一次光标移动的上传面积 **72 px²**（整页是 102000 px²）、矩形覆盖光标、
读后清零、打字的上传面积 **12338 px²**（一行带）、打字后 `auditPage` 仍为 0、
改底色后四页全部重光栅、同样配置再设一次 **0 页**重光栅（反向一半）。
