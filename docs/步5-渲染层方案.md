# 步 5：渲染层（页位图 + 覆盖层）实施方案

先测绘现状，再定刀口与判据。这份文档的作用是：动手之前把"改哪些成员、加哪些接口、
每刀怎么验、哪里可能翻车"写死，避免做到一半发现接口对不上又回头改设计。

## 一、现状测绘

### 1.1 数据（引擎侧）

| 对象 | 尺寸 | 内容 |
| --- | --- | --- |
| `base_` | `pageW × (槽数 × 步距)` | 整窗底图：页底色、页边框、表格格线、字形 |
| `bitmap_` | 与 `base_` 同 | 帧：从底图拷贝 + 选区 + 光标 + 表单标记 |
| `prewarm_` | `pageW × 96` | 预热带，`shareFonts(base_)` |

`bitmap_` 是"窗口内所有页拼成一张图"，宿主拿到它再按页切回去贴到页画布上 —— 拼一次、
切一次，这是 D5 要删的那道中间层。

### 1.2 账（判断"画面上是什么"的八本）

| # | 成员 | 回答什么 |
| --- | --- | --- |
| 1 | `slot_page_` | 这个槽里现在装的是哪一页 |
| 2 | `page_fp_new_` / `page_fp_in_base_` | 页内容变了没有 |
| 3 | `line_fp_new_` / `line_fp_in_base_` | 这一页的哪几行变了 |
| 4 | `line_lo_in_base_` / `line_hi_in_base_` | 底图里每行的块轴范围（擦除用） |
| 5 | `frame_needs_full_refresh_` | 帧要不要整块重贴 |
| 6 | `mark_sig_prev_` / `control_marks_prev_` | 表单标记的计划与上一帧的矩形 |
| 7 | `selection_rects_prev_` | 上一帧的选区矩形 |
| 8 | `caret_rect_px_prev_` | 上一帧的光标矩形 |

外加：`base_valid_`、`base_first_page_`、`base_page_count_`、`frame_slot_count_`、`blit_acc_`。

### 1.3 接口

- 引擎：`frame()` / `frameBytes()` / `frameWidth()` / `frameHeight()`、`dirtyPages()`、
  `windowFirstPage()`、`windowPageCount()`、`setFrameSlots()`、`frameSlots()`、`takeBlitBox()`。
- wasm 门面：`frameRgba()`、`present()`、`setFrameSlots()`、`takeBlitBox()`、`relayoutAndPaint()`。
- `presentInternal(first, count, force_full)` 739 行，含：槽表维护、底图全建/增量、
  行带筛选、页指纹/行指纹记账、选区差集、光标擦除与填充、表单标记、记账与上报。

### 1.4 宿主

两个宿主都已经是"一页一张画布"：宿主按槽摆 canvas（worker 宿主把每张
`transferControlToOffscreen` 交给 worker），引擎给一张整帧，宿主按 `srcY = 槽号 × 步距`
切片 `putImageData`。页间隙的白色纸底由宿主用 CSS（`syncSpacer` 的 linear-gradient、
单线程的 `syncPageBackdrop`）画，引擎底图里那份页间隙背景是重复的。

### 1.5 判据

| 判据 | 现在的比较对象 |
| --- | --- |
| `auditFrameJson` | 帧 vs "强制整帧重贴" |
| `auditBaseJson` | 底图 vs "强制底图全建" |
| `selfCheck` | 宿主画布 vs 引擎帧 |
| `edit_probe` / `worker_probe` / `stress_probe` / `multi_probe` | 直接读 `frameRgba` / `canvas` / `dirtyPages` |

## 二、目标形态

### 2.1 页位图

```cpp
struct PageBitmap {
    Bitmap px;                      // pageW x pageH，原点 = 页左上角
    uint64_t fingerprint = 0;       // 页内容指纹（沿用现在那把尺子）
    std::vector<uint64_t> line_fp;  // 页内行指纹
    std::vector<float> line_lo;     // 行带上下界（页内磅，擦除用）
    std::vector<float> line_hi;
};
```

引擎持 `std::unordered_map<int, PageBitmap>`，容量上限按页数（默认 `max(2×窗口页数, 8)`），
超出时淘汰"离窗口最远"的页。页位图**只含页本身**：页底色、页边框、格线、字形；
页间隙不进页位图（宿主已有纸底，见 1.4）。

### 2.2 覆盖层

"覆盖层"指现在直接画在帧上、靠矩形清单擦除的那两样：**选区蓝条、光标竖条**。内容是
页纸底、页边框、格线、字形。表单括号与小点不在此列 —— 它们的每一次变化都伴随重排或
光栅签名变化，归内容层（判据与理由见 5D 小节）。

必须分开的理由：内容那张图贵（一页上千字，8~9 ms），瞬态那张便宜（几十微秒）。现在两者
在同一张位图里，所以"光标闪一下"要靠"从底图贴回光标矩形再重画"来收尾 —— 一页一张画布
之后，页内容位图不能再被光标动（一动就是整页重光栅）。

`putImageData` 是覆盖不是合成，透明像素会把下面刷成透明，所以 alpha 混合必须发生在某处。
三种做法，差别只在"由谁做"：

| 做法 | 混合在哪 | 代价 | 前置条件 |
| --- | --- | --- | --- |
| 两张画布叠放 | 浏览器合成器 | DOM 里 canvas 翻倍；`multi_probe` / `web_probe` 数 canvases 的断言要跟；两层要对齐 | 无 |
| 一张可见画布 + 离屏覆盖层，每帧 `drawImage` | 宿主 JS | DOM 不变；覆盖层变化时多一次 `drawImage`（一页 0.9 Mpx，估计 0.2~0.5 ms，未实测） | 要量 |
| **引擎合成**：页内容位图 + 一份合成缓冲 | 引擎 | DOM 完全不变；多一份页大小的缓冲（**不是每页一份**）；覆盖层变化时多一次矩形 memcpy | 引擎按矩形做增量合成 |

三种都不影响 5A / 5B / 5C —— 那三刀只动"页内容位图"。

**调研补记（2026-10-20）**：查过 pdf.js / Excalidraw / tldraw / Flutter / Figma / PSPDFKit /
Chromium 的做法之后，这一项的判断口径改了。见 `docs/分层渲染调研-2026-10-20.md`，要点：

- 别人的"几十层"便宜，是因为那些层是**显示列表或稀疏 DOM**，不是全幅位图。全幅像素层
  按 `W×H×4×dpr²` 收费，跟内容多少无关；Chromium 自己的层策略是"默认合并，能压就压"，
  Chrome DevTools 团队还说过"多个 canvas 比一个更大的 canvas 更贵"。
- 真正决定成本的是**每次上传/重画的面积**，不是层数。现状是"一次光标移动上传整页
  893×1263 = 1.13 Mpx"，而光标只有 2×20 —— 这一笔比"层不够多"严重得多。
- 因此三种做法的差别不在"混合由谁做"（上传面积三者相同），而在**像素账是否逐字节可控**：
  两张画布把混合交给浏览器合成器，`selfCheck` 要改成"合成后再比"，且 alpha 取整可能差
  1 LSB；引擎合成则与现在完全同源，现有 365×2 条像素判据的形状不变。

**当前倾向第三种（引擎合成、单画布）**，前两种降为备选。真正的分叉收窄为一句话：
覆盖层是"单层 + 矩形合成"，还是"每页再开一张稀疏透明层"（后者只在出现昂贵静态内容、
批注、协同光标时才值得）。这一条等到 5D 前用实测确认，不再作为 5A–5C 的前置条件。

第三种容易被误读成"每页两份位图"，实际不是。引擎合成的形状是：

- 页内容位图：每页一份，整页（3.4 MB/页）—— 内容缓存，省不掉；
- 合成缓冲：**只有一份**，页大小，跨页复用；
- 三份擦除清单（光标 / 选区 / 标记）：仍然是矩形，几百字节，不是像素。

每帧对"覆盖脏矩形"（旧 ∪ 新）做三步：把页内容位图那一块 `copyRectFrom` 进合成缓冲、
在这块上画覆盖、把这一块 `putImageData` 回页画布。矩形通常只有一行高，全选时最坏是一整页
3.4 MB —— 而那一笔现在也存在（选区画在帧上，本来就要重贴整块）。这一条与现在的
`copyRectFrom(base_, r)` 完全同构，坐标从帧换成页内，不是新增机制。

内存对照（5 页窗口，现状 `base_` 18 MB + `bitmap_` 18 MB）：

| 路线 | 像素缓冲 |
| --- | --- |
| 引擎合成 | 页缓存 N×3.4 MB + 一份 3.4 MB 合成缓冲 |
| 两张画布 | 页缓存 N×3.4 MB + 宿主每页一张 3.4 MB 覆盖背衬 |
| 离屏 + drawImage | 页缓存 N×3.4 MB + 宿主一张 3.4 MB 离屏画布 |

三条都比现状省，因为"整窗拼接"的那一张没有了。

两种模式下的落地形态不同：

- 分页：一页一张页画布，覆盖层按页给（同尺寸，叠在页画布上或 `drawImage` 上去）；
- 连页：一张视口内容画布 + 一张视口覆盖画布，每页的覆盖小图按 `dy = page*step - scrollY`
  贴上去，相邻页在缝上不重叠。

缓存键：`(selection, caret, mode, bracket 计划, zoom, page)` 的签名；签名没变就不重画。

### 2.3 页间隙归宿主

引擎不再画页间隙背景。判据要加一条"页纸底色与引擎页底色是同一个值"——两边白不一样
时会出接缝，而它只在页边界那一两像素上，像素判据容易漏。

### 2.4 连页：条带画布（2026-10-20 定）

连页现在是"一张视口画布 + 每拍按 `页号 × 步距 − scrollY` 重贴"（`worker_host.js` 的
`syncViewCanvas`、`engine_worker.js` 的 `blitPageContinuous`）。这条路径要删掉，改成与
分页**同一套贴图**：spacer 撑到 `contentPx`，画布按 `页号 × 条带高` 绝对定位，gap = 0、
不画页边框。原生滚动，滚动时引擎一次都不用被叫醒。

**为什么不是"一张真实高度的画布"**：画布有硬上限（Chrome 单边约 65,535，Firefox 约
32,767，Safari 桌面约 25,600；dpr 2 时全部减半）。96 dpi 下一页 1123 设备 px，58 页就
顶到 Chrome 的边、29 页顶到 Firefox 的边；内存是 O(文档)——58 页 207 MB、200 页 713 MB，
而现在是窗口 5 页 18 MB。超限时 canvas **不抛错**：宽高一设，后续绘制全变 no-op，
表现是整片空白。

**为什么条带能直接换过去**：连页排版是"无翻页、页号由 y 现算"（`layout.cpp` 的
`slabOfY`），一**行**可以跨条带。表格行按 `PageSpan` 分页，同样落在条带内。

**接缝必须按几何相交，不能按页号归属**（落地时踩到的第一条）。一行跨了条带边界时，
"这一条带该画什么"的答案是"与它相交的一切"，不是"页号等于它的那些"。三条规则缺一条
就是半行字或半行高亮：横排的字形跟行盒同属一条带（按基线取页号会把整行塞进下一带、
页内 y 为负、上半截裁掉；竖排仍按字形自己的 y，因为一列本来就是一列到底）；
下一条带在顶部补画上一条带越过带底的那一截（字形、原子框、格线、括号与小点同一趟，
整体上移一个带高）；页指纹把越界的字形同时混进下一条带，否则改一行只重画上一带。
选区与光标同理，`collectTransient` 会把上一条带里越界的那一截在本带再记一份。
判据是 `edit_test` [59]：同一份文档切成 N 带拼起来，与切成一条整带逐字节相同。

**要删的**：`syncViewCanvas` / `viewCtx` / `blitPageContinuous` / 门面的"视口画布"消息；
`syncSpacer` 里那条 `viewContinuous` 分支的滚动高度来源保留（它取 `contentPx`，是对的）。

**风险**：原生滚动的亚像素位移会让快速滚动时字轻微重采样 —— 分页模式已经如此，
产品已接受。条带边界接缝按上面那三条规则处理，判据见 [59]。

### 2.5 水印：最底层，但不是第二张画布（2026-10-20 加）

产品后续要加水印，层序因此定死为：

```
页底色 -> 水印 -> 页边框 / 格线 / 字形 / 原子框 -> 装饰 -> 瞬态
```

水印在**视觉上**是最底层，但**物理上不该是第二张画布**。理由是内容位图不透明（页底色 + 字），
要让下面的水印透出来，内容层必须带 alpha：整条像素路径（字形抗锯齿混的是水印色还是透明）、
`selfCheck`、"内容层 == 文档的纯函数"这条不变量全要改，代价远大于收益。

实际形状是**一张共享的水印位图**：

- `WatermarkLayer { Bitmap px; uint64_t fp; bool valid; }`，**页大小、全文档一张**（不是每页一张）。
  它同时包含页底色——因为它是最底层，底色本来就属于它。
- 页光栅的起点从 `fillRect(page_fill)` 换成 `blitFrom(watermark.px, 该页或该带)`。
  带光栅时只搬那一条带，面积与原来的整页填充相同，成本是 memcpy 对 memset，同一量级。
- 水印本身只光栅一次（文本 / 倾斜 / 平铺 / 图片都画进这一张），之后每页只是搬它。
  水印关闭时 `valid = false`，走回原来的 `fillRect`，**默认路径零回归**。

**失效靠"光栅纪元"，不靠逐项比对。** 水印状态（文本、字体、字号、颜色、角度、间距、页大小、
zoom）连同缩放、页度量、底色、边框、格线、原子框，一起混进一个 `raster_epoch_`；每一页的
指纹 = `hash(内容指纹, raster_epoch_)`。改水印 = 纪元 +1 = 所有页自动失效。
这同时把 5A 里"`setConfig` 手动比七项再整份清缓存"收成一处，是 TRAPS 128 的正解
（页面底色这类配置本来就不在内容指纹里，靠人工列表迟早漏一项）。

**判据**：

- 水印关闭时，页位图与今天的实现逐字节相同（默认路径零回归）；
- 开水印后 `auditPage` 仍逐字节一致（它绕开缓存从零光栅，也会走水印）；
- 改一次水印文本，窗口内**所有**页 `repainted_pages == 窗口页数`（纪元让它们全失效），
  且再改回来像素回到原值；
- 排版自审的摘要 A/B/C 不变——水印不进排版，只进光栅。

**什么时候才需要真正的一张底层**：水印动态变化（每页不同、随时间变、按用户变）或必须
"不可移除"地压在最上面时。那时按页缓存水印位图，或按 PSPDFKit 的 overlay mode 拆层；
静态文档水印用共享位图就够了。另：本方案是"水印在下、文字在上"，若产品要的是
"安全水印盖在文字上"，那是顶层，需要另一套混合规则，不要混为一谈。

## 三、刀口与判据

四刀，每刀都能独立验证、独立回退。先后顺序按"风险从低到高"排。

### 5A 页位图（纯引擎内部，对外接口一个字不改）

- 新增 `PageBitmap` 与 `pageCache_`；`paintPageIntoBase` 改成 `rasterPageInto(PageBitmap&, page, band)`，
  坐标全部页内化（`off_y` 从 `frameOffsetOfPage(page)` 变成 0，页边框与格线的坐标跟着减）。
- 每次 present：
  1. 按页指纹判断哪些页要重光栅（页在缓存里且指纹相同 → 跳过）；
  2. 重光栅的页写进 `pageCache_[page]`（可只画一条行带）；
  3. 把窗口内每页从缓存 `copyRectFrom` 到帧的槽位置（新增
     `Bitmap::copyRectFrom(src, srcRect, dstX, dstY)`）；
  4. 覆盖层逻辑原样不动。
- 槽、`slot_page_`、`frame_needs_full_refresh_` 这一刀都保留。
- **收益**：换窗与"窗口外页回来"不再整窗重光栅（现在 `base_valid_ = false` 会整窗重来）。
- 判据：
  - 新增 `auditPageJson(page)`：页位图 vs 从零光栅同一页，逐字节相同；
  - 现有 `auditFrame` / `auditBase` 改指向页缓存，diff 必须仍为 0；
  - 空转 present 耗时不变（现 0.1 ms 量级）；
  - 换窗计数器：只光栅"新进窗口且缓存里没有"的页。

### 5B 按页接口（引擎加，宿主不用）—— 已落地

- `pageRgba(page)`：这一页的像素视图（wasm 堆上，零拷贝）。**纯读**：页不在缓存里或已过期时
  给空视图，不在读命令里补一次光栅 —— 补了会把字形账算到读命令头上，而账是"这一拍排了多少"
  的证据。宿主在 `present()` 之后读它。
- `pageDirtyRects(page)`：自上次取走以来这一页写过哪些矩形（页内坐标），读后清零。
  口径是"页位图上真的变了的地方"：内容重光栅（整页或行带）+ 瞬态（光标 / 选区 / 标记）的
  新旧矩形；**帧的重建不算** —— 帧重建只改落点，页像素一个字节都没动，算进来会让换窗
  退化成整窗重传。
- `frameRgba()` 保留（内部用页缓存拼），作诊断与 5C 之前的兼容路径。
- 判据：`pageRgba(p)` 与 `frameRgba()` 里第 p 页那一块逐字节相同（对窗口内每一页）。
  **比之前必须藏光标**：页位图不含瞬态，帧含瞬态，不藏就永远差光标那一块（TRAPS 132）。

这一刀同时落地了 **`raster_signature`（光栅签名）**：把缩放、页度量、页面底色/边框、
格线、原子框混成一个哈希，记进每条 `PageBitmap`，`pageBitmapFresh` 比它。
`setConfig` 里原先那张"手写八项、任一不同就清缓存"的清单删掉 —— 漏一项就是 TRAPS 128
那种"改了底色屏幕不变"。改水印时只要把水印状态加进 `rasterSignature()`，所有页自动失效。

### 5C 宿主按脏矩形上屏 —— 已落地；删帧与槽并入 5D

原计划在 5C 里删掉帧与槽。实施时确认这条走不通：**页位图只有内容**，宿主按页贴就等于
把光标、选区、表单括号全丢了 —— 它们今天画在帧上，而帧是"内容 + 瞬态"的合成品。
要让宿主按页贴，得先让瞬态有一条自己能导出的路，那正是 5D 的事。硬做只有两种收场：
把瞬态烘进页位图（擦一次就得重光栅那块内容），或者每页多存一份全幅导出位图
（5 页 +18 MB，比现在更差）。

所以 5C 只落它真正独立的那一半：**上屏面积**。

- `engine_worker.js` 的 `blitPage(p, rects)` 与 `app.js` 的 `blitFrame`：按
  `pageDirtyRects(p)` 只贴变了的块。槽过期（窗口刚平移进来的页）仍整页贴；
  引擎报了脏却给不出矩形时也退回整页 —— 宁可多传，不能让画布停在上一拍。
- 连页模式不变：目标 y 随滚动变，整页都得重贴，矩形在这里没有意义（滚动不是"某几块变了"）。
- 引擎补了两条。第一条：整帧重贴（`frame_needs_full_refresh_`）时，**旧光标 / 旧标记 /
  旧选区都要进页脏矩形** —— 原先那个分支只填"选区变了"的那一份，因为帧整窗重画之后
  旧标记自然没了；但页画布上的那份还在，不记就是永久残留（TRAPS 134）。
- 第二条更要紧：**页脏矩形的来源必须是完备的那一份**。第一版按"谁画的"记（内容光栅记
  整页/行带，瞬态记旧光标 / 旧标记 / 选区差集），看起来覆盖了每条绘制路径，实测仍漏
  93 px（3×31，一个旧光标）——`selfCheck` 报"画布有、帧没有"，而 `auditFrame` 是 0、
  native 判据全绿。现在把 `refresh`（帧上真的写过哪儿）也一并转成页矩形：它包含擦除，
  所以不会漏（TRAPS 136）。代价是整帧重贴那一拍退回整页上传，与改动前同价。
- 上传面积（`edit_test` [58] 实测）：光标一次移动 **72 px²**、打字 **12 338 px²**、
  整页 102 000 px²。宿主侧另有 `blitPx` 账（`lastBlit.px` / `viewDiag.blitPx`）。
- 宿主侧两条实施时才发现的约束（都只在浏览器里显形，native 看不到）：
  - worker 的 `OffscreenCanvas` 上，`putImageData` 的**六参数形式 + 负 dy** 会把那一块
    裁错（普通 canvas 上同一个表达式是对的）。改成逐块拷成小图、两参数贴（TRAPS 137）。
  - `selfCheck` 要先 `host.blitPages()` 再比：两次操作之间可能有一拍只 present 没 blit，
    直接比会把时序当成贴错（TRAPS 138）。

剩下来这些都以"瞬态能独立导出"为前提，随 5D 一起做：
`setFrameSlots` / `frameSlots` / 槽表 / `slot_page_` / `frameOffsetOfPage` /
`frame_slot_count_` / `base_valid_` / `base_first_page_` / `base_page_count_` /
`takeBlitBox`；`frameRgba()` 改成现场拼一张（只给探针与诊断）；连页换成条带画布
（见 2.4），删掉视口画布那条支线。

### 5D 瞬态层（形态待定，倾向"单层 + 矩形合成"）

**括号与小点不进瞬态层，搬进页内容位图**（2026-10-20 晚改判，推翻本节初稿）。
判据不是"它今天画在帧上"，而是**"它变的时候会不会顺带改页指纹或光栅签名"**：

| 改什么 | 占位宽度 | 排版 / 页指纹 | 光栅签名 | 结果 |
| --- | --- | --- | --- | --- |
| 边界字符 `[` → `【` | 变 | 变 | 变 | 重排 + 重光栅 |
| 显示 / 不显示边界 | 变（占位没了） | 变 | 变 | 重排 + 重光栅 |
| 小点开关 | 不变 | 不变 | 变 | 只重光栅 |
| 边界颜色 | 不变 | 不变 | 变 | 只重光栅 |

最轻的一档也是整页重光栅，所以"矩形出口"永远用不上；对照光标移动，四列全不变 —— 那才是
需要出口的东西。**瞬态只剩光标与选区两样**（括号常显之后小点也不再随焦点走）。

搬家的落点：`drawControlMarks` 的绘制搬进 `rasterIntoBitmap`（页内坐标），配置项并进
`rasterSignature`：边界字符（左右两串）、`control_mark` / `control_mark_ro`、小点开关与
`control_dot_pt`。于是 `control_marks_prev_`、`mark_sig_prev_`，连同它们在 `refresh` 与
`transient_dirty` 里的分支整个删掉。

**已落地（2026-10-21 00:29）**：

- 绘制搬进 `rasterControlMarks(Bitmap&, page, band_lo, band_hi)`，在 `rasterIntoBitmap`
  末尾调用 —— 页内坐标、跟着 band 裁剪，于是页位图 / 整窗底图 / `auditPage` 三条路径
  自动同源。`drawControlMarks` 与它在 `presentInternal` 里的调用删除。
- `rasterSignature` 补 `show_brackets` / `show_control_dots` / `control_mark` /
  `control_mark_ro` / `control_dot_pt`。
- **只读位是个特例**：它只改括号颜色，不进块哈希、页指纹看不见 —— 所以 `relayout()` 里
  比一份 `mark_readonly_prev_`（上一次各控件的只读位），变了就清页缓存。漏了它的症状是
  "字段改成只读之后括号还是蓝的"，判据是 `edit_test` 里那条"变了的列只有它那一对括号"。
- 删 `control_marks_prev_`、`mark_sig_prev_`、`markPlanSignature()` 及它们在 `refresh` /
  `transient_dirty` / `grow` / `notePage` 里的分支。`frame_needs_full_refresh_` 保留
  （切模式、undo / redo、`auditFrame` 还在用）。
- 层序随之改变：光标从"括号之下"变成"括号之上"。旧注释里那条"画光标前 `copyRectFrom`
  会把标记一并抹掉"的 bug 类随这次搬家消失，对应断言降级成回归判据。

判据：native 4/4（150 / **1433** / 845 / 297），三个 `LayoutDigest` 摘要仍逐位不变
（搬家只动绘制位置，没动排版）；web `edit_probe` 369 ×2、`worker_probe` 74、
`multi_probe` 35、`error_probe` 19 ×2 —— 只剩 4 条已知字体存储账红（TRAPS 131）。

三条实现要点：

- **改字符必须重排**：槽宽 = 字符 advance + 间隙，字符是排版输入。`setConfig` 里
  `plan_changed` 要从"档位变了"扩成"占位计划变了"（含字符），否则按新字符画、按旧宽度排
  —— 正是 `setConfig` 注释里记的那个 bug。字符因此要进排版参数（进而进块哈希），
  不能只在光栅层用。
- **缺字形要兜底**：自定义字符在 `bracket_font` 里没有 nominal glyph 时不能静默不画
  （槽里空一条），要么退回 `[` / `]`，要么拒绝这次配置。
- **层序随之改变**：今天括号画在光标之后（压住光标），搬进内容层后变成光标压住括号，
  重叠的那几个像素画面会变，像素判据要跟。

只读模式不受影响：`bracketedControls()` 返回空 → 排版没有占位 → 内容位图里本来就没有
括号，打印 / 导出天然干净（目前还没有导出实现）。

**小点开关的粒度**：它不占宽度、不动排版、不动页指纹，只动光栅签名 —— 所以是"整页
重光栅"，不是"补几块"。严格说，开小点可以只补画（绘制顺序固定为内容→小点，补画结果与
全量一致），关小点却必须恢复被盖住的像素；而引擎只有行带级的内容重光栅
（`blitPageIntoBase(page, lo, hi)`），没有任意矩形级。第一版统一走整页（8~9 ms/页，
开关是设置项不是每帧操作），优化留到实测之后，且不得破坏 `auditPage` 的逐字节对拍。

### 5D-0 配置化与砍掉 Focused 档（与 5D 分开做）

产品口径（2026-10-20 定）：

- 边界字符可配置，默认 `[` / `]`，**支持多字符**；一串边界是**一个整体**（一个占位簇），
  光标与选区都不进入它内部；
- 小点是独立开关（`show_control_dots`），开启时**所有控件**都画，与焦点无关；
- `FormBracketScope::Focused` 直接砍掉，`form_brackets` 退化成 `bool show_brackets`。

为什么单独一刀：它只改语义、不改绘制位置，每条都能用现有判据验证（`auditFrame` 对拍、
`edit_test` 的括号用例）。做完之后 5D 只剩"搬家"，不会两件事同时改。

影响面（按文件）：

- `engine_config.h`：删 `FormBracketScope`；`form_brackets` → `show_brackets`；新增
  `bracket_open` / `bracket_close`（UTF-8，上限 4 个码点）与 `show_control_dots`。
- `engine.h`：`bracketedControls()` 去掉档位分支；`bracketPlanId()` 退化成
  `bool bracketsOn()`（只读 / 无控件 / 开关关 → false），**但 12 处调用点要留着** ——
  它们防的是"这次编辑改了'要不要显示括号'"（撤销删掉最后一个控件、进出只读），
  只是比较值从 int 变 bool。`bracketPlanKey()` 整个删掉：它多出来的一半是控件节点 id，
  防的是"聚焦换了、下标相同而字段不同"，集合退化成"全部或没有"之后这个场景不存在。
- `engine.cpp`：`setConfig` 的 `plan_changed` 改成"占位计划变了"（开关或字符变了）；
  `markLayoutDirtyForBrackets` 的脏区仍要带右端（TRAPS 125 的教训在排版脏区本身，
  与档位无关，别顺手把右端删掉）。`markPlanSignature()` 里"聚焦字段下标"那一项删掉，
  同时补上 `control_mark` / `control_mark_ro` / 小点开关 —— 它今天不含颜色，改标记颜色
  会留下旧颜色的括号，只是 UI 没暴露这个入口所以没显形。
- 排版：槽宽 = 整串字符 advance 之和 + 间隙；`LineCluster` 结构不用改（`advance` 已经
  能表示任意宽度），但绘制要逐字符推进；一串比行还宽时按原子处理（现状不会出现，补测）。
- `engine_paint.cpp`：`drawControlMarks` 删 Focused 分支与 `innermostAt`；小点改成
  "开关 + 遍历全部控件"。
- `wasm_main.cpp` / `web/`：配置项改名与新增；界面把"档位"换成"显示边界 / 边界字符 /
  显示小点"。
- 测试：Focused 档的用例删。TRAPS 125 只有后半条（"换字段的脏区取两段凸包"）随档位
  一起失效；前半条"排版脏区必须带右端"是通用的，必须留 —— 开关 / 字符变化的脏区仍然
  只在右端已知时才敢走后缀复用。
  `LayoutDigest` 默认值不变（默认仍是 `[]` + 常显），两个摘要必须逐位不变。

判据：native 4/4（`edit_and_caret` 1433 项，0 失败）；三个 `LayoutDigest` 摘要逐位不变
（`0xf0f0d9e785e9abc4` / `0x6cc491bde1299030` / `0x53923fb9d204873a`）；web 侧
`edit_probe` 369 ×2、`worker_probe` 74、`multi_probe` 35、`error_probe` 19 ×2 —— 只剩
4 条已知字体存储账红（TRAPS 131）。新增判据：小点开关 → 帧逐字节变化 + 关掉后逐字节回到
开之前（native）；小点开关不触发重排、开 / 关后屏幕都等于引擎帧（探针）。

两条被改写的老判据：

- `edit_test` [12]（两次 present 的账）：制造"整窗重贴"的动作从"Focused 档换字段"
  改成"关括号"。
- `edit_test` [56](d)：从"聚焦换字段后占位真的挪了"改成"开关括号 → 全篇 8 段占位翻转，
  增量仍与全量一致"。

不论选哪种形态，这三条是共同的：

- 瞬态不再触发整页重贴，上屏粒度是**矩形列表**（与 5B 的 `pageDirtyRects` 同一口径）；
- 擦除方式从"从底图拷回"变成"重新合成这一块"（先清、再画），
  于是 `sel_paint` 那套"整块重铺再混一次"的防累积逻辑连同它防的 bug 类一起消失；
- 三份 `prev` 清单的角色从"擦除依据"变成"脏矩形来源"，`frame_needs_full_refresh_`
  随 5C 一起消失。

两种形态：

| | B 单层 + 矩形合成（推荐） | A 每页稀疏透明覆盖层 |
| --- | --- | --- |
| 额外全幅像素 | 0（一份矩形大小的合成暂存） | 有标记的页各一张（通常 1~3 页） |
| 混合由谁做 | 引擎（与现在同源） | 浏览器合成器 |
| `selfCheck` | 语义不变，逐字节 | 要改成"合成后再比"，容差 1 LSB |
| 像素判据 | 365×2 条形状不变 | 凡是对着画布找光标/选区的都要跟 |
| 内容层是否被弄脏 | 是（小块，一次 `putImageData`） | 否 |
| 新风险 | 全页重贴时要把瞬态重新合成一遍 | 两层对齐（分数 DPR / 亚像素滚动） |

选 **B** 的理由是判据面与像素账都不变；选 **A** 的触发条件是出现"昂贵且几乎不变"的内容
（扫描件底图、水印、签名图）或批注、协同光标这类有独立更新频率的装饰 —— 那时它符合
"同频同层"，才值得为它多开一张位图。依据见 `docs/分层渲染调研-2026-10-20.md`。

- 引擎：`pageUploadRects(page)`（内容损伤 ∪ 瞬态新旧矩形的并集）、
  `pagePixels(page)`（合成后的页视图，零拷贝）；分配只给"这一页真的有瞬态"的情况。
- 宿主：仍然一张页画布，`putImageData(img, 0, -rect.y, rect.x, rect.y, rect.w, rect.h)`。
- 删：`control_marks_prev_` 与 `mark_sig_prev_`（括号与小点已归内容层）；
  `selection_rects_prev_` / `caret_rect_px_prev_` 保留，但语义从"擦除依据"变成
  "脏矩形来源"。
- 判据：一次光标移动的上传矩形 ≤ 2 个、总面积 < 200 px²（现在是整页 1.13 Mpx）；
  `selfCheck` 逐字节；全选拖动时上传面积 == 选区矩形面积之和，不是整页。

### 5D-2 删帧与槽、瞬态改成导出时合成、连页换条带 —— 已落地（2026-10-21 02:5x）

这一刀之后，**引擎里没有"帧"这个东西**了。落地形态与本节初稿的差别只有一处措辞：
瞬态不是"另开一层再合成"，而是**导出时才叠**——

```
页位图（内容，唯一可写真相） --pageDisplayPixels--> 内容 + 选区 + 光标（一页的导出图）
```

导出图就是 `pageRgba(p)`，宿主直接贴它。于是：

- **没有"擦旧瞬态"这一步**：旧光标之所以消失，是因为下一次导出从干净的页位图重来。
  旧版靠 `caret_rect_px_prev_` / `selection_rects_prev_` 记账再擦，那套账漏一次就永久
  残留（TRAPS 134）；现在这个失败模式在结构上不存在。
- **差分只剩"要告诉宿主哪几块变了"**：`PageBitmap::transient`（选区矩形 + 光标矩形）
  与上一拍比，旧有新无、新有旧无的各自记脏。没变的页产生零上传。
- **零拷贝只在没有瞬态的页成立**：窗口里通常四页属于这一档，直接返回页位图指针；
  有瞬态的那一页拷进 `page_export_`（一页 3.5 MB，0.2~0.4 ms）再叠。

删除清单（都删干净了，没有留兼容壳）：`Bitmap bitmap_` / `Bitmap base_` /
`setFrameSlots` / `frameSlots` / `frame_slot_count_` / `slot_page_` / `slotOfPage` /
`frameOffsetOfPage` / `base_valid_` / `base_first_page_` / `base_page_count_` /
`blitPageIntoBase` / `takeBlitBox` / `noteBlitDirty` / `blit_acc_` /
`frame_needs_full_refresh_` / `noteTransientDirty` / `selection_rects_prev_` /
`caret_rect_px_prev_` / `mark_sig_prev_`（5D-1 已删）/
`syncViewCanvas` / `viewCtx` / `blitPageContinuous`，以及位图接口上两个随之失去调用者
的方法 `Bitmap::shiftVertical`（窗口平移复用）与 `Bitmap::copyRectFrom`（帧 = 底图贴回）。

留下来的两块"导出"是**派生视图**，不是第二个真相：`frame_export_`（窗口图，
给探针/`markCheck`/`inkRows`/`auditFrame` 用）与 `page_export_`（一页合成图）。
两者都在 `presentInternal` 里作废、第一次读时重拼，数据源只有页位图。

**为什么保留 `frame()` / `frameRgba()`**：`edit_test` 有上百条像素判据按"扫一遍画面"
写（`frame()` + `frameWidth()` + 按 y 找行），探针的 `markCheck` / `inkRows` 也是。
删掉它们要改几百条断言，而收益只是少一次 memcpy —— 不划算。它们的语义收窄成
"窗口的读视图"：`frameHeight = 窗口页数 x 步距`，页按窗口顺序摆。

**两个坐标口径一起改了**（TRAPS 140）：`caret_x/caret_y` 与选区矩形都变成**页内像素**，
页号另给（`caret_page`）。宿主的输入法定位、光标滚入视野、探针的点击换算三处各加回
`页号 x 步距`；旧版那个"加一次再减一次"的槽偏移彻底消失。

**连页换成条带画布**（2.4 的落地）：`worker.html` 与 `multi.html` 的 worker 形态各加一个
`#pages` 容器（`position:absolute; overflow:hidden`，高度 = 滚动内容高度），页画布挂在
它里面、按 `页号 x 步距` 绝对定位。连页 = 间隙 0 + 同一套贴图，滚动时引擎一次都不被叫醒。
`setViewMode` 从"交视口画布"降级成纯配置消息（`viewMode`）。

**顺手修掉的一个真 bug（TRAPS 139）**：行带光栅的前提是"带外已经有一份完整像素"。
旧版由"首次全建"那一支绕开，删掉整窗帧之后没有那一支了 —— 页第一次光栅就只画一条带，
带外留零。判据 `edit_test` [16] 的"表单括号"当场红 48 万像素。

**判据**：native 4/4（150 / 1433 / 845 / 297，`edit_test` 里 [12] 从 `takeBlitBox` 改成
"按页 drain 出脏矩形并集"、[58] 去掉槽换算）；web `edit_probe` 369 x2、`worker_probe` 74、
`multi_probe` 35、`error_probe` 19 x2 —— 只剩 4 条已知字体存储账（TRAPS 131）。
连页另做了一次冒烟检查（切过去 / 滚一屏 / 切回来：`selfCheck` 均为 0）。

**收尾清扫（同日）**：注释里描述已删机制的地方全部按现行口径改写，其中最要紧的是
`EngineStats` 六段分解的标签 —— `paint_blit_ms` 名为"帧贴回"、实量"瞬态差分"，已改名
`paint_transient_ms`（JSON 键同步为 `paintTransientMs`，无消费方），面板与 native 报告里
的"帧搬运 / 帧尺寸 / 帧字节数"改成"呈现其余 / 窗口尺寸 / 窗口导出图"。
另补一条判据：画布背衬有像素不等于屏幕上看得见 —— `worker_probe` 用
`elementFromPoint(页中心)` 钉它，`multi_probe` 用"页容器装得下页画布"钉它（TRAPS 141）。

### 5D-3 导出图退出每份状态的通路（2026-10-21 上午）

5D-2 把帧降级成"按需拼的读视图"，但漏了一处通路：`statsJson` 每份状态都带
`"frameBytes"`，而它当时实现成 `ensureFrameExport()`。`presentInternal` 每次都把
`frame_export_valid_` 置假，于是**每呈现一次就重拼一整窗** —— 而这张图在 Web 侧
没有任何消费方（只有探针 `rawFrame` / `markCheck` 与 native 的像素判据读 `frame()`）。

实测（`worker.html`，dpr 2，场景 7 = 2000 段、窗口 6 页）：导出图 **82.9 MB**，
一次按键往返中位 **58.9 ms**、`stateMs` 36.4 ms，而引擎自报排版 1.4 + 上屏 0.7 ms；
常驻堆 242 MB。默认场景（1 页窗口、13.8 MB）同样是 26.4 ms —— 都是"没人读的数字"。

两条改法：

- `frameBytes()` 只做乘法（`frameWidth x frameHeight x 4`），拼图只留给 `frame()`；
- 删掉 `zeroCopyFrame`（`frameRgba()` 是 `typed_memory_view`，那个判据恒真，
  却要先拼一次导出图才能算出来）—— 连同 `worker_probe` 里那条断言与启动栏那一格。

结果（同一探针）：场景 7 按键 58.9 → **12.9 ms**、`stateMs` 36.4 → 16.0、堆 242 → 158 MB；
默认场景 26.4 → 18.7 ms、堆 77.3 → 63.4 MB。拆开看剩下的时间不在状态构造：
`ask('buildStamp')` 0.2 ms、`ask('editStats')` 0.2 ms、`ask('stats')` 0.3 ms，
`present()` 2.4 ms，而 `type()` 12.8 ms —— 差在编辑链路与贴页（TRAPS 143）。

顺带清扫（都是"旧版本的引用"）：

- `web/app.js` 的上屏账按现行口径改名：`frameMs/imageMs/putMs` → `alignMs/blitMs/imeMs`。
  旧标签"上屏取帧 / putImageData"量到的其实是"对齐页画布"与"摆 IME"，
  真正的贴页那段（构造 ImageData + putImageData）反而没显示；
- 删掉两个空桩 `apiHost.viewCtx` / `apiHost.isContinuous`（`engine_api.js` 已不调）；
- 删掉 `engine.cpp` 的死函数 `subtreeHasParagraphMark`（局部重建删掉之后没人调，
  wasm 构建一直在报 `-Wunneeded-internal-declaration`）；
- 注释里指向已删机制的引用全部改写：`base_valid_` / `base_page_count_`（测试）、
  `paintPageIntoBase`（engine.h）、"引擎的帧槽"（worker_host）、"整帧贴一次底图"
  （index.html 的像素账提示）、"帧缓冲组装完"（面板耗时说明）。

判据：native 4/4（150 / 1439 / 845 / 297）；`worker_probe` **74**（删掉零拷贝那条恒真断言）、
`multi_probe` 36、`edit_probe` 369 x2（只剩 4 条 TRAPS 131）、`error_probe` 19 x2、
`web_probe` 6、`stress_probe` 69 次点击；`lint_comments` 0。

## 四、回退点与"停下来问"的条件

### 为什么不做"任意脏矩形"（2026-10-20 判断，暂不做）

行带 → 任意矩形是"像素重画"这条路的最后一段，但它不是最强的一档：再往上是 display list
（`SkPicture` 式指令重放 —— 改一个字只重放两条指令，不重画任何像素）。两者差一个维度，
不是同一条尺子的两端。

现在不做的依据是实测，不是成本：

- 一页 1.13 Mpx、整页重光栅 8~9 ms —— **页有物理上限，任何像素级优化的收益都被它封顶**；
  无限画布或超大页（PDF 阅读器一页五千字）才有 display list 的用武之地。
- 行带已经把打字压到 12 338 px²、光标 72 px²。再切矩形，省的是行内横向空白，量级 10⁴ px，
  与整页差两个数量级。
- 一次敲键 3.2~3.6 ms（2000 段 wasm）里，投影 0.8~1.1 ms，其余主要不是像素写入 ——
  真正的成本在 shaping 与排版。

富文本的增量难点也不在重画，而在**排版的流式性**：改一个字可能改断行点，下游全体平移。
那条线已经在做（增量投影 + 增量排版 + `LayoutDigest` 锁），收益比脏矩形大一个量级。

值得回来做任意矩形的触发条件（任一）：

1. 某次编辑的光栅耗时 > 投影 + 排版耗时（看 `stats_` 的六段账，不是靠猜）；
2. 表格编辑成为主路径 —— 单元格窄、行带宽，是矩形唯一明显赢过行带的地方
   （现在"有表格时一律不做增量排版"，这条路还没打开）。

★ 更值钱的是另一件事：**脏矩形解决"小改动别画大片"，分层解决"大片别每次画"**。
页边框、表格线、水印都是"面积大、变化少"，对它们用脏矩形是浪费 —— 该进缓存层
（水印层的做法见 2.5）。

每刀的检查点，出现下列任一情况先问，不自行改设计：

- 5A：`auditPage` 出现非零 diff，且原因不是"页间隙/页边框坐标没减干净"。
- 5B：`pageRgba` 与 `frameRgba` 的对应块差在 1 个通道以内但位置整体偏移 —— 那说明
  页内坐标与帧坐标的换算还有一处没统一，属于设计问题不是笔误。
- 5C：`multi_probe` 因 DOM/画布数量变化翻红（它直接数 `canvases`）。
- 5D：一次光标移动的上传面积没有降到 10³ 像素以下，或 `selfCheck` 出现 1 LSB 的差 ——
  后者说明合成路径与绘制路径没有真正同源（同一个 Skia 调用面），不要用容差糊过去。
- 任何一刀要让 `edit_probe` 的像素断言改写超过 20 条 —— 说明接口粒度选错了。

## 五、不做的事

- 不动 `bitmap_skia.cpp` 的 Skia 调用面（hinting / 亚像素 / 灰度抗锯齿 / 旋转），
  那是"今天的像素长这样"的全部原因。
- 不改 `Continuous` 的**排版语义**（页间隙为 0、页号由 y 现算、无翻页）；2.4 换的只是
  贴图方式，排版一行不动。
- 不做"多线程光栅"、不做"GPU 合成"。
- 不顺手改表格增量（`can_resume` / `trySuffixReuse` 的两个早退），那是另一条欠账。

## 六、2.1 与 2.2（块流收成一份、位置索引）

复核报告把这两项挂在步 5，理由是"与 `blocks` 所有权同一件事"。实际读下来它们
**与渲染层正交**：`rasterPageInto` 只读 `layout_`（行、字形、`placed_tables`）与 `cfg_`，
不读 `blocks()`；`syncInlineObjects` 读块流是在排版之前，不在光栅里。

所以它们是步 5 的伴生项，可先可后，但**建议放在 5D 之后**：那时渲染层已经稳定，
改块流只需要跑排版与编辑两套判据，不用同时盯像素。

2.2 的位置口径有三种选法（复核报告 2.2 的追记），需要在动手前定：

- a：位置仍由 `finishRebuildFromTree` 递推，只是把 `block_flow_*` 收进 `BlockFlow` 结构
  —— 只收形状，不动口径，风险最低；
- b：位置进块流（每块带 `flow_start`），复用时按 delta 平移 —— 要解决"复用块的 delta
  各不相同"，是真正把位置变成块属性的做法；
- c：位置按需计算（查询时用前缀和），不常驻 —— 每次查询 O(块数)，与"空转 present 0.1 ms"
  冲突。

建议 a：它兑现"引擎不再有七个数组"，但不引入任何会静默漂移的坐标。

## 八、5A 实施记录（2026-10-20）

已落地。实际形状与上文 2.1 的草图有三处不同，都是实施时才定下来的：

**缓存条目只记一个版本号。** `PageBitmap` 是 `{Bitmap px; uint64_t fp; bool valid;}`：
`fp` 记"这一份像素对应哪一版页指纹"，与 `page_fp_new_[page]` 相等就不重光栅。
指纹数组里没有这一页时一律判"不新鲜"——没有版本号就不敢断言像素作数。
`markPagesChangedFrom` 的哨兵值也算一版（它的低位每次都会翻，同一个哨兵不会连着出现两次）。

**配置变化必须整份作废缓存，页指纹看不见它。** 缩放、页度量、连页、页面底色、页边框、
格线、原子框这几项决定页里画出来的像素，而它们一个都不在页指纹里（指纹只哈希字形）。
`setConfig` 里据此比一遍，任一不同就 `page_cache_.clear()`。
漏掉这一条的后果是"改了底色，屏幕上还是旧底色，直到某一页的内容变了"。

**容量是"窗口页数 + 2"，整篇窗口不缓存。** 这一阶段整窗底图（`base_`）还在，缓存的每一页
都是净增内存（96 dpi 一页 3.6 MB）。两条余量够"滚回来一页"。窗口页数超过 12（没有视口
锚点的整篇模式）时整份清掉：那种模式下"离窗口近"没有意义，而内容没变的页在下一拍
根本不会走到光栅那一步，清掉不亏。

实施中新发现的两条口径：

- `blitFrom` 的取整必须与 refresh 那个 `Rect` 完全一致（`floor(起点)`、`ceil(起点 + 高)`）。
  少取一行就是"版面上留一条旧墨迹"，而且只在恰巧跨半像素时出现。
- `auditBaseJson` 必须先 `page_cache_.clear()`：不清的话"底图全建"只是把同一批页位图
  再搬一遍，比出来的是搬运的确定性，而不是光栅的确定性。

判据（`edit_test` [57]，8 条）：窗口内每页 `auditPage` 与从零光栅逐字节一致；换窗一页时
`repainted_pages == 1`；缓存清空后四页全部重光栅（反向一半，防止计数器恒报小值）；
打字之后逐页仍与从零光栅一致（行带增量没有留下旧像素）。
另外 [5] 里那条"页数变了 → 两页都重画"改成了"新页被光栅进缓存"——第 0 页内容没变，
复用它的像素正是这一刀要省的那笔。

## 九、5B 实施记录（2026-10-20）

已落地。接口与判据如上，实施时定下来的三处：

**脏矩形按"页位图写入"记，不按帧的 `refresh` 记。** 帧整窗重建时 `refresh` 里每一页都有
一整块，但那些页的像素一个字节都没动；照抄 `refresh` 会让换窗/改配置时所有页都整页重传。
所以内容部分在 `rasterPageInto` 的调用点记（整页或行带），瞬态部分单独记（旧光标、旧标记、
选区新旧差集），最后落到页内坐标。

**合并规则要能收住表单页。** 一页几十个字段时，新旧标记加起来上百个小矩形，逐条
`putImageData` 反而更贵。`notePageDirty` 把相交/相接的并成一个（光标擦旧画新就是这种），
超过 16 条退回一个并集 —— 并集是上界，宁可多传不可少传。

**`pageRgba` 不补光栅，`pageDirtyRects` 读后清零。** 前者保证读命令没有副作用（字形账不被
污染），后者与 `takeBlitBox` 同一套"取走即消费"的语义。宿主在 `present()` 之后按页读，
顺序反了会读到空视图 / 上一拍的矩形。

判据 `edit_test` [58]（14 条）：四页 `pageRgba` 与帧对应块逐字节相同（先藏光标）、
无缓存的页给空视图、一次光标移动的上传面积 **72 px²**（整页是 102000 px²）、矩形覆盖光标、
读后清零、打字的上传面积 **12338 px²**（一行带）、打字后 `auditPage` 仍为 0、
改底色后四页全部重光栅、同样配置再设一次 **0 页**重光栅（反向一半）。
