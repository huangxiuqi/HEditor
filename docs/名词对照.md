# 名词对照

这份文档只做一件事：把仓库里出现过的名词按"它属于哪一层"排好，并指出最容易混的几对。
名词是按层长出来的，离开层谈名字就会混。所以先记住四层：

```
模型层（树）  →  编译层（块流）  →  排版层（行盒/几何）  →  编辑层（事务）
   节点            块、run、对象          簇、槽、行内轴         落点、区间、步骤
```

层与层之间只有一处换算收口（`compile` 与 `EditorEngine` 的桥），**跨层同名不同物是设计使然，
不是命名混乱**。真正需要警惕的是同一层里同物不同名，那几处列在最后。

## 模型层（树）

| 名字 | 代码 | 是什么 |
|---|---|---|
| 节点 | `Node` / `NodeId` | 树的单位。`NodeId` 是身份，插入删除之后不变 |
| 节点种类 | `NodeKind` | `Document` / `Section` / `Table` / `ContentControl` / `TextRun` / `ParagraphMark` 等 |
| 文本节点 | `NodeKind::TextRun` | 贡献码点的原子叶子，带字符属性。名字借自 Word 的 `w:r` |
| 段落标记 | `NodeKind::ParagraphMark` | 切段的那一位，**同时挂段落格式**（所以拆段/合并要修格式归属） |
| 内容控件 | `NodeKind::ContentControl` | 常简称"控件"。结构形态（容器型/原子型）与业务类型都是**数据**，不是节点种类 |
| 节 | `NodeKind::Section` | 页面设置的作用范围 |
| 标记 | `Mark` / 字符属性 | 文本节点上的属性集合（粗体、字号……） |
| 节点级位置 | `Pos` | `{container, offset}`：容器里 `offset` 是子槽序号，文本节点里是码点下标 |

## 编译层（树 → 块流）

| 名字 | 代码 | 是什么 |
|---|---|---|
| 块 / 块流 | `BlockSpec` | 引擎的输入单位，就是"段"的排版视图。一段一个 |
| 段落文本 | `cp_text` | 整段文本的**码点数组**。多个 `TextRun` 的码点首尾相接拼成它 |
| 格式 run | `runs` / `FormatRun` | 字符格式区间：`[cp_begin, cp_end)` + 字体/字号/颜色。**不存文本** |
| 行内对象 | `objects` / `InlineObject` | 块流里除文本之外的一项（本期是控件边界）。`cp` 是锚点 |
| 编译产物 | `blocks_full_` | 编译出来的那份，含**全部**边界（不区分显示与否） |
| 显示表 | `blocks_` | 按"要显示哪些括号"筛过的那份（`syncInlineObjects` 产出） |
| 来源身份 | `BlockSource` | 每块对应的树元素（首个内容元素、段落标记），桥接靠它 |

## 坐标（从粗到细）

这四套是同一个位置的不同说法，换算只在引擎内部收口。

| 名字 | 代码 | 数什么 | 谁在用 |
|---|---|---|---|
| 节点级位置 | `Pos` | 容器 + 子槽序号 / 文本节点内码点下标 | 树的操作、`ControlApi` |
| 流位置 | `FlowPos`（`int`） | 深度优先展开后的**全局**元素序号 | 树、能力表、事务、`setCaretAtFlow` |
| 段内流位置 | `rel`（`caret_rel_`） | 段内"数格子"：文本字与边界对象各占一位 | **引擎内部的唯一真源** |
| 码点偏移 | `(段, 段内第几个码点)` | 只数文本字，**不数边界** | 对外接口、`editStats`、命中测试返回 |
| 侧别 | `caretSide()` | 同一个码点偏移上跨过了几枚边界 | 排版几何、命中测试（由 `rel` 派生） |

**簇**（`LineCluster` 的 cp 那一维）：不是坐标，是**量化单位**。见下。

## 排版层（块流 → 几何）

| 名字 | 代码 | 是什么 |
|---|---|---|
| 簇 / 字素簇 | `LineCluster` | **用户感知的一个字符**。整形阶段切出来的不可分单位：`e` + 组合重音 U+0301 是**一簇、两码点**。光标只能停在簇边界上，所以"偏移 +1"不等于"光标右移一格" |
| 簇表 | `para_cluster_starts` | 每段的簇首码点表（段级） |
| 括号占位 | `LineCluster::placeholder` | 控件边界在排版侧占的那**一枚簇**：有宽度、没有字形。它让括号进文档流，把后面的字挤开而不是盖上去 |
| 槽 | 占位那一格 | 槽宽 = 括号字形 advance + 间隙。括号与字一样占位，所以方向键在 `][` 上要按两下 |
| 行盒 | `LineBox` | 一行。簇表、`first_cp`/`last_cp`、行内起点/末位都在它上面 |
| 行内轴 / 块轴 | `inline_pt` / `block_lo_pt` | 行内方向（横排是右、竖排是下）与换行方向 |
| 朝向 | `BracketSide` | 占位是开括号还是闭括号。只服务一件事：同一个 cp 上两个视觉位置，光标要落在朝向内容的那一侧 |
| 槽的归属 | `owner_control` | 占位簇上记的**产生端句柄**。排版层不解释它 |

## 编辑层

| 名字 | 代码 | 是什么 |
|---|---|---|
| 落点 | `caret_para_` / `caret_rel_` | 编辑之后光标停在哪，由操作算出的流位置给出 |
| 区间 | `Range` | `[起, 止)` 的流位置区间 |
| 事务 / 步骤 | `Transaction` / `Step` | 树上编辑的提交单位（先建步骤、后提交） |
| 撤销栈 | `UndoStack` | 引擎持，`undo` / `redo` 恢复的位置本来就是流位置 |
| 归属 | `hintFromRel` / `innermostAt` | 落点算哪个控件：区间树里包含它的最深那个，同深度取下标小者 |
| 默认侧别 | `defaultSideAt` | 没有侧别信息时的投影约定，**只给"宿主按 (段, 偏移) 定位"与 Home/End 用** |
| 句柄 vs 下标 | `controlIndexOfOwner` / `slotOwnerOf` | 占位簇上记的是产生端句柄（树路径是控件节点 id，旧路径是下标）；**对外一律下标** |

## 增量

页指纹（判断这一页要不要重画）、脏段（必然是后缀）、续排（`ReflowState`）、
后缀复用（`FragmentIndex` 的块行切片 + `repaginateSuffix`）。
正确性判据只有一条：**与全量一致**（`auditLayout`）。

## 最容易混的四对

**一、码点 vs 簇。** 一个簇可以占多个码点（`e` + 重音 = 2 码点 1 簇）。所以"偏移 +1"是"往后一个
码点"，不是"光标右移一格"；方向键走的是簇。光标与编辑落点都要先吸附到簇边界。

**二、流位置 vs 段内流位置 vs 码点偏移。** 全局 / 段内 / 不数边界 —— 三个都不一样。
`FlowPos` 是全局的（跨段、含段落标记与节边界），`rel` 是段内的，码点偏移连边界都不数。
换算只有两处入口：`flowPosAtSide`（正）与 `cpOffsetInBlock`（反）。

**三、三个 run。** `TextRun` 是**树里的文本节点**；`FormatRun` 是**编译产物的格式区间**；
`FontRun` 是**排版期按字形覆盖切出的段**（派生量、不落盘，与 `FormatRun` 求交才是整形边界）。
`cp_text` 是**三者都不是**：它是多个 `TextRun` 的码点拼成的那一串，节点边界在拼进去时就没了。

**四、段落 vs 块。** "段落"是模型概念（由 `ParagraphMark` 切出来），`BlockSpec` 是它的排版视图。
一一对应，但不是同一个东西 —— 块流里还有段落的边界对象、格式 run 这些模型层没有的东西。

## 一处需要留意的同名

"控件"在三个地方出现，指的都是同一件事但携带的信息不同：模型层是 `ContentControl` 节点
（有身份、属性、子树）；编译层是边界对象（`InlineObject`，只有锚点与句柄）；排版层是占位簇
（`LineCluster`，只有几何与朝向）。看到"控件"先问一句"在哪一层"。
