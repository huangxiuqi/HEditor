# 架构复核：数据流、特例面与引擎拆分的剩余项

复核日期 2026-10-27。范围是整条交付链路（模型 → 投影 → 排版 → 光栅 → 宿主），外加
`EditorEngine` 拆分的完成度。

与 `docs/架构复核-2026-10-19.md` 的关系：那一份写的是 rev 迁移**之前**的实况（树 + 两份块流 +
八本账），其中的"补丁的形状"一节仍然成立，但数据流的描述已经被本份取代。两份冲突时以本份为准。

## 一、数据流

### 1.1 分层

```
                  ┌──────────────── 引擎门面 EditorEngine ────────────────┐
                  │ 命令层 · 光标与选区 · 重排调度 · 呈现与导出            │
                  └──────┬───────────┬───────────┬───────────┬───────────┘
                         ▼           ▼           ▼           ▼
  模型层   rev::Doc（不可变修订 + 撤销栈）—— 唯一可写的真相
                         │
                         ▼
  投影层   rev::project ──▶ blocks_full_ · tables_ · controls · block_extents_ · flow_
                         │
                         ▼
  排版层   layout ──▶ LayoutResult（LineBox · 占位簇 · PlacedTable · 页号）
                         │
                         ▼
  光栅层   bitmap_skia ──▶ page_cache_（页位图）· 行带重画 · 页/行指纹
                         │
                         ▼
  宿主层   pagePixels ──▶ RGBA + 脏矩形 ──▶ 页画布（Worker）
```

侧输入是样式表、字体库、图片资源表、引擎配置与编辑模式：它们只影响投影与呈现，不改真相。

规模（源码行数）：`doc` 16109 / `rev` 7647 / `layout` 4572 / `render` 1322 / `engine` 20428 /
`wasm` 2346 / `web/src` 13092。

### 1.2 一次编辑的链路

```
命令层 edit_command   意图 ──▶ Step[]                       只读 Doc 与块流；拒绝条件全在这一层
      │ commitSteps
      ▼
会话层 rev::Session   applySteps ──▶ Doc′                  旧修订不动：撤销 = 把旧值取回来
      │
      ▼
损伤 rev::damage      块区间 [lo, hi)                       两份修订一减；区间自带右端
      │
      ▼
投影 rev::project     blocks_full_ · 表 · 控件 · 块长       损伤区间外原地复用
      │
      ▼
排版 relayout         LayoutResult                          前缀留 · 后缀搬 · 中间重排
      │
      ▼
光栅 presentInternal  page_cache_                           光栅签名 → 页指纹 → 行指纹 → 行带
      │
      ▼
导出 pageDisplayPixels RGBA + 脏矩形 ──▶ 画布                光标与选区只在这一步叠
```

### 1.3 单向性与权威性

**写路径是单向的**，这一条成立而且有结构保证：命令层的 `EditView`（`edit_command.h:75`）里
文档是 `const rev::Doc*`、块流是 `const std::vector<BlockSpec>*`，命令层没有任何可写的派生结构；
`blocks_full_` 全仓只有 `rev::project` 一个写点（`engine.cpp:655`）；`layout_` 只有 `relayout`
一个写点；页位图只有 `presentInternal` 一个写点。唯一的逆行边是宿主输入事件回到命令层。

**权威要分两边看。** 写侧唯一，读侧不唯一：

| 事实 | 权威存放 | 并存的表示 | 写入口数 |
| --- | --- | --- | --- |
| 文档内容 | `rev::Doc`（`engine.h:3481` 写明"唯一真相"） | 无 | 1（会话层） |
| 撤销历史 | 一串旧修订（`rev/session.h`） | 无 | 1 |
| 块流 | `blocks_full_` | `blocks_`：筛过括号的整份拷贝（`engine_layout.cpp:1205`） | 1 |
| 位置 | `block_extents_` 前缀和 | `block_flow_` / `block_flow_span_` | 1（唯一来源做对了） |
| 排版 / 像素 | `layout_` / `page_cache_` | `frame_export_`（派生） | 1 |
| 光标与选区 | `caret_.selection_`（Range，流位置） | 整格选区另有 `cell_lo_/hi_/cell_blocks_/cell_mask_/cell_caret_` | 2 |
| 表结构 | `tables_`（投影产物） | `BlockSpec.cell_path` 与 `LayoutCell.first_block/block_count` 互为反向索引 | 2 |
| 控件区间 | `ControlSet`（TextPos） | `rev::ControlSpan`（块, 码点）、`FlowIndex::intervalOf`（FlowPos） | 3 套坐标 |

这四类"同一事实多份表示"才是缺陷温床：分叉不会崩，只表现为"光标偏一个字""括号画在别处"，
所以只能靠判据抓 —— 这也解释了 `engine_audit.cpp` 里为什么要写"两份记录互查"。

### 1.4 仍然存在的三个不唯一写入口

- `EditorEngine::controls()` 非 const 版本（`engine.h:1273`）对外交可写的 `ControlSet&`。
  它现在是投影产物，外面改一下，下一次 `rebuildFromTree` 就覆盖掉 —— 静默。树路应该只给 const。
- `ControlApi`（`doc/control_api.cpp`）直接往 `UndoStack` 提交，绕过 `EditHost::commitSteps`。
  当前只有 `validation.cpp` 的 `ChangeGate` 引用它，引擎路径不经过 —— 属于旧模型的遗留面。
- `setDocument(tree)` 整份换树会重建修订并丢掉撤销栈。它是装载入口，行为本身合理，但宿主侧
  "改一个字段就整份换树"的用法会让用户之前的撤销记录一起消失。

## 二、表格特例面

### 2.1 量

13 个文件、226 处机械命中，人工归并成**约 99 个独立分支点**：编辑与光标 31、排版 24、
投影 19、模型 18、绘制与审计 7。

先说做对的两处：`rev/flow.cpp` 全文 0 处表格判断（表、行、格在 `isContainer()` 里就是普通容器），
`control_spans.h` 与表格正交。问题不在这里，在于**同一件事的换算被写了 28 遍**，
其中只有"跨度 → 网格"（`doc/table.cpp` 的 `buildGridFromSpans`）是共享的。

| 换算 | 实现数 |
| --- | --- |
| 节点树 → 每行跨度序列 | 4 |
| 格 → 网格列 | 5 |
| 格 → 流区间 | 5 |
| 块 → 格（"最内层"） | 4 |

| 表宽求值与夹取 | 4 求值 / 3 夹取 |

### 2.2 跨页切片：几何单一来源，语义三处解释

切片的**几何**是干净的：`layout.cpp:1274-1478` 一次产出 `PlacedRow{page,y,h,cont_top,cont_bottom}`
并回填 `LineBox.cell_top/bottom`，之后绘制、命中、栅格、格线拖拽都读同一份。这一点不要动。

不一致的是**语义**：

- "这一片是不是切出来的"有两个真相：排版写 `cont_top/cont_bottom`，绘制在
  `engine_paint.cpp` 里又按"下一片的页号不同"自己推一遍 `seam_bottom`。
- 没有 `(page, y) → 格` 的反向查询。命中（`engine.cpp` 的格框优先）、表格栅格、格线命中
  三处各自重写同一个双层遍历，容差还分家（0.01 / 1.0 / 6.0 磅）。
- 格框有三份实现：行内轴 `cell_box_lo/hi`、块轴 `LineBox.cell_top/bottom`、
  查询期 `PlacedTable::cellBoxOnPage`。

### 2.3 固有的复杂度

合并格（续格在模型里不存在）、`cantSplit` / 标题行 / 行高三档 / 格内垂直对齐、表宽三态与
水平对齐、跨页补画边框、行高必须等整行排完才结算、表后间距（表不是段落）。这些换任何表示都还在，
`docs/文档模型设计.md` 第九节已经把理由写清楚了。

### 3.2 提示文字不进流位置是对的，但扩散了

`InlineObject::hint`（`layout.h:359-366`）的理由成立：提示占宽不占位，自成对象会毁掉
"流位置 ↔ 排版槽一一对应"。但它被实现成挂在起始边界上的旁路字段之后，"数位置"的每一处都必须
知道跳过它 —— 一个正确的决定扩散成四处硬编码 skip 加一处反向例外。

### 3.3 固有的复杂度

容器与原子并存、值投影（内容即值）、表单语义（只读 / 必填 / 结构锁 / 屏障 / Tab 目标）、
半覆盖控件只能拆壳复制、嵌套取最内层、段落标记可以落在控件内、设计态与呈现态两种可见性。

## 四、三个根因与收敛

真正的补丁都指向三处数据结构的表达力，不是三处"漏了判断"。

### 4.1 位置只有一维

块流是扁平的，表格是二维的。空格的流区间退化成点，`cell_blocks_` 的注释
（`caret.h:190-217`）已经写明"格身份不能是流区间"。于是整格选区要靠五个字段补一个矩形，
"块 → 格"要写四遍，删除要按块区间而不是流区间兜。

收敛：给 `LayoutCell` 加一个投影期算好的 `grid_col`（`layout.h:740` 现在只有 `row/cell/span`），
`cellAt(para)` 只留一个实现；整格选区收成一条 `CellRange` 记录。

### 4.2 格不是内容容器

格的内容只存在于块流里，`block_count == 0` 的格在流里没有身份。于是"新格必须带段落标记"
在三处手工构造，空格删除要特判，审计要数 `empty_cell`。

收敛：空段由模型层在"格"这个容器上生成，命令层不再补哨兵。

### 4.3 边界是流里的对象副本

同一个边界在模型层是节点、投影层是 `InlineObject`、排版层是占位簇，三者之间靠 `side`（int）、
`owner` 提示码、`control_hint` 布尔、`-2` 哨兵对位。宽度算三遍（`slotOf` / `hintAdvancePt` /
`engine_paint.cpp:1735`），位置数两遍。

收敛：一张 Slot 索引，`{flow, kind(Open/Close/Hint/Atom), owner, width}`。提示用
`flow_width = 0` 表达"占宽不占位"，skip 从四处变成一条可断言属性。

### 4.4 净效果与顺序

表格特例点 99 → 约 40，控件的边界解释 15 份算法 → 6 份。按"删掉的重复 ÷ 风险"排序：

1. `LayoutCell` 加 `grid_col`、`cellAt(para)` 单点。纯加法，零语义变更，用 `auditTablesDetail` 对拍。
2. 删三处死重复：两份括号计数合成一份；槽宽三处求值合成一处；`stepEditable` 与 `confineCaret` 合并。
3. Slot 表。收益最大，风险中等，先与现有对象表逐位对拍再切。
4. 格自带内容根 / `CellRange`。动 `Step` 语义与位置映射，放最后。

## 五、明确不要动的

- 跨页切片的几何（`PlacedRow` 单一来源）。只补一个共享谓词，别重写切片。
- 表格行列操作"改跨度 + 复用既有 Step"（`SetCellSpec`）。撤销与位置映射的零额外成本靠它。
- 两套投影的对拍：`compile.cpp` 现在只被 `engine_audit.cpp:689` 调用，看着像重复代码，
  它是唯一能证明 `rev::project` 没分叉的 oracle。等第 3、4 条落地再评估。

`tableStateJson` 104 行都还在门面里算。

### 6.2 已经完成的

- 拆文件（五片 → 八片）：`engine.cpp` / `_layout` / `_paint` / `_audit` / `_control` / `_image` /
  `_table` / `_diag`。这只改了成员函数定义在哪个 TU，不改类结构。
- 命令层 `EditCommand`（`edit_command.h`，3449 行）与位置解析 `CaretResolver`（`caret.h`，868 行）
  已经是独立的类，通过 `EditView` / `PositionView` 拿输入 —— 这是两次真正的拆类。
- 页缓存 `PageCache`（`page_cache.h`，243 行）：拥有页格、脏矩形与光栅签名三样状态，
  引擎只留一个 `pages_` 成员。这是渲染器那一刀的第一步。

### 6.3 为什么停在这里

4.7 写的是"顺序只能是先定形状、再切依赖"。当时挡着三格：绘制等阶段 4（行内原子）、
控件查询等阶段 5（表格）、门面等阶段 6（序列化）。前两个阶段已经落地（原子与表格都在），
所以挡路的只剩一条：**状态归属**。

`presentInternal` 直接读十来个私有成员（`page_cache_`、五份指纹账、行带临时量、`raster_sig_`、
`cfg_`、`layout_`、`images_`、`stats_`），`rasterIntoBitmap` 还读字体库与字形缓存。要把它变成
独立渲染器，得先回答"绘制需要哪些输入、哪些输出归谁"，而这份输入的形状现在**已经定了**
（`LayoutResult` + 页几何 + 光栅配置 + 资源表）。也就是说，第三格现在可以动了。

### 6.4 下一步三刀

**第一刀：渲染器（`PageRenderer`）。** 已经开始，分三步走：

第一步（**已落地**）：页位图缓存独立成 `src/core/engine/page_cache.{h,cpp}` 的 `PageCache`。
它拥有三样东西 —— 页格（页像素 + 页指纹 + 光栅签名 + 瞬态账）、脏矩形表、当前光栅签名，
提供 `fresh`（新鲜度）、`noteDirty` / `takeDirty` / `dirtyPages`（脏矩形合并与取走）、
`trim`（按离窗口远近淘汰）四组行为。`PageTransient` 与 `PageBitmap` 两个嵌套结构从
`EditorEngine` 里搬出去变成 `PageTransient` / `PageSlot`，`engine.h` 因此少了约 110 行。
引擎侧只剩 `pages_` 一个成员，原来"签名一变就清脏矩形"的三处手写块合并成一次
`pages_.setSignature(...)`。

第二步（未做）：四组指纹账（页 / 行 / 表格片段 / 浮动图，各存"这一轮"与"已画那一版"）
与行带临时量。它们要读 `LayoutResult` 与块流，所以得先定 `RenderInput` 的形状 —— 那是
这一步真正的工作量，不是搬字段。

第三步（未做）：`rasterIntoBitmap`（373 行）与 `rasterControlMarks` / `rasterWatermark` /
`drawAtomBox` 一族搬进渲染器。它们读字体库、资源表、水印、编辑模式，输入面比第二步宽，
所以排在第二步之后：输入结构不定就搬，等于把十来个私有成员换成十来个参数。

第二刀：**控件索引**。`control_spans.h` 已经是 FlowPos 的唯一面，把 `bracketSpanAt`、
`confineCaret`、`controlRects`、`innermostControlAtFlow` 的重复实现收到一个 `ControlIndex`
类里，`capability` 的两份屏障判定合成一份。

第三刀：**门面收薄**。前两刀之后，把 `hitTestPt`、`effectiveFormatAtJson`、`tableStateJson`
这类"在门面里算"的方法移进各自的实现类，公开方法只剩转发与参数夹取。

顺序不能颠倒：门面收薄依赖前两刀给出可转发的目标类。


### 6.5 本轮实际做的

两批，都不改行为，判据逐条跑过。

第一批（失效账收敛）：

## 七、判据

改这三处结构时，每条都要有正向与反向两半：

| 收敛项 | 正向 | 反向 |
| --- | --- | --- |
| `grid_col` | 格线拖拽仍只换两列、表宽不变 | 嵌套表与外层表的格号不串 |
| `cellAt(para)` | 整格选区铺满每一页 | 跨页行里没有行盒的格仍能选中 |
| Slot 表 | 括号占位、命中、光标侧别与现在逐位一致 | 提示文字不占流位置、点在提示上落光标 |
| 格自带内容根 | 新建表格的空格可编辑 | 删除不会因空格流区间退化而拒 |
| 渲染器 | 像素与现在逐字节相同（帧指纹） | 改一行只重画一条带，不是整页 |
