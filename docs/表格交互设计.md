# 表格交互：三份记录与五条不变量

这份文档回答三件事：表格相关的缺陷为什么总是同一批症状反复出现、它们的共同结构是什么、
以及判定与删除该按哪条边界切。写法与 `docs/控件与段落边界交错.md` 一致：先摆结构，
再摆不变量，最后摆判据。

---

## 一、三份记录

表格在引擎里同时存在三份记录，各自负责一段流程：

| 记录 | 谁产出 | 说什么 |
|---|---|---|
| 树 `NodeTree` | 模型层 | `Table` / `TableRow` / `TableCell`；段落标记是块边界，也属于它所在的格 |
| 块流 `BlockSpec` | 编译层 | 扁平的段序列；每段带 `cell_path`，说自己属于哪一格 |
| 格表 `LayoutTable` / `LayoutCell` | 编译层 | 每格 `first_block` 与 `block_count`；排版按格取内容，光标按块找格 |

流的坐标里还有第四类东西：**表格的结构位**（格尾、行尾这些位置）。它们不在任何一段内容里，
也不在任何一条可删区间里 —— 这一点决定了后面所有的删除路径。

三份记录两两对照，就是全部判据的来源。任何一份单独看都"自洽"，两份对不上就是损坏。

## 二、五条不变量

| 不变量 | 破坏之后的症状 |
|---|---|
| 每格至少一个块 | 那一格没有行盒，命中测试落不到它，光标点不进去 |
| 每格最后一个块有结束标记（文档最后一块除外） | 同上：格内容删空就整块消失 |
| 格的块区间两两不重叠；嵌套表的内层落在外层之上 | 两块被两格同时认领，选区与删除分叉 |
| 块的 `cell_path` 最内层一段指向认领它的那一格 | 光标的"当前格"与反白、删除的格不是同一个 |
| 段落合并只在同一格内发生 | 跨格合并会把前一格的结束标记删掉，格结构随之塌掉 |

最后一条是这几条里最容易被绕过的：合并段落看起来只是"删掉一枚段落标记"，但那枚标记在格尾
时它是**结构位**，不是可删内容。删掉它不会把两段并起来（两段在两个容器里），只会让前一格
少一个结束标记，于是上面第二、第三条连锁失效。

## 三、三条操作线

### 1. 落光标

命中的唯一入口是行盒（`LineBox` 的 `cell_lo_pt` / `cell_hi_pt` / `cell_top_pt` / `cell_bottom_pt`）。
点的位置落在格左内边距那一条带上时，命中测试回传这一格的首段段号（`hitTestPt` 的
`out_cell_para`），宿主据此发起"选整格"；点在字上仍是文字光标。回传段号而不是流区间，
是因为空格的内容长度为 0（见下一节）。

带的两头取**外框**与文字左沿。空格也只给左边这一条：整格都算边距带的话，点空格任何地方
都成了"选整格"，光标连放都放不进去（用户要的是"点一下落光标，拖或三击才选格"）。

### 2. 一格的身份是"它占的块区间"

单元格选区记的是**哪几格**，而"哪一格"只能用块区间回答（`CaretResolver::CellBlocks`：
`{first_block, count}`）。不能记流区间的理由只有一条，但它够致命：**空格的内容长度为 0**。
空段不占流位，所以它的流区间退化成一个点，而下一格的第一段起在同一个流位置上 ——
按流位置分不出"这是哪一格"。退化还有第二个后果：按流区间求交永远得到零宽，
空格连一条高亮都画不出来（表现就是"空单元格无法选区"）。

于是流包络退成摘要：它由块区间现算，只服务"选区报告、撤销快照、覆盖输入的范围"这几处，
渲染与删除都按块区间走。反白筛行盒用的也是块区间（`cellCoversPara`），合并成不相交的
几段之后一次二分就能答（外层格可以包住内层表的段，直接二分会漏）。

### 3. 反白铺的是格的外框，不是内容区

行盒上两组格几何：`cell_lo_pt / cell_hi_pt` 是**内容区**（命中测试要用它找"文字左沿之前
那一条"），`cell_box_lo_pt / cell_box_hi_pt` 是**外框**（格线本身，两侧各多一层内边距）。
反白用外框：按内容区铺会在左右各留一条内边距宽的缝，看起来就是"选区没铺满"。

### 4. 选区有两套，粒度是显式状态

文字选区只盖文字；单元格选区整格反白。两者不是粗细两档，而是两条独立操作线，
所以粒度记在 `CaretResolver::sel_cell_` 上，靠几何去猜必然出错（"把一段文字选到最后一个字"
与"选整格"的位置一模一样）。

单元格选区记的是**哪几格**（`cell_spans_`），不是一条流区间：矩形在流里是断的 ——
文档顺序逐行，从第二行第三列拖到第三行第五列，流区间会顺带把第三行前四列包进来，
表现就是"一跨行就整行"。包络（`cell_lo_` / `cell_hi_`）只是这些格的 min/max，
给撤销快照与"光标落在哪一端"这类只需要范围的地方用。

插入点钉在焦点那一格的末尾（`cell_caret_`），不跟鼠标在格内跑。

**锚点是用户的原值，谁都不许改写。** 拖选每动一步都靠 `rawSelection()` 判"两端还在不在
同一格"：不在同一格就长成矩形，拖回同一格就退回文字选区。所以 `setCellBlocks` 一个字都不写回
`sel_.anchor / sel_.focus`，它算出来的包络只是摘要。一旦把包络写回锚点，反向拖选就再也长不
回去 —— 锚点被搬到了最早那一格的起点上，"从下往上、从右往左"拖到一半整格反白就消失了。
单格吸附（单击边距带、三击）由调用方先 `setSelection({格首, 格末})` 再挂块区间，这是唯一
需要搬端点的地方，而它明确知道自己在选整格。

### 5. 删除有三条路

| 选区形态 | 走哪条 | 为什么 |
|---|---|---|
| 单元格选区（含矩形） | 逐格清空（空格跳过：它没有内容可删） | 格与格之间的结构位不能删；清空内容之后每格仍是空段落 |
| 选区完整跨过若干张表 | 整表删节点，表外空隙按流区间删 | 表是块级容器，没有"删一部分结构"的形态 |
| 不跨格的文字选区 | 按流区间删 | 区间的每一格都是可删内容 |
| 跨格但没跨过整表 | 拒绝 | 没有局部删结构的语义；宁可不动，也不要删掉半格 |

第二条同时解决了全选删除：全选的区间两头都落在块内容上，够不到表的节点边界，
所以"整表被跨过"的判据按块的区间算，不按表的节点区间算。判据的完整形式是
"表被区间盖住，**而且**区间两头真的在表外"（或区间就是整篇）—— 只被盖住不算跨过，
那种形态只在程序化设区间时出现，仍然拒绝。

**格内首尾的删除什么都不发生。** 光标在表格第一段的最前面按退格、最后一段的末尾按前删，
一次按键都不产生 —— 光标在表内，删的是内容；把格里的字删空之后再按一下也不该轮到整张表。
删表只能通过选区（把表整个选上，或用全选），这样"删结构"永远是一次显式动作而不是连按的后果。

## 四、判定表

| 动作 | 判定位置 | 落到哪条 |
|---|---|---|
| 单击格左内边距带 | 宿主判 `hit.cellPara` | 选整格（单格，按段号） |
| 单击空格里的任何位置 | 只有左边那条带算边距带 | 落光标（空格照样能进，整格只给带内那一条） |
| 三击 | 宿主连击计数，走命令 | 选整格（单格） |
| 拖选跨格 | 引擎 `syncCellSelection` | 单元格选区（矩形，正向反向同一套） |
| 拖回起手那一格 / 拖出表格 | 同上 | 退回文字选区 |
| 退格 / 前删（有选区） | `planEraseSelection` | 上表四条 |
| 退格（格首无选区） | `mergeParagraphInto` 的前置判据 | 同格才并，跨格拒绝（表内首段因此什么都不发生） |
| 前删（格尾无选区） | 同上 | 同上 |
| 全选 | `selectAll` | 全部整格反白；删除走"整表删 + 区间删" |

## 五、判据

| 判据 | 位置 | 盯的是 |
|---|---|---|
| 表格结构自审（六类计数） | `EditorEngine::auditTables` | 上面五条不变量 |
| 矩形选区与跨格合并 | `edit_test` 的 `[49] [50]` | 反白的格集合、拒绝合并后结构不变 |
| 空格可选中、反白铺满外框 | `edit_test` 的 `[52]` + `out/_emptycell.mjs` | 空格的三条手势、反白宽高、点中间落光标、删除不动结构 |
| 格内首尾不删表 | `edit_test` 的 `[46]` | 删空之后再按退格，表还在 |
| 全选删除与格内文字选区 | `edit_test` 的 `[51]` | 整表删、撤销、拒绝时一格不少 |
| 拖选与三击（浏览器） | `out/_tabledrag.mjs` | 宿主那一路的指针事件与落点、正向与反向 |
| 边距带与三击（原生） | `edit_test` 的 `[47] [48]` | 命中侧回传的格区间 |
| 行列操作、合并拆分、三层记录、落点归属 | `edit_test` 的 `[85]` | 上面那张表逐条（含被拒时不动、一步撤销、幂等） |
| 右键菜单（浏览器） | `menu.spec` | 落点判出的菜单、禁用态、动作真的落到文档、属性面板一进一出 |

**判据必须走"逐步拖"。** 按下只落一次锚点，之后每一步只搬焦点（`setCaretAtSideLine` 一次 +
`setFocusAtSideLine` 多次）。一次 `setCaret` 配一次 `setFocus` 的写法每次都把锚点重设一遍，
会把"实现偷偷改写了锚点"这类错整段盖住 —— 第一版判据就是这样，注入旧行为之后仍然全绿。
浏览器侧同理：`mousePressed` 一次 + 六段 `mouseMoved` + `mouseReleased`。

结构自审与排版自审是两把尺子，不能互相替代：排版自审比的是"增量排版与全量排版"，
两边吃同一份 `blocks_` 与 `tables_`，结构坏了照样全绿（一格连一个块都不剩时，
两边都排不出那一格的行盒，逐字段比对完全一致）。

## 五之二、行列操作与属性（命令层的口径）

结构操作不是新的步骤类型：插一行是"插一棵行子树"，删一行是"上面跨进来的格子先缩短 + 删这
一行"，插一列是"跨线的格子加宽 + 其余行各插一新格"。所以撤销、位置映射与不变量检查全部复用
现成那条路，一次动作 = 一批步骤 = 一步撤销。

| 动作 | 造的步骤 | 拒绝的条件 |
|---|---|---|
| 插行 | 一行 `InsertNode`（照参照行的跨度序列造） | 光标不在表里、模式不是文档 |
| 删行 | 若干 `SetCellSpec`（跨进来的纵向合并缩短）+ 一条 `RemoveNode` | 只剩一行、行内有 `row_span > 1`、模式不对 |
| 插列 | 每行一条 `InsertNode` + 跨线格子的 `SetCellSpec` | 光标不在表里、模式不对 |
| 删列 | `SetCellSpec`（变窄）+ `RemoveNode`（窄到 0 的格子） | 只剩一列、模式不对 |
| 合并 | 锚格 `SetCellSpec`（跨度 = 包络）+ 其余格子 `RemoveNode` | 少于两格、没铺满矩形、要并的格子有内容 |
| 拆分 | 锚格 `SetCellSpec`（回到 1x1）+ 补格子的 `InsertNode` | 这一格本来就没合并 |

三条边界值得单独说，因为它们都是"宁可拒绝，也不替用户决定"：

**合并只接受空格子。** 合并会删掉除锚点以外的格子，有内容就是丢数据。要合并有内容的格子，
先清空或先搬走 —— 那是另一个语义（Word 的做法是把内容接起来），要落地得先有"块搬运"这条
路径，现在没有。

**新行的跨度照参照行。** 参照行里有一格跨三列，新行也是那一格跨三列。否则新行与网格对不上，
而"每行跨度之和相等"那条不变量要到下一次检查才报出来。

**改记录一律整份 `CellSpec` 一起走。** 只写跨度的写法会把格内垂直对齐静默清成顶端：任何一次
行列操作都会经过那几个步骤，于是"设了居中、插一列之后又变回顶端"。判据钉的就是这一条
（`edit_test` 第 85 节：设居中 → 插列 → 还是居中）。

三层记录的入口分开（`setTableCell` / `setTableRow` / `setTable`），但现状是一次读全的
（`tableState`）：属性面板上这三层本来就是同一张表单，分三次问会拿到三个不同时刻的状态。

## 六、已知未覆盖

跨格的部分文字选区（起点与终点都在格内，而又跨了两格）不删：没有"局部删结构"的语义。
宿主拖选会产生单元格选区，只有程序化设区间才会碰到这一形态。

整格选区的撤销恢复的是文字选区：撤销快照只记一条流区间，逐格信息不进快照。

合并格（跨度大于一）在矩形里按"盖住的整块"算：跨进它的行或列都算选到它，
不做"矩形必须对齐网格"的裁剪。

表格后紧挨的空段落仍占整行，段落标记画在行首而不是表格右侧：那是排版层的行盒起点问题，
与选区、编辑无关。
