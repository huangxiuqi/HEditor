# 阶段 4 后续项：分页模型扩展

## 背景

阶段 4 的产品范围只覆盖单一全局页度量下的正文排版。以下能力被显式排除：

- 按节页度量；
- 页眉页脚投影与排版；
- 域元素排版。

它们不是“少接一个字段”，而是要求分页模型从“整篇一套页度量”改成“每一页有自己的几何与内容流”。当前 `LayoutResult`、`PageScene`、`PageCache` 都以全局 `PageMetrics` 为输入，所以不能在现有结构上静默补齐。

## 需要先改的基础设施

1. `LayoutResult` 带每页页度量：
   - 页宽、页高、页边距；
   - 页与节/段的对应关系；
   - 页缓存键必须包含页度量，否则换节后旧页位图会被误复用。
2. `PageScene` / `PageCache` 按页取度量：
   - 页位图尺寸不再来自全局 `EngineConfig`；
   - 页范围、脏矩形、滚动几何都要按页尺寸计算。
3. 块流带节身份：
   - 每个块能回答“属于第几节”；
   - 多节连续/分页行为与页度量切换在同一处结算。

## 能力落地顺序

1. 每页页度量贯穿 `LayoutResult` / `PageScene` / `PageCache`。
2. 多节页度量：按节生成页，节首切换页尺寸与页边距。
3. 页眉页脚：按页取节记录的页眉页脚内容，独立排版到页边距区域。
4. 域元素：在页数稳定后求值页码/总页数，回填并允许一次迭代收敛。

## 验收判据

- 多节：第二节改成横向 A4 后，页尺寸、页边距与页缓存都随节变化；保存/打开往返不丢节记录。
- 页眉页脚：每页页眉页脚位置按该页边距计算；首页/奇数页/偶数页变体各取自己的内容；页眉页脚不进入正文流。
- 域：页码与总页数在排版后求值；重复求值不产生编辑步骤；页数变化后最多迭代一次收敛。
- 反向：删除某一节的页度量或页眉页脚内容，往返与渲染都必须失败，不能静默退回全局页度量。

## 风险

- 页缓存键漏掉页度量：换节后旧页位图复用，画面看似正常但内容错位。
- 页眉页脚按错误页边距排版：分页位置与页内坐标同时偏移，很难从文本判据看出来。
- 域求值写回修订：会产生编辑步骤和撤销栈污染，必须只写缓存值。
