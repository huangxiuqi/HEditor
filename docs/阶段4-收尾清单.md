# 阶段 4 范围与收尾清单

## 范围决定

本阶段按“产品路径单一模型”收口，不按原方案 7.2 的全部前置条件收口。

原方案把多节页度量、页眉页脚、域排版、资源表列进阶段 4 前置条件，是因为它们当时还由旧树模型承担。产品路径切到 `doc::Doc` 之后，这些能力没有进入产品必需范围；在单一全局 `PageMetrics` 的排版模型上硬补，会把页尺寸、页眉页脚位置和域求值做成错误但能编译的状态。因此本阶段对它们做显式拒绝，后续需要时单独立项；实现前提与验收判据见 `docs/阶段4-后续项-分页模型扩展.md`。

## 已交付

- 产品路径只保留 `doc::Doc`；`NodeTree`、`fromTree`、树编译、树事务、树适配器已删除。
- 测试与演示直接构造修订；wasm 宿主不再保留块流底稿 `g_blocks` / `syncBlocksFromEngine`。
- `compileDocument` 已删除；审计改为对投影的全量重算。
- 命名样式表随文档保存，引擎 `saveDocument` / `loadDocument` 接入。
- 二进制图片资源随文档保存：`res` 表、base64 像素、`ImageStore::list()` / `putPremultiplied()`。
- 孩子表按 64 分块、不可变、可共享；路径复制只替换受影响块；父节点哈希与段落数按块聚合。
- `RunPayload::text` 与 `BlockSpec::cp_text` 使用共享缓冲区切片，投影单个 run 零拷贝。
- 性能项判据与说明见 `docs/阶段4-性能项-2026-10-28.md`。

## 不在本阶段范围的能力

这些形状可以表示、可以序列化，但排版层没有实现；打开时由 `doc::checkSupportedLayout` 显式拒绝，不做静默降级：

| 能力 | 当前状态 | 不做的原因 | 后续条件 |
| --- | --- | --- | --- |
| 按节页度量 | `SectionSpec` 可存可序列化；打开时拒绝非默认节页度量 | 布局、页场景与页缓存都按单一全局 `PageMetrics` 组织 | 先把每页页度量贯穿 `LayoutResult` / `PageScene` / `PageCache` |
| 页眉页脚 | 节记录保存页眉页脚引用；打开时拒绝有内容的页眉页脚 | 没有独立的页内容流、按页排版与页边距处理 | 在按页页度量之后补页眉页脚排版 |
| 域元素 | `FieldSpec` 可存可序列化；打开时拒绝 | 页码/总页数需要排版后求值并回填，再迭代排版 | 先有按页排版结果，再做域求值迭代 |

## 显式拒绝行为

`doc::checkSupportedLayout` 对以下情况返回失败原因，`EditorEngine::loadDocument` 在安装文档前拒绝，现场不变：

- 页眉页脚内容或非默认页眉页脚距离/链接设置；
- 非默认按节页度量；
- 域元素。

保存端仍保留这些形状，不做有损删除；打开端拒绝是范围声明，不是解析失败。
