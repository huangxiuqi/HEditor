# 位置与坐标：一份坐标、一个类型、两个换算

定稿日期 2026-10-29。范围是"位置"这一族：文档里的位置、引擎内的位置、对外 API 的位置、
光标与选区的端点。目标是**一套坐标**，不是一套接口形状。

本文只定契约与验收，不含实施步骤的排期；落地顺序见末节。

## 结论

- 位置的**文档坐标**只有一个：`FlowPos`（流位置）。它不是字符序号，是结构展开后的元素序号。
- 位置的**对外类型**只有一个：`Position{FlowPos flow; int affinity}`。
- 选区的对外类型只有一个：`TextSelection{Position anchor, focus}`。
- 换算只有两个函数：`flowAt`（地址到位置）与 `textPosOf`（位置到地址）。
- `affinity` 是本地视图态：只在光标/选区/命中这一层存在，不进文档、不进持久化、不做跨端。
- `side`（槽序号）不是坐标，是"地址 → 位置"换算内部的一位；只允许出现在三个函数里，
  不进光标状态、选区、撤销记录与任何载荷（见第四节）。

判据（改完之后全仓应成立）：

```
grep -rn affinity src/core/doc        # 0 处
grep -rn 'Position{' src              # 3 处：光标、命中、wasm 入口，此外 0
grep -rn 'struct Range' src           # 0 处（类型已删）
```

## 一、分层与归属

| 层 | 坐标 | 带 affinity | 说明 |
| --- | --- | --- | --- |
| 文档（树） | `Pos{container, offset}` | 否 | 子槽序号 / 文本节点内码点下标 |
| 展开流 | `FlowPos`（int） | 否 | **引擎内的真坐标**，跨段连续，`block_flow[i]` 是块起点 |
| 地址（对外输入） | `TextPos{para, cp}` | 否 | 文本投影，丢维（见第二节） |
| 光标 / 选区端点 | `Position{flow, affinity}` | **是** | 唯一带 affinity 的地方 |
| 排版 | `offset -> 视觉行`（多值） | 否 | `linesOfBlock` / `linesOnPage` 只提供映射，不做决策 |
| 渲染 | `Position -> (行, x)` | 消费 | `findLineFor` + `offsetAtSide` |

`flow` 与 `affinity` 的归属不同，这一条决定了后面所有取舍：

| 半 | 归属 | 可持久化 | 可跨端 | 失效条件 |
| --- | --- | --- | --- | --- |
| `flow` | 文档坐标 | 可（配合 `Step` 的位置映射） | 理论可 | 编辑后按 map 重映射 |
| `affinity` | 本地视图态 | **不可** | **不可** | 每次重排按位置重算；插入删除后归一化 |

跨端不可传的理由是硬的：不同窗口宽度下软换行点不同，同一个 `affinity` 在另一端指向另一行。

## 二、真坐标为什么是流位置，不是文本偏移

文本偏移是 `flow` 的一个投影，且**丢维**。一块占几位由投影逐位累加得出
（`doc/project.cpp:423` 进控件、`:438` 出控件、`:446/:448` 节的两端），不是"字符个数"：

| 内容 | 占几位 |
| --- | --- |
| 每个码点 | 1 |
| 每个控件边界（进、出各一） | 1 各 |
| 段落标记 | 1 |
| 节的两端 | 1 各 |
| 表格：出格 + 进格 | 2 |
| 表格末尾：出格 + 出行 + 出表 | 3 |

后果就是 `][` 这种共享边界：同一码点偏移上有三个插入点（`]` 前、两括号之间、`[` 后），
文本偏移只给一个。`side` 就是被丢掉的那一维的余数 —— `rel = cp + before + side`
（`engine/caret.cpp:102`）。只要对外坐标还是"段 + 码点偏移"，这一维就必须在；把它换成
`flow`，它自动消失（每个边界各占一位）。

所以编辑命令一律走流位置：`insertTextUtf8(para, offset)` 是唯一"按地址写"的入口，进引擎
立刻换成流位置。若按"文本偏移是唯一真坐标"改，控件内外就没有区别，等于删掉控件。

## 三、类型冻结

- `Position{FlowPos flow; int affinity}`：唯一位置类型。`affinity` 语义：`0` 贴上一行、
  `1` 贴下一行（`findLineFor` 只认 `> 0`，`caret.cpp:655`）；传 `-1` 表示"让引擎按位置推"，
  它是入口参数，不落进状态 —— 落进 `sel_.focus.affinity` 的永远只有 0 与 1。
- `TextSelection{Position anchor, focus}`：唯一选区类型。
- `Range{FlowPos, FlowPos}`（`doc/range.h:13`）**删除**。现在对外 `selection()` 把它当返回值
  （`caret.h:229-237`），撤销记录也收它（`engine.h:2884`），两处都把 `affinity` 丢了。
  撤销那一处**不修**：撤销记录在 doc 层（`SelectionSnapshot` 两个 int），而 affinity 是视图态，
  按本契约不许进 doc 层 —— 撤销后行别由 `lineAffinityAtFlow` 重推，折行处可能落到上一行，
  这是"affinity 不进持久化面"的必然代价，不是缺陷。需要有序区间的地方给 `lo()` / `hi()`。
- `TextPos{para, offset}` **不是位置类型，是地址**。它可以出现在命令入参与诊断输出里，但
  **不许成为状态**：不得作为结构体成员、不得跨入口存留（地址过期不会报错，只会静默指到别处）。
  全仓唯一的例外是 `ControlRange`（`doc/control.h:57`）：它每次投影整份重建
  （`exportControls` 先 `clear()` 再填），过期问题由重建承担。那条注释里"与光标同一把尺子"
  的说法要一并改 —— 光标用的是流位置。

## 四、换算冻结

| 函数 | 方向 | 用途 |
| --- | --- | --- |
| `flowAt(para, offset, field?) -> Position` | 地址 → 位置 | 唯一"猜侧别"处；默认归属 = `innermostAt(include_end=true)`，没有控件时取 `closes` |
| `textPosOf(Position) -> TextPos` | 位置 → 地址 | 只给诊断与显示，不参与编辑 |

禁令：其他地方不许再拼 `cp + before + side`。今天散在三处（`caret.cpp:125` 的
`textSpanAt`、`caret.cpp:1000` 的 `span_of`、`engine_layout.cpp:87` 的光标夹取），
三处都改为读 `block_flow_span` 或调 `flowAt`。

### 槽序号（今天的 `side`）为什么还留着

它是"同一码点偏移上第几个槽"的序号，是文本地址丢掉的那一位：`rel = cp + before + 槽序号`。
只要地址是"段 + 码点偏移"，这一位就必须在某处被补回来 —— 要么在地址里带一个字段（那就是给它
改个名字继续存在），要么在换算处按默认归属猜（`flowAt` 的职责）。取消地址语法才能让它彻底消失，
但那样外部作者无法说"第 3 段第 5 字"。

所以它不消失，但被压缩到三个函数的局部变量里，别处一律不出现：

| 位置 | 作用 |
| --- | --- |
| `flowAt` 内部 | `(cp, 槽序号)` → `rel`，唯一"猜"的地方 |
| `LineBox::offsetAtSide`（`layout.h:1662`） | `rel` 拆回 `(cp, 槽序号)` 再取行内 x |
| `hitTestInLine`（`caret.cpp:946`） | 行内 x → `(cp, 槽序号)` |

配套改名（S3 的机械改动，纯重命名，无行为变化）：`side` → `slot`、`bracketCountAt` →
`slotCountAt`、`kInlineOffsetOuter` → `kSlotOutside`、`sideFromHint` → `slotOfField`。
叫"侧别"会让人以为它是能对外传的语义量，叫"第几个槽"就不会有人想把它塞进协议。

另一条降维的路值得记住：填表这个真实场景的天然地址是**控件**（`focusControl`、控件下标），
不是文本偏移。按控件定位的路径完全不需要槽序号；需要它的只有"按任意文本偏移写"。

## 五、公开面冻结

写入口三个：

| 方法 | 吸收 | 不变量（各不相同，不许合并） |
| --- | --- | --- |
| `setCaretPosition(flow, affinity)` | setCaretAtSide / setCaretAtSideLine 那条路 | 清选区、**夹**屏障、一次呈现 |
| `extendTo(flow, affinity)` | setFocusAtSide / setFocusAtSideLine | 只搬移动的那一端、anchor 不动、**不夹**屏障（`applyDragAnchor`） |
| `select(anchor, focus, affinity)` | setSelection(flow, flow)、setSelectionPositions | 两端给定即生效；行别只取焦点端 |

`select` 的第三个数是焦点端的行别。anchor 的行别不进引擎 —— 反白的每一段按它自己的流位置
投影，画哪一行与端点无关；焦点端不同，折行处它与 anchor 共用同一个流位置，少了行别末端会
停在上一行。

命名：定位入口留 `Position` 后缀，因为 wasm 那一层的入参是两个整数，`setCaretAt` 与
`setCaretPosition` 单看签名分不出哪个收位置、哪个收地址；拖选叫 `extendTo`，因为 `focus`
在 Web 语境里会被读成 `element.focus()`，而它动的是选区的另一端。地址入口一律带
`para` / `offset`，一眼可分。

读入口两个：`position() -> Position`（吸收 `caretPositionJson` 与 `caretReport` 的位置字段）、
`selection() -> TextSelection`（吸收 `selectionPositions()` 与 `selectionReport` 的位置部分）。
这两个名字是目标形态，今天导出的仍是 `caretPositionJson` / `selectionReport`（读的是同一份
东西，只是一个回扁平键、一个回整份报告）；改名不影响正确性，所以没跟这一轮一起动。

几何入口一个：`hitTest(x, y, clamp)`。它一次把位置、格、图片、能否起拖四件事一起答回来，
`clamp` 是拖选那条路要的（指针拖出画布仍要能选）。只回位置的那条薄版已经删掉 ——
回的是子集，留着就是给同一个几何开两个出口。

它的载荷里位置只有一个键：`position: { flow, affinity }`。地址投影（`para` / `offset` /
`side` / `line`）已经从命中结果里退场 —— 那四件套是同一个位置的低维写法，宿主搬落点时
解了又拼，中间隔着一次文本投影。要读数就给 `position` 过一次 `textPosOf`。

诊断入口两个：`flowAt`（地址 → 位置）、`textPosOf`（位置 → 地址）。两条都按此名导出，
diag 面也各有一份 —— 判据若拿 (段, 偏移) 当位置判等，那正是本契约要证伪的写法，
所以必须有一条能换回来的诊断通道。

地址入口一个：`setCaretAt(para, offset, field?, side?, line?)`。三个修饰的缺省值就是"什么都
没给"：那时按程序化定位落，**不夹**屏障（属性面板要能把光标停进只读字段）；给了控件下标
或槽序号就与点击同一档，夹屏障。判据与自动化用它摆位 —— 控件下标比文本偏移稳（文档改短
也不失配）。它不收方向、不收几何，只收地址，所以属于"命令参数"而不属于坐标系。

已删（不得再出现）：`setCaretAtSide`、`setFocusAtSide`、`setFocusAtSideLine`、
`setCaret(para, offset)`、`setCaretAtSideLine`、`setSelection(flow, flow)`、
`hitTest` 的 `para` / `offset` / `side` / `line` 四个键、`flowIndexAt`（改成 `flowAt`）、
`flowTextPosJson`（改成 `textPosOf`）。
还要删的：`setSelectionPositions`、`selectionPositions`、`Range`。

留在 C++ 侧不进公开面的：`setCaretAtPosition`（两条导出的唯一实现）、`setCaretAtSide*`、
`setFocusAtSide*`、`setCaret(para, offset)` 一族。判据用的是它们 —— 它们收的是地址，
正好当"地址 → 位置"那一半的对照物。

不在本契约范围的：`moveCaret`、`caretToLineStart/End/DocStart/DocEnd`、`moveCaretVertical`、
`moveSelectionTo`、`selectWordAt`、`selectParaAt`、`selectCellAtPara`、`tabCaret`。它们是
**命令**（收方向或几何，不是收位置），保留。

## 六、三条语义写死

- `affinity` 只描述"画在哪一行"，不改位置。只存在于 `Position` 里，不进 `Range`、`Step`、
  持久化面与协作协议。非断点处必须为 `0`（归一化）：`lineAffinityAtFlow`（`caret.cpp:356`）
  已经这么做。
- 槽序号（`side`）只存在于第四节列的三个函数里；公开类型、载荷、光标状态、撤销记录一概不出现。
  命中结果改吐 `position` 之后，它连读数都不在载荷里 —— 落点身份由 flow 唯一确定
  （`rel` 已经把"第几枚括号之后"算进去了），要某一段边界上的具体一槽，给 flow 就够。
- 地址只能用来**显示**，不能用来**判等**。`][` 相邻两处插入点的 `(段, cp)` 完全相同，
  拿它当"光标变没变"的键就会把挪一格判成没动。宿主的键（`host/dom.ts`）现在取
  `段:偏移:侧别:行别:页:可见`，选区键取两端的流位置；状态载荷为此带了 `caretSide`、
  `caretLineAff`、`selectionAnchor`、`selectionFocus`。
- 三个写入口的屏障规则如上表，写在同一处；改一个必须同时看另外两个。

## 七、闸

四条闸里三条已落地，一条明确不做。

1. **结构闸（已落地）**：`scripts/check_position_surface.py`，在 `npm run check` 里。它比对
   `wasm_main.cpp` 的注册清单与 `api.ts` 的命令表，位置类名字（含 caret / position / select /
   extend / hit）必须与脚本里的白名单分毫不差 —— 多一个少一个都红。同时断言文档层没有
   `affinity`。名字按词判会漏掉"叫别的名字却收位置"的新入口，那类要在评审里拦。
2. **载荷闸（已落地）**：`gen_payloads.py --check` 锁键集，载荷增删字段必须重生成并过闸。
3. **行为闸（已落地）**：`feature_test` 第 5 节。两条口径：
   一是任意流位置落一次、读回、再落一次必须收敛（全篇扫描，表与格的空隙都在里面）；
   二是控件边界上逐个位置比对地址入口与位置入口，分歧必须为 0。
4. **类型闸（不做）**：原计划删 `Range`，让"两个裸 flow 当位置用"编译不过。实测不值：
   `Range` 是文档层的流区间（`doc/range.h`），撤销记录另有一个同形的 `SelectionSnapshot`
   （`doc/session.h:120`）—— 删掉 `Range` 只会立刻长出第四个同形物，概念不减反增。
   位置的重合靠结构闸与行为闸拦，不靠类型系统。

## 八、落地顺序

从"补无损"到"删概念"分三步，每步都能单独回滚。

- **S1 补无损、不改名（已落地）**：`hitTest` 载荷新增 `flow`（与已有的 `line` 合起来就是
  Position，宿主搬运落点不再需要四件套）；`setCaretPosition` 直落流位置，删掉
  `flowToTextPos` + `sideForFlow` 的两次换算，并补上"夹屏障 + 记待定拖选锚"（此前程序化落点
  与点击对同一处给出两个答案）。
  判据在 `feature_test` 第 5 节：普通位置、折行处两个行别、格边界两位归一化。
- **S2 把宿主搬到位置入口（已落地）**：宿主的落点与拖选改走 `setCaretPosition` /
  `extendTo`，命中到落点的中转类型 `CaretAction` 只剩 `{flow, affinity}`
  （`input/keymap.ts`），`hitToAction` 不再从段号与偏移拼位置。
  引擎侧两条导出的唯一实现是 `EditorEngine::setCaretAtPosition`：定位夹屏障并记下待定的
  拖选锚，扩展不夹但要重算整格粒度，括号计划变了再按新槽宽落一次（Position 那一路此前
  少了这三步，只够裸文本，跨格拖选与控件边界都会偏）。判据是 `feature_test` 第 5 节新增的
  两条差分：控件边界上逐个位置比对旧入口（段, 偏移, 侧别）与新入口（Position），
  定位 21 个位置、拖选 9 个位置，分歧必须为 0。
  这一步没动的：外部 API 的 `setCaret(pos, {side})` 仍走地址入口（`setCaretAtSideLine`）；
  宿主的变化键仍用段号与偏移判等（见第六节最后一条）。
- **S3 删名、上闸（已落地）**：
  一条地址入口收掉了三个旧名字 —— `setCaret`、`setCaretAtSideLine`、带控件下标的 `setCaretAt`
  合并成 `setCaretAt(para, offset, field, side, line, plain)`；`plain` 非零才是"只挪位置"，
  不夹屏障。这一条是合并的关键：此前 `setCaret` 不夹、`setCaretAt*` 夹，混成一条命令时
  必须先把这个区别显式化，否则属性面板再也停不进只读字段。
  另删 `setCaretAtSide`、`setFocusAtSide`、`setFocusAtSideLine`（全仓无调用方）与
  `hitTestPosition` 那条读命令（`hitTest` 的薄版，回的是子集）。
  `setSelection(flow, flow)` 换成 `select(anchor, focus, affinity)`：焦点端带行别。
  宿主的变化键改成"段:偏移:侧别:行别:页:可见"，选区键改用两端流位置。
  命中载荷的位置收成一个 `position` 键（`para` / `offset` / `side` / `line` 四个键退场），
  两个换算按契约名导出：`flowAt` / `textPosOf`。
  闸落地三条（结构闸 / 载荷闸 / 行为闸），类型闸按第七节第 4 条明确不做。

每步独立可绿，验收口径是第六节的 `grep` 与第七节的行为闸，不是"用例全绿"——用例全绿只
证明行为没变，不证明概念少了。

## 九、明确不做

| 事项 | 理由 |
| --- | --- |
| 把 `affinity` 写进文档、持久化、协作协议 | 它是视图态：换窗口宽度就失效，写进去等于把"算不准"固化成"对不上" |
| 用"行号"或"行首/行尾标记"代替 `affinity` | 行号重排即失效，±1 不会；标记法要么改文档（排版依赖文档），要么只是给同一个概念换名字 |
| 把 `(段, 码点偏移)` 升格成位置类型 | 它丢维；一旦升格，`][`、格边界、表尾的位置就必须另找地方存 |
| 把三个写入口并成一个带 mode 的方法 | 三个意图的不变量不同（清不清选区、夹不夹屏障、算不算一步撤销），合并只是把分叉搬进函数体 |
| 在模型里存几何（为了"反向映射更准"） | 反向精度由正向是否单射决定；存几何只会把单射关系固化成两份真相 |

## 现状核对（本文所据的事实，供复核）

- `Position` 的构造只有三处：`caret.cpp:386`、`engine.cpp:2361`、`wasm_main.cpp:817`。
- `src/core/doc/` 对 `TextSelection` 与 `affinity` 的引用为 0：`Position` 目前只是光标坐标。
