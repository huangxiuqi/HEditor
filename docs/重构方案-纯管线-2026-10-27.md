## 一、目标与非目标

### 1.1 目标

把现在这条“不可变修订 + 可变引擎 + 扁平排版快照 + 手写失效账”的混合管线，改成一条
单向、可缓存、可证伪的纯管线：

```text
Doc（不可变修订）
  → Projection（扁平 IR + 结构索引 + 文本切片）
  → BlockLayout（块局部、与页无关的纯函数）
  → FragmentIndex（分页与跨页片段）
  → PageScene（页级绘制指令表）
  → RasterCache + Overlay
```

三条结构目标：

- **唯一真相**：文档只有 `doc::Doc`；位置只有 `Position`；一页画什么只有 `PageScene`。
- **纯函数 + 内容寻址**：投影、块排版、页场景都是输入到输出的函数；缓存键是内容哈希，
  不是“脏段起点/终点/是否全量”这类手工状态。
- **失效结构化**：改一个字只重算一个块、只重排受影响的页、只重画变化的绘制项；
  不再靠四组指纹去猜“哪里变了”。

### 1.2 非目标

- 不重写整形、断行、书写模式与字体回退。HarfBuzz 调用面、贪心断行、横竖排共用、
  Skia 的 hinting/亚像素/灰度抗锯齿，原样保留。
- 不引入第二个光栅后端，不做 GPU 合成，不做多线程光栅。
- 不把模型换成 ProseMirror/Lexical 那类 JS 模型。模型不是难点，排版与判据才是。
- 不做协同编辑。位置设计只保留扩展位，不实现 OT/CRDT。
- 不在本方案里扩大表格功能（标题行重复、表格样式系统、动态行模板仍另行处理）。

### 1.3 成功判据

本方案不按“写完能跑”验收，按四类可证伪的判据验收：

| 类别 | 判据 |
| --- | --- |
| 像素 | `auditPage` / `auditFrame` 逐字节为 0；相同场景第二次呈现 0 页重光栅 |
| 排版 | `auditLayout` 全量对增量逐字段为 0；`LayoutDigest` A/B/C 在不应改行为的阶段逐位不变 |
| 结构 | 重算块数、重排行数、重光栅页数、场景项数、分配次数，全部用计数器而不是耗时阈值 |
| 行为 | 边界、空控件、跨段控件、空单元格、嵌套控件、跨页表格、浮动图、竖排各有正向与反向用例 |

每条判据都必须能红。只证明“新实现与旧实现一致”不够；还要在参照侧注入一处错误，
证明判据看得见它。

## 二、现状：哪些已经成立，哪些还缺

### 2.1 已经成立的部分

这些是资产，重写时一行都不要改逻辑：

- **不可变修订 + 撤销取旧值**：`doc::Doc` 是唯一写侧真相，`doc::Session` 的历史是一串旧修订。
- **投影作为唯一接缝**：`BlockSpec` 是排版输入，`doc::project` 一次遍历产出块、控件跨度、
  表格与内容哈希。
- **块内容哈希 + 损伤区间**：两份修订一比就知道哪几块要重排，不需要谁上报“我改了什么”。
- **段落是流里的范围，控件是跨度**：模型与编译产物同构，行内字段与一栏多段是同一机制。
- **长度的整数/有理数表示**：EMU + 分数，落盘不经过浮点。
- **整形、断行、书写模式、Skia 调用面**：这些是像素一致性的根。
- **判据文化**：`auditLayout`、`auditFrame`、`auditPage`、`LayoutDigest`、故障注入。

### 2.2 六个结构性问题

| # | 问题 | 现在的表现 | 根因 |
| --- | --- | --- | --- |
| P1 | 两套文档模型、两套编辑原语、两套序列化 | `NodeTree` 与 `doc::Doc` 并存；`rev.cpp` 的六个原语与 `rev/steps.cpp` 是两份实现；`compileDocument` 与 `doc::project` 两条产出路 | 迁移停在“引擎持修订、宿主仍造树” |
| P2 | 位置没有贯穿 | 步骤与光标内部用 `FlowPos`，宿主用 `TextPos`，控件用 `TextPos`，排版用 `(cp, side)` | 边界在 API 边界被压扁，再用 `defaultSideAt` 猜回来 |
| P3 | 表格/控件摊平后失去层级 | 格内容靠 `cell_path` 与 `first_block` 互查；空格的 `block_count == 0` 没有身份；控件嵌套靠区间包含 | 投影把树摊平，消费者各自重建结构 |
| P4 | 排版是整篇 fold | `layoutDocumentRangeWithTables` 约 1700 行；`ReflowState` 只有三个标量；表格/浮动图退化整篇 | 断行、分页、落位、表格结算在一个循环里 |
| P5 | 渲染靠四组手写指纹 | 页/行/表/浮动图各一组 `new/prev`；表格/浮动图一变就整页回退 | 绘制输入没有被枚举成一份可比较的值 |
| P6 | 引擎门面拥有太多 | 约 139 个公开方法、60 个上下私有成员；两套历史；宿主手写命令表与镜像 | 状态所有权没有切开 |

下面只展开与方案直接相关的四项：P2、P3、P4、P5。P1 与 P6 放在阶段 4、5。

P1 还有一层数据结构代价：`doc::Node` 的路径复制在每一层复制整个孩子表，`makeNode` 对全部
孩子重算 `paras`、`paras_display` 与哈希。2000 块的节上，改一个字就是 O(块数) 的复制与
重算，而不是 O(树高)。这是阶段 4 要换分块持久向量的原因。

P6 的一个具体形状：`commitSteps` 每次提交都记选区，而 `Session` 按 `MergeRun` 合并撤销步。
拖拽合并 N 帧之后，撤销只把选区历史减一格，恢复的是最后一帧之前的选区，而不是整个拖拽
之前。两套历史必须收进同一份 `Snapshot`。

### 2.3 位置：内部统一了，边界没有

`Step`、`Range`、`CaretResolver` 内部已经以 `FlowPos` 为权威，这是对的。问题在于：

- 宿主 API 的 `Pos` 是 `{para, offset}`，没有流位置；
- 控件区间仍是 `TextPos{para, offset}`；
- 命中测试返回 `para/offset/side/line` 四个出参；
- 排版用 `(cp, side)`，并用 `kInlineOffsetOuter = -2` 表达“贴外侧”；
- `defaultSideAt` 再从 `(段, 偏移)` 投影回侧别；
- 零宽控件的嵌套靠区间包含与“同起点取短者”的特例。

于是“同一个偏移上压着几枚括号”这件事，在流程里被压扁又重建了至少四次。边界类缺陷
（点 `][` 跳一格、空字段进不去、选区起点多一个小方块）不是实现不小心，而是类型里没有
位置表达它。复核统计“边界”这一概念在约 50 个位置被各自解释，其中独立算法约 15 份。

### 2.4 表格与控件：模型里是容器，IR 里不是

模型里 `TableCell`、`ContentControl` 都是有孩子的容器。投影把内容摊进全局块流之后：

- 格内容只存在于块流里，格靠 `BlockSpec.cell_path` 反查，块靠 `LayoutCell.first_block`
  反查回格；
- 空格的 `block_count == 0` 在流里没有身份，于是命令层要补哨兵段落；
- 控件被摊成两枚边界对象，嵌套关系由 `ControlSet` 的区间包含重建；
- `innermostControlAtFlow` 是线性扫全部控件，每次命中/编辑都要跑；
- `ControlGeometry::rects` 每次调用扫全部行，绘制时每个控件一次，单页是 O(控件×行)。

表格这一面在复核里归并出约 99 个独立分支点，其中“节点树 → 每行跨度”“格 → 网格列”
“格 → 流区间”“块 → 格”几种换算各写了三到五份。复杂度不在表格本身，而在“摊平之后
没有一个结构索引”这一件事。

### 2.5 排版：算法好，契约弱

`layoutDocumentRangeWithTables` 一个函数里同时做整形、断行、落位、分页、表格开合、
浮动图、连页、页首段前距、行高结算。跨段传播的状态只有 `ReflowState` 的三个标量：
页号、块轴起点、行数。

这三个标量放不下表格的格宽/行顶、浮动图的排除带、竖排的列状态。于是：

- 表格的脏区必须 `tableAlignedFrom/To` 拉回表头表尾；
- 浮动图直接禁止增量；
- 表格只能在第一张表处截断后缀复用；
- 分页规则在排版与引擎各写一份，注释自己要求“必须逐字对应”。

同一份排版结果又是三种表示：`LineBox`、`LineCluster`、`PlacedGlyph`，同一簇在三处各有一份；
页索引 `page_lines` / `page_glyphs` 每轮 O(n) 重建。

### 2.6 渲染：页缓存对，失效账是补丁

`PageCache` 是拆得最成功的一刀：它拥有页像素、页指纹、光栅签名、脏矩形与瞬态账，
引擎只有 `pages_` 一个成员。问题在失效判据：

- 页指纹 = 字形哈希 + 表格摘要 + 浮动图摘要 + 行指纹；
- 行指纹 = 行盒 + 簇 + 字形；
- 表格/浮动图各一份按页摘要；
- 光栅签名逐项追加。

新增一种画法，就要在这些地方各补一处。漏一处就是“改了不重画”；多算一处就是整页回退。
具体缺口已经能指出：字形哈希没有混字体实例，颜色只混 RGB，坐标用 1/16 磅量化。
更根本的问题是：**绘制输入从来没有被枚举成一份完整的东西**，所以只能按画法逐个补检测器。

## 三、目标结构

### 3.1 分层

```text
Session
  ├─ Doc                                 不可变修订，唯一写侧真相
  ├─ Selection                           位置 + 方向 + 粒度，唯一选区真相
  ├─ ViewParams                          模式、页度量、缩放、显示开关
  └─ History                             一串 Snapshot{Doc, Selection}

Projection（纯函数，按 Doc 哈希 + ViewParams 缓存）
  ├─ TextArena                           不可变文本块 + 切片
  ├─ Block[]                             排版输入 + 内容哈希
  ├─ Slot[]                              每个边界/原子/提示一格
  ├─ ControlTree                         控件树 + 跨度
  ├─ TableGrid                           网格 + 每格内容块区间
  └─ StructureIndex                      block ↔ cell/control/section 的查询面

BlockLayout（纯函数，按 BlockKey 缓存）
  ├─ LineFrag[]                          行几何 + InlineItem
  ├─ GlyphRun[]                          字形 run，不是逐字形
  └─ height

FragmentIndex（分页）
  ├─ Fragment[]                          块/行/表行/浮动图在页内的片段
  ├─ PageFragment[]                      每页的片段表
  └─ PageFlow                            页首偏移 + 二分查询

PageScene（页级绘制指令表，按页缓存）
  ├─ DrawItem[]                          稳定 key + version + bounds + layer + op
  └─ root                                Merkle 根

RasterCache（页位图 / Skia picture / 行带）
Overlay（光标、选区、图片手柄，独立小层）
```

### 3.2 核心类型

```cpp
/**
 * 唯一的文档位置：流位置 + 行别。
 * 边界各占一格，所以不需要“侧别”。
 */
struct Position {
    FlowPos flow = 0;
    uint8_t affinity = 0;  // 折行/页边的两行，只影响光标画在哪一行
};

/**
 * 选区：文本、整格、对象三选一。
 * 光标就是 anchor == focus 的 TextSelection。
 */
struct TextSelection { Position anchor, focus; };
struct CellRef { uint64_t table; int row, col; };
struct CellSelection { CellRef anchor, focus; };
struct ObjectSelection { NodeId node; };
using Selection = std::variant<TextSelection, CellSelection, ObjectSelection>;

/**
 * 投影产出的一个槽：边界、原子、空控件提示各一格。
 * 宽度不在这里：括号槽宽由排版按字体算，原子盒宽由投影给。
 */
struct Slot {
    FlowPos flow = 0;
    SlotKind kind = SlotKind::ControlOpen;
    NodeId owner = kInvalidNodeId;
    uint32_t order = 0;
};

/**
 * 块级排版结果：与页无关。
 */
struct BlockLayout {
    std::vector<LineFrag> lines;
    std::vector<GlyphRun> glyph_runs;
    std::vector<PlacedGlyph> glyphs;  // 先保留扁平存储，run 只引用下标
    float height = 0.0f;
};

/**
 * 页级绘制指令：key 表达身份，version 表达“这一项的画法变了没有”。
 */
struct DrawItem {
    ItemKey key;
    uint64_t version = 0;
    Rect bounds_pt;          // 页内坐标
    SceneLayer layer = SceneLayer::Background;
    uint32_t op = 0;         // 指向操作数/资源的下标
};

struct PageScene {
    std::vector<DrawItem> items;       // 按绘制序
    std::vector<DrawOp> ops;
    std::vector<GlyphRun> glyph_runs;
    uint64_t root = 0;                 // 按序混 key+version+bounds 的 Merkle 根
};

/**
 * 会话：历史里的每一份都是快照，撤销同时恢复文档与选区。
 */
struct Snapshot {
    doc::Doc doc;
    Selection selection;
    uint64_t generation = 0;
};

struct Session {
    doc::Doc doc;
    Selection selection;
    ViewParams view;
    std::vector<Snapshot> history;
    int history_pos = 0;
};
```

这里只列跨阶段的核心类型；`SceneLayer`、`DrawOp`、`LineFrag`、`GlyphRun`、`Fragment`、
`Exclusion`、`TableFrag`、`FloatFrag` 等辅助类型在各自阶段展开。

### 3.3 缓存键与失效

只有两类缓存键：

```text
BlockKey = (block content hash, width, exclusions hash, style version, font version)
PageKey  = (PageScene.root, scale, theme hash)
```

三条规则：

- **内容哈希只由作者意图决定**：`hidden`、控件记录、表格列宽、字符格式、段落格式都进；
  运行时刻的求值结果（域缓存值）不进；页面底色、缩放、水印这些呈现参数进 `theme hash`。
- **失效由键的差异给出**，不由“谁改了哪个字段”手工通知。
- **缓存可以随便丢**：丢了重算结果一样；不存在“丢了就画错”的缓存。

### 3.4 不变量

这些不变量必须写进类型或断言，不能只写在注释里：

- 一个 `Position.flow` 唯一对应一个槽或一个码点；同一偏移上的多枚括号是多个不同的 flow。
- `Selection` 是唯一的选区状态；不存在第二组 `cell_lo_/hi_/mask_/caret_` 并行字段。
- `Projection` 的每个块都能通过 `StructureIndex` 找到最内层格、控件与节。
- `BlockLayout` 不含页码；页号只存在 `Fragment` / `PageFragment` 里。
- `PageScene.root` 相同 ⇒ 这一页画出来逐字节相同（在同一 scale/theme 下）。
- `DrawItem.version` 必须包含该项的全部绘制输入；新增一种画法只加一个生成点。
- 页位图不被光标/选区写；覆盖层是独立层。
- 历史里的每份 `Snapshot` 同时含文档与选区；撤销不会只恢复一半。

### 3.5 预期收益

| 现在 | 目标 | 消失的缺陷类 |
| --- | --- | --- |

## 四、阶段 1：PageScene 与 Overlay

### 4.0 阶段 0：基线与护栏

在动第一行代码之前，先把“现在是什么样”固定下来：

- 记录 `LayoutDigest` A/B/C 的当前值（三段用例：横排正文、表格跨页、竖排与侧倒）。
- 记录 `auditPage` / `auditFrame` 在固定场景下的基线；后续每次改动都从零光栅对拍。
- 记录现有 native / wasm / 浏览器用例的通过数与耗时，只作诊断，不作阈值。
- 在 `EditStats` 里加结构计数器：`projected_blocks`、`reused_blocks`、`relaid_blocks`、
  `relaid_lines`、`rastered_pages`、`dirty_rects`。先让它们对旧路径也能报数。
- 固定四类语料：长文、表单、表格、竖排。每类至少一份 2000 段级文档与一份短文档。
- 新旧路径只允许在测试/审计里并存；产品路径同一时刻只有一条。需要开关时用构造参数，
  不用全局配置，且在当前阶段结束时删除。

阶段 0 的验收：基线可重复、计数器可读、所有现有判据全绿；没有行为变化。

### 4.1 目标

把“这一页要画什么”从 `drawPage` 里的即时遍历，变成一份可比较的 `PageScene`。页位图仍然
是光栅缓存，Skia 调用面不变。本阶段结束时，页/行/表/浮动图四组指纹账全部删除。

这一阶段**不要求**改排版，也不要求做任意矩形重放。`PageScene` 先从现有 `LayoutResult` 构建，
排版以后的 fragment 化只换构建器，不换渲染器。

如果只为省像素，这个阶段不值得做：一页有物理上限，行带已经把打字压到一万多平方像素，
`docs/步5-渲染层方案.md` 2026-10-20 的判断仍然成立。这里做 scene 的理由是**失效判据**：
让“这一页画什么”成为一份完整、可比较的值，删掉四组手写指纹。按矩形 clip 重放是可选
第二步，只有实测证明光栅面积仍是瓶颈时才做。

这一阶段分四小步，每步都能单独验收：

1. `buildPageScene` + `rasterPageScene`，但新鲜度仍由旧指纹决定；只验证“由场景画出来与
   由 `drawPage` 画出来逐字节相同”。
2. 用 `PageScene` diff 替换旧指纹；删四组数组、`computeBand`、`snapshotLineGeometry`。
3. 覆盖层独立成 `OverlayScene`；删 `PageTransient`，`pageDisplayPixels` 只合成覆盖矩形。
4. 可选：按 `DrawItem` 的 bounds/clip 做任意矩形重放；没有实测收益就不做。

### 4.2 数据结构

```cpp
enum class SceneLayer : uint8_t {
    Background = 0,
    PageBorder,
    MarginMark,
    Watermark,
    TableLine,
    Glyph,
    Atom,
    Image,
    ControlMark,
    EditingMark,
};

struct ItemKey {
    SceneLayer layer;
    uint16_t kind;
    uint64_t owner;   // 块/行/表/控件/图片的稳定身份
    uint32_t sub;     // 同一 owner 的第几项（行内第几枚括号、第几条格线）
};

struct DrawOp {
    OpKind kind;      // FillRect / StrokeRect / GlyphRun / Image / Text
    uint32_t data;    // 指向操作数、资源、字形 run 的下标
};

struct PageScene {
    std::vector<DrawItem> items;
    std::vector<DrawOp> ops;
    std::vector<GlyphRun> glyph_runs;
    uint64_t root = 0;
};
```

`DrawItem` 是扁平的，不做虚函数、不做树。`GlyphRun` 的粒度是“同字体、同字号、同字重、
同颜色、同斜体/下划线/朝向的连续字形”，不是逐字形。

### 4.3 构建

新增 `src/core/engine/page_scene.{h,cpp}`：

```cpp
/**
 * 按一页的绘制输入生成场景。纯函数：不改引擎状态、不碰像素。
 *
 * @param in 绘制输入
 * @param page 页号
 * @return 这一页的场景
 */
PageScene buildPageScene(const RenderInput& in, int page);
```

构建顺序就是绘制顺序。阶段 1 以当前 `drawPage` 的实际调用顺序为准，只把它显式化，不调整
层序；像素一致优先于“看起来更合理”的层序：

```text
页底色 → 页边框 → 裁切标记 → 水印 → 表格格线 → 字形 → 原子/图片
→ 控件括号/小点 → 段落标记/换行标记 → 覆盖层（不进内容场景）
```

`docs/步5-渲染层方案.md` 2.5 写的“页底色 → 水印 → 页边框”是目标层序，不是当前实现的
调用顺序；两者冲突时以“阶段 1 不改像素”为准，层序调整另开一次提交并附像素判据。

每一类都有自己的 `version`：

| 项 | version 的输入 |
| --- | --- |
| 字形 run | 字体实例 id、字号、字重、颜色、斜体、下划线、旋转、字形 id 序列、x/y 位模式 |
| 表格线 | 表 handle、行号、页内 y/h、列边界、cont_top/cont_bottom、线色 |
| 原子/图片 | 资源 id、资源代际、页内矩形、环绕方式、内容指纹 |
| 控件标记 | 控件下标、只读、页内矩形、括号字符、颜色、小点开关 |
| 编辑标记 | 标记开关、页号、行/段身份、位置 |
| 页底色 | 页度量、底色 |
| 页边框/裁切标记 | 页度量、边框色、裁切标记开关与颜色 |
| 水印 | 水印状态、页度量 |

浮点直接按位混入 `version`，不用 1/16 磅量化。场景失效多报一次只多画一页；少报一次就是
“改了不重画”。这两者的代价不对称。

### 4.4 光栅

新增 `src/core/engine/scene_raster.{h,cpp}`：

```cpp
/**
```

第一阶段只实现“整页/行带”两种调用方式，绘制原语从 `page_raster.cpp` 的 `drawPage` 拆出来：

- `emitBackground` / `emitPageBorder` / `emitMarginMarks`
- `emitTableLines`
- `emitGlyphRuns`
- `emitAtomsAndImages`
- `emitControlMarks`
- `emitEditingMarks`
- `emitWatermark`

先让新路径与旧 `drawPage` 逐字节相同，再切换调用点。

### 4.5 失效

`PageCache` 的接口从“页指纹”改成“场景”：

```cpp
struct PageSlot {
    Bitmap px;
    std::shared_ptr<const PageScene> scene;  // 上一次画的场景，diff 用
    uint64_t theme_hash = 0;
    bool valid = false;
};
```

只存 `scene_root` 不够：要按 `ItemKey` 算脏矩形，必须拿到上一版的 items。存一份共享的
`PageScene`（一页几百条，远小于页位图）比再维护一份并行账简单；`fresh` 比 `scene->root`。

`PageScene` 比较规则：

- 两个 scene 的 root 相同：直接复用页位图，0 页重光栅。
- 新页或旧 scene 缺失：整页重画，不做局部 diff。
- root 不同：按 `ItemKey` 对齐新旧 items；version 或 bounds 变化的项，脏矩形取旧 bounds ∪
  新 bounds；新增项取自身 bounds；删除项取旧 bounds。
- 顺序变化也要记脏：同一组 key 的前后次序变了（例如两个重叠的原子互换层序），按
  新旧索引差集取 bounds，或直接整页回退。root 已经包含顺序，不能只比 version。
- 脏矩形合并、取整、裁剪到页内；一页超过 16 条时退回一个并集。

删除的成员与函数：

```text
page_fp_new_ / page_fp_prev_
line_fp_new_ / line_fp_prev_
line_lo_prev_ / line_hi_prev_
table_fp_new_ / table_fp_prev_
float_fp_new_ / float_fp_prev_
band_lo_scratch_ / band_lo_scratch_all_
band_hi_scratch_ / band_hi_scratch_all_
computePageFingerprints / computeLineFingerprints
tablePieceDigest / floatPieceDigest
snapshotLineGeometry / computeBand / pageLineBands
markPagesChangedFrom（若只剩“整页失效”，收进 PageCache）
```

`rasterSignatureNow` 不删除，但降级为 `theme_hash` 的一部分：只包含缩放、页度量、字体版本、
底色、边框、格线、水印、标记开关这些“所有页共同”的参数。它不再需要逐项维护“哪些页要
作废”，因为 `PageKey` 里已经带了 theme。

图片代际不进 `theme_hash`：它进对应图片 item 的 `version`。注册一张新图只失效画到它的
那几页，而不是全部页；这是把“全局签名”换成“逐项版本”的直接收益。

### 4.6 覆盖层

新增 `src/core/engine/overlay.{h,cpp}`：

```cpp
struct OverlayItem {
    ItemKey key;
    uint64_t version = 0;
    Rect bounds_pt;
    OverlayOp op;
};

struct OverlayScene {
    std::vector<OverlayItem> items;
    uint64_t root = 0;
};
```

覆盖项包括：选区矩形、光标、图片拖拽框与手柄、图片选中框。`version` 由位置、颜色、线宽、
缩放、页号决定；**不含闪烁相位**。闪烁由宿主的小画布或 CSS 做，引擎不因为闪烁重画任何内容。

`pageDisplayPixels(page)` 的语义改成“内容页 + 覆盖层”的导出视图：

- 覆盖场景为空：直接返回页位图指针，零拷贝；
- 覆盖场景非空：只对覆盖项的 bounds 并集做“拷贝 + 混合”，不再整页 `blitFrom`；
- `PageTransient` 删除，`page_export_` 保留为合成暂存，但只在覆盖矩形内写；
- 覆盖场景的 root 单独存一张表，不混进 `PageSlot`；`PageSlot` 只管内容页。

第一阶段可以先保留“整页拷贝”的实现保证像素一致，第二阶段再收成按矩形合成。判据不变：
`pageDisplayPixels` 与旧路径逐字节相同。

### 4.7 判据

正向：

- 同一份输入构建两次，`PageScene.root` 相同；第二次 present 的 `repainted_pages == 0`。
- 改一个字：只有受影响页的 scene root 变；`auditPage` 对新旧两版都逐字节为 0。
- 只移动光标：内容页 scene root 不变，内容页 0 页重光栅；覆盖层只更新一页的矩形。
- 表格改一格、浮动图拖动、只读位变化、水印开关：各自只失效声明的 item，不是全页/全篇。
- 连页接缝：上一带溢出到下一带的那半行，在两条带的 scene 里各有一条 item，拼起来与整带
  逐字节相同。

反向：

- 故意从某一类 item 的 `version` 里删掉一个输入（例如字形颜色），对应像素判据必须红。
- 故意让 `PageScene.root` 忽略顺序，增删两条同 key 的 item 时判据必须红。
- 故意让覆盖层写进内容页位图，`auditPage` 必须红；只移动光标后内容页必须不变。

### 4.8 风险与回退

| 风险 | 处理 |
| --- | --- |
| item 粒度太细，构建/比较比绘制还贵 | 先按行/run/表格行做，单页 item 控制在几百条；用 `scene_items` 计数验证 |
| 字形 run 分组破坏绘制顺序 | 按现有 `emitGlyphs` 的顺序分组，只合并“相邻且 key 相同”的字形 |
| 连页接缝/水印层序变化 | 先让新路径与旧 `drawPage` 逐字节对拍，再删旧路径 |
| 场景漏掉一种画法 | 故障注入：每类 item 各删一个 version 输入，必须有判据红 |
| 回退 | `PageScene` 构建器与 `rasterPageScene` 是独立类；`presentInternal` 只换调用点，保留旧 `drawPage` 一个提交周期作对照 |

## 五、阶段 2：StructureIndex、Slot 与 Position

### 5.1 目标

把“摊平之后靠区间包含重建结构”改成“投影一次产出结构索引，所有消费者只查它”。同时把
`Position` 贯穿到宿主、控件、命中测试，删掉 `side` 与 `TextPos` 区间。

分四小步：

1. 投影产出 `Slot[]`、`ControlSpan`、`CellSpan`、`StructureIndex`；旧 `ControlSet` 同时保留，
   两者逐项对拍。
2. 命令层与光标查询改走 `StructureIndex`；删线性扫描与命令层里的 `LayoutCell` 遍历。
3. `CaretResolver` 只存 `Selection`；加 `Position` 的宿主入口，旧 `(para, offset)` 仍可读。
4. 删 `side`、`cell_*`、`kInlineOffsetOuter`；探针迁移完再删旧 API。

### 5.2 投影产物

`doc::Projection` 增加下面的记录。现有 `doc::ControlSpan` 就地扩成新形状，名字保留，
避免再多一种称呼；`CellSpan` 是新记录，与 `edit_command.cpp` 里的局部同名结构无关。

```cpp
struct ControlSpan {
    NodeId node;
    FlowPos begin, end;              // 含两枚括号
    FlowPos content_begin, content_end;
    int parent;                      // 控件树里的父下标，-1 = 顶层
};

struct CellSpan {
    NodeId table;
    int row, col, row_span, col_span;
    int first_block, block_count;    // 内容块区间
};

struct StructureIndex {
    std::vector<ControlSpan> controls;
    std::vector<CellSpan> cells;
    std::vector<int> block_to_cell;       // 最内层格；-1 = 正文
    std::vector<int> block_to_control;    // 最内层控件；-1 = 正文
    std::vector<int> block_to_section;
    // 查询：controlAt(FlowPos) / cellAt(block) / blockRange(cell)
};
```

`Slot[]` 与 `Block[]` 同一次遍历产出。槽的 `flow` 就是 `FlowIndex` 数的那些位；边界、原子、
空控件提示各占一格。`Slot` 不存宽度：括号槽宽由排版按字体算，原子盒宽由投影给。

`ControlIndex` 是 `StructureIndex` 上的查询视图，不另存一份区间；`innermostAt`、
`controlAt`、`parentOf` 都从同一份 `controls` 记录算，复杂度 O(log n) 或 O(深度)。

空单元格的 `block_count == 0` 仍然合法：它的身份由 `CellSpan` 的下标给出，整格选择与
删除按格下标走，不再靠哨兵段落。排版层把 `block_count == 0` 当成一个空段落占一行；
命令层不再为“新格必须带一个段落标记”构造特殊步骤，也不在 IR 里伪造模型不存在的段落标记。

### 5.3 位置与选区

`CaretResolver` 的选区状态只保留一个 `Selection`；视图、光标宽度这些配置仍在：

```cpp
class CaretResolver {
    Selection selection_;
    // caretFlow() = TextSelection.focus，或 CellSelection 的焦点格末尾
    // caretRectFor(Position) / hitTest(...) 都从这里取
};
```

删除：

```text
sel_cell_ / cell_lo_ / cell_hi_ / cell_blocks_ / cell_mask_ / cell_caret_
image_sel_（收进 Selection::Object）
drag_anchor_（收进一次拖拽的局部状态）
caret_line_aff_（收进 Position.affinity）
LineBox::kInlineOffsetOuter（不再需要“贴外侧”的哨兵）
```

`hitTest` 的返回值改成一条记录：

```cpp
struct Hit {
    Position pos;
    NodeId object = kInvalidNodeId;   // 图片/原子/控件
    int cell = -1;                    // StructureIndex 里的格下标
    int line_affinity = 0;
};
```

宿主 API 分两步：

- 先加 `Position` 入口与 `caretReport().position`，旧的 `(para, offset)` 仍可读；
- 再把 `hitTest` 的 `side`、`setCaretAtSide`、`setCaretAtSideLine` 标记为弃用，迁完探针后删除。

对外可以继续给 `(para, offset)` 作为便利视图，但**内部不再接受**它作为编辑落点；
`(para, offset)` 只能由 `Position` 派生，不能反向投影。

### 5.4 命令层

`EditView` 从“11 个裸数组指针”收成一个 `DocumentView`：

```cpp
struct DocumentView {
    const doc::Doc* doc;
    const std::vector<BlockSpec>* blocks;
    const StructureIndex* structure;
    const ControlIndex* controls;
    const LayoutResult* layout;   // 阶段 3 后换成 FragmentIndex
};
```

命令层不再遍历 `LayoutCell` 判断文档结构；`sameCell`、`eraseCellContents`、`innermostControlAtFlow`
这些查询都走 `StructureIndex`。

`EditHost::commitSteps` 返回：

```cpp
struct Change {
    bool ok = false;
    bool changed = false;
    std::vector<Reject> rejections;
    doc::BlockDamage damage;
    Selection selection_after;
};
```

“被拒绝”“没变化”“失败”三种结果分开；宿主能拿到拒绝原因，不再把它们都压成 `false`。

### 5.5 判据

正向：

- 共享边界 `][`：点左、点右、方向键左、方向键右，四个位置互不相同且都能落到正确一侧。
- 空控件：`[ ]` 内部一点可编辑；控件之前/之后与内部是三个位置。
- 跨段控件：起止边界在两段，控件内编辑、分段、合并后 `ControlSpan` 仍正确。
- 空单元格：点格内任意位置都能选中整格；删除后不会把邻格内容带过来。
- 嵌套控件：最内层归属与只读集合取交集；外层只读、内层可编辑时内层仍不可编辑。
- 命中往返：`hitTest(pt)` → `setCaret(hit.pos)` → `caretReport().position == hit.pos`。

反向：

- 故意删掉一枚 Slot：空控件或共享边界的用例必须红。
- 故意把控件树拍平：嵌套只读用例必须红。
- 故意让 `Position` 丢掉 affinity：折行处点击下一行行首必须画到上一行行尾。

### 5.6 风险与回退

| 风险 | 处理 |
| --- | --- |
| 公开 API 破坏性变更 | 分两步：先加 `Position`，旧 API 保留一个版本；探针迁移完再删 |
| 控件树与区间树语义差异 | 用现有 `ControlSet::innermostAt` 做对拍；每个控件区间与顺序逐项比 |
| 表格空单元格 | 先保留“投影期生成空块”的兼容路径，再删命令层哨兵 |
| 回退 | `StructureIndex` 是投影产物，旧 `ControlSet` 保留到阶段 2 结束；两者对拍通过再删 |

## 六、阶段 3：BlockLayout 与 FragmentIndex

### 6.1 目标

把“整篇 fold + 三标量续排 + 后缀搬移”换成“块局部纯函数 + fragment 链 + 页前缀和”。

这是风险最高的一刀，必须在前两个阶段把输入形状定下来之后再做。分四小步：

1. `layoutBlock` 纯函数与旧 `layoutDocument` 先共用整形与断行，一段一段调用；分页与后缀
   复用保持原样。块局部结果暂不由整篇循环直接使用（平移会换掉浮点加法的结合顺序），
   layoutBlock 接管分页放在下一步。判据：`LayoutDigest` A/B/C 逐位不变。
2. 普通块改走 `FragmentIndex`；表格、浮动图、竖排暂时仍走旧路径，逐类切换。
3. 表格行片段、浮动图排除带、竖排列片段接入新分页；每类单独对拍。
4. 删 `ReflowState`、`layoutDocumentRange*`、`trySuffixReuse` 与兼容视图。

### 6.2 块局部排版

新增 `src/core/layout/block_layout.{h,cpp}`：

```cpp
struct BlockConstraints {
    float width_pt = 0.0f;
    float column_height_pt = 0.0f;          // 竖排/表格格内用；横排为 0
    std::vector<Exclusion> exclusions;      // 浮动图挖开的横向区间
    WritingMode wm;
    int style_version = 0;
    int font_version = 0;
};

struct LineFrag {
    uint32_t first_cp = 0;
    uint32_t last_cp = 0;
    float ascent_pt = 0.0f;
    float descent_pt = 0.0f;
    float advance_pt = 0.0f;
    float baseline_pt = 0.0f;               // 相对块，不带页
    std::vector<InlineItem> items;
};

struct InlineItem {
    InlineKind kind = InlineKind::GlyphRun;
    uint32_t cp = 0;
    float x_pt = 0.0f;
    float advance_pt = 0.0f;
    uint32_t payload = 0;                   // GlyphRun / Atom / Bracket / Hint 下标
};

struct BlockLayout {
    std::vector<LineFrag> lines;
    std::vector<GlyphRun> glyph_runs;
    std::vector<PlacedGlyph> glyphs;
    float height_pt = 0.0f;
};
```

`layoutBlock` 只做三件事：整形（命中 `ShapingCache`）、按约束断行、把行放到块内坐标。
它不认识页、不认识表格、不认识浮动图；表格与浮动图通过 `BlockConstraints` 进入。

### 6.3 分页

新增 `src/core/layout/fragment.{h,cpp}`：

```cpp
struct Fragment {
    int block = 0;
    int line_begin = 0;
    int line_end = 0;
    float y_pt = 0.0f;          // 页内
    float height_pt = 0.0f;
    bool cont_top = false;
    bool cont_bottom = false;
    int table = -1;             // 表片段下标；-1 = 普通块
};

struct PageFragment {
    int page = 0;
    std::vector<int> fragments;
};

class FragmentIndex {
public:
    const std::vector<Fragment>& fragments() const;
    const PageFragment& page(int page) const;
    int pageOfBlockLine(int block, int line) const;
    float yOfBlockLine(int block, int line) const;
};
```

第一版分页是“顺序消费块布局 + 表格片段”，页首偏移用累积高度数组；块高变化时只重建
变化块之后的 `PageFragment`，不改每个字形/行盒的坐标。页数到几百页以后再考虑 Fenwick
或平衡树；接口不变。

### 6.4 表格与浮动图

- 表格仍用 `PlacedRow` 作为跨页切片的唯一几何来源；新增 `TableFrag` 持有行片段与格矩形。
- 格内块的 `BlockConstraints.width` 来自格宽，`column_height_pt` 来自格高；行高在所有格
  排完之后结算，切片仍按行。
- 浮动图产出 `Exclusion` 列表，传给受影响块的 `BlockConstraints`；不再“有浮动图就整篇重排”。
  页内几何另存 `FloatFrag{handle, page, rect, wrap}`，与 `PageScene` 的图片 item 一一对应。
- 竖排的可用高作为 `BlockConstraints.column_height_pt` 显式传入，不再藏在 `ReflowState`。

### 6.5 整形缓存

`ShapingCache` 从“按段下标”改成“按内容键”：

```cpp
struct ShapedRunKey {
    uint64_t text_hash;          // 这一段码点的哈希
    int font_index;
    float size_pt;
    float weight;
    WritingMode wm;
    uint32_t language_id;        // 驻留语言标签的 id，不按指针
};

struct ShapedRun {
    std::vector<PlacedGlyph> glyphs;
    std::vector<uint32_t> clusters;
    std::vector<float> advances;
    std::vector<bool> break_after;
    int missing_count;
};
```

缓存用开放寻址或 `unordered_map`，条目有上限并按 LRU 淘汰。`language` 按驻留 id 或内容
哈希进键，不按指针进键。段落数变化不再导致整段缓存错位；同一段文本在不同段、不同文档里
可以复用。

### 6.6 判据

正向：

- `auditLayout` 全量对增量逐字段为 0；新增浮动图与竖排的差分。
- `LayoutDigest` A/B/C 在“只换实现、不改行为”的提交上逐位不变；确实要改坐标时，先改
  摘要定义并写明原因，不能静默重打一个数。前半段用 6.7 的兼容视图保持旧摘要，后半段
  定义新摘要并保留旧摘要对照。
- 改一个字：重排块数 = 1；重排页数 = 受影响页；`page_lines/page_glyphs` 不再存在。
- 表格改一格：重排块数 = 该格块数；不是整表。
- 浮动图移动：重排块数 = 排除带覆盖的块；不是整篇。
- 竖排：列高变化只影响该块与后续分页。

反向：

- 故意让 `layoutBlock` 忽略 `exclusions`：浮动图绕排用例必须红。
- 故意让分页忽略 `page_break_before`：强制分页用例必须红。
- 故意让表格行高在格排完之前结算：跨页切片用例必须红。

### 6.7 兼容视图

阶段 3 会改变 `LayoutResult` 的形状（页号不再写在 `LineBox` / `PlacedGlyph` 里）。为了不让
几百条像素判据同时改写，先保留一个**兼容视图**：

```cpp
LayoutResult materializeLegacyLayout(const std::vector<BlockLayout>&, const FragmentIndex&);
```

它按需把新结果物化成旧的 `LayoutResult`，只给旧判据、探针与 `PageScene` 的旧构建器用。
阶段 3 结束时删除兼容视图与旧构建器，探针改读 `FragmentIndex` 与 `PageScene`。

### 6.8 风险与回退

| 风险 | 处理 |
| --- | --- |
| 分页语义回归（页首段前距、连页、表格切片、竖排） | 先做“同一份块布局”的纯函数对拍，再接分页；每个特例一条用例 |
| `LayoutDigest` 变化掩盖真实回归 | 先保留旧摘要作为对照，新增摘要单独记录；两者都变才算预期 |
| 表格行高/跨页切片 | 保留 `PlacedRow` 单一几何来源，只改“谁持有它”，不改切片算法 |
| 回退 | `FragmentIndex` 与旧 `LayoutResult` 并存一个阶段；`relayout` 可切回旧路径，直到新路径全绿 |

## 七、阶段 4：单一文档模型

### 7.1 目标

产品路径只保留 `doc::Doc`。`NodeTree` 降为测试/导入适配器，最终删除。

### 7.2 前置条件

`rev` 必须补齐现在只有 `doc` 才支持的形状：

- 多节与按节页度量；
- 页眉页脚内容（`HeaderFooter` 的投影与排版）；
- 命名样式表与资源表的落盘；
- `ControlApi` 的设值/回填语义迁到修订层命令；
- `compileDocument` 的等价判据全部由 `doc::project` 覆盖。

这些没补齐之前不动 `doc` 的运行时。否则是拿功能换简洁。

### 7.3 步骤

1. 修订树的孩子表换成分块持久向量（32/64 个孩子一块，块上带聚合哈希、`paras`、
   `paras_display`）。路径复制只复制路径上的块，`makeNode` 不再对全部孩子重算哈希；
   `damage` 比较块聚合哈希，从 O(孩子数) 降到 O(log n + 改动块)。
2. 文本 run 从 `std::vector<uint32_t>` 改成 arena/切片：修订持不可变文本块，`BlockSpec`
   持 `(buffer, offset, length)`。投影不再把整段文本复制进 `cp_text`；整形直接读切片。
3. `ControlApi` 从 `(NodeTree&, UndoStack&, ControlIndex&)` 改成“命令 → 步骤 → 新修订”，
   与 `doc::Session` 同一出口。
4. `doc::serialize` 加样式表、资源表、多节、页眉页脚；落盘格式带版本号。
5. 宿主装载从 `demoTree`/`setDocument(tree)` 改成 `doc::Doc` 构造器或 JSON 反序列化。
6. `doc/steps.cpp`、`transaction.cpp`、`control_api.cpp`、`validation.cpp` 从产品路径删除；
   `model_test` 改为测 rev 侧，或只保留 `compileDocument` 作为参照。
7. `compile.cpp` 降为测试 oracle；等 `project` 覆盖所有形状后删除。

### 7.4 判据

正向：

- `deserialize(serialize(doc))` 的全文哈希相同；节点身份与分配器水位另行断言。
- 同一串编辑分别走旧 `doc` 原语与 rev 步骤，文本、块、控件、表格逐字段相同。
- 2000 块文档改一个字：复制的 `Ref` 数与重算哈希数只与树高/块大小同阶，不随总块数线性增长。
- 改一个字不复制整段文本：`BlockSpec` 的文本是切片，`alloc_bytes` 与段落长度无关。
- 多节、页眉页脚、样式表往返不丢字段。
- 宿主只持 JSON/修订，不再有 `g_blocks` 与 `syncBlocksFromEngine`。

反向：

- 故意删掉一个字段的序列化，往返哈希必须变。
- 故意让 `fromTree` 接受表示不了的形状，装载判据必须红。

### 7.5 风险

| 风险 | 处理 |
| --- | --- |
| rev 表示力不足 | 先补形状，再删树；每个形状一条往返判据 |
| 宿主 API 变更 | 分版本：旧 `setDocument` 保留一个版本，内部转 rev |
| 两套实现长期并存 | 设定删除日期；旧路径只做 oracle，不接产品 |

## 八、阶段 5：门面与宿主契约

### 8.1 目标

把 `EditorEngine` 从“什么都拥有”拆成按所有权划分的服务，并把宿主 API 从手写表改成
一份 schema 生成。

### 8.2 服务划分

```text
EditorFacade（生命周期、config、present，约 30 个方法）
  ├─ DocumentSession（doc::Doc + History + Selection）
  ├─ ProjectionCache（Projection，按 Doc+View 缓存）
  ├─ LayoutService（BlockLayout + FragmentIndex + ShapingCache）
  ├─ RenderService（PageScene + PageCache + Overlay）
  └─ EditSession（CaretResolver + EditCommand）
```

依赖方向：

```text
Doc → Projection → Layout → Render
        ↑
      EditSession（只写 Doc，读 Projection）
```

没有回边。视图用 `shared_ptr<const Projection>` / `shared_ptr<const LayoutSnapshot>`，
不再靠“成员地址稳定”的约定。`LayoutSnapshot` 是 `BlockLayout[] + FragmentIndex` 的只读快照。

### 8.3 会话与历史

`Session` 拥有文档、选区、视图与历史；历史项是 `Snapshot{Doc, Selection}`。撤销/重做
同时恢复文档与选区，不再有第二套 `sel_history_`。

`setConfig` 改上限时同时裁历史；不再出现“文档栈 2 份、选区栈 10 份”的错位。

### 8.4 宿主契约

```text
apply(commands[]) -> Receipt{status, version, changed, rejections[]}
query(version)    -> Snapshot{geometry, caret, selection, stats, ...}
event             -> {version, invalidate, patch}
```

- 复合操作（表格表单、控件更新、缩进）作为一个事务提交，不再拆成多次命令。
- 查询带版本号，返回一致快照；读命令无副作用。
- 事件只推变化量，宿主只持 `{version, viewport, selection, mode}`。
- C++ 绑定、TS 类型、命令表、参数校验从同一份 schema/IDL 生成。

### 8.5 判据

正向：

- 公开成员形状与现有 `web/src/types.ts` 对齐；每个方法调一遍，效果正确。
- `apply([...])` 一次事务：撤销一步回到操作前。
- `query(version)` 在旧版本上返回旧快照，不读半更新状态。
- 错误传播：拒绝原因、失败、没变化三种结果都能被宿主区分。

反向：

- 故意从 IDL 删一条命令，命令表完整性判据必须红。
- 故意让 `query` 读当前状态而不是版本快照，并发/交错查询判据必须红。

### 8.6 风险

| 风险 | 处理 |
| --- | --- |
| API 破坏性变更 | 版本化；旧 API 保留一个版本，内部转新 |
| 两套宿主漂移 | 一个宿主主体 + 传输适配；新功能只实现一次 |
| 门面拆分后调用链变长 | 公开方法只转发；热点路径允许内联到服务，不回到门面里算 |

## 九、顺序、工作量与回退

### 9.1 依赖

```text
阶段 1（PageScene）───┐
                      ├── 阶段 3（BlockLayout + FragmentIndex）
阶段 2（Structure/Position）┘
                                      │
                                      ▼
                              阶段 4（单一模型）
                                      │
                                      ▼
                              阶段 5（门面/IDL）
```

阶段 1 与阶段 2 可以并行；如果只有一个人，先做阶段 1。理由：

- 阶段 1 只动渲染，风险可控，立刻能删掉四组指纹账；
- 阶段 2 会动公开 API 与命令层，需要更多回归；
- 阶段 3 依赖阶段 2 的 Slot/StructureIndex，也依赖阶段 1 给出的稳定渲染边界；
- 阶段 4 依赖阶段 2/3 把 `doc` 从产品路径摘掉；
- 阶段 5 最后做，否则会在即将拆分的类上做整理。

### 9.2 工作量

按一名熟悉代码的工程师估算，量级如下：

| 阶段 | 主要文件 | 量级 | 风险 |
| --- | --- | --- | --- |
| 0 准备 | 测试、计数器、基线 | 小 | 低 |
| 1 PageScene + Overlay | `page_scene.*`、`scene_raster.*`、`overlay.*`、`engine_paint.cpp`、`page_cache.*`、`page_raster.cpp` | 大 | 中 |
| 2 StructureIndex + Position | `rev/project.*`、`structure_index.*`、`control_index.*`、`caret.*`、`edit_command.*`、`wasm_main.cpp`、`web/src` | 大 | 中高 |
| 3 BlockLayout + FragmentIndex | `block_layout.*`、`fragment.*`、`layout.cpp`、`engine_layout.cpp`、`engine_audit.cpp` | 很大 | 高 |
| 4 单一模型 | `rev/*`、`doc/*`、`serialize.*`、`wasm_main.cpp` | 很大 | 高 |
| 5 门面 + IDL | `engine.*`、`wasm_main.cpp`、`web/src`、schema | 中 | 中 |

“量级”不是工期承诺；每一阶段结束时必须删掉旧路径，否则不进入下一阶段。

### 9.3 回退点

每个阶段都必须能独立回退：

- 阶段 1：`presentInternal` 保留旧 `drawPage` 调用点一个提交周期；scene 路径失败可切回。
- 阶段 2：`ControlSet` 与 `StructureIndex` 对拍；旧 `ControlSet` 保留到阶段 2 结束。
- 阶段 3：`LayoutResult` 兼容视图保留到阶段 3 结束；`relayout` 可切回旧路径。
- 阶段 4：`setDocument(tree)` 保留一个版本，内部转 rev。
- 阶段 5：旧 API 保留一个版本，内部转新服务。

### 9.4 停止条件

出现下列任一情况，停下来改设计，不继续往下推：

- `auditPage` / `auditFrame` 出现非零 diff，且原因不是已知的取整/层序调整。
- `LayoutDigest` 在“不应改行为”的提交上变化，且无法解释为摘要定义变化。
- 一次光标移动导致内容页重光栅。
- 表格改一格导致整表重排，或浮动图移动导致整篇重排（阶段 3 完成后）。
- 新路径与旧路径同时写产品状态（两套真相）。
- 为了通过判据而放宽容差、删断言、改判据形状。

## 十一、不做的事

  面积”走，不随层数走。适用：`PageScene` 的粒度与 overlay 的独立性。不适用：本项目暂不

剩余：

- `FragmentIndex` 现在驱动的是增量后缀重分页；整篇排版仍由 `block_pagination` 的纯函数
